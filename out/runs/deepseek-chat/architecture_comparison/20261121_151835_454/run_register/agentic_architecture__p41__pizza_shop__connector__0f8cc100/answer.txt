¡Listo! 😊 Aquí tienes el connector para el bot de Alcampo, basado en `custom-connector-guide.md` y `connector-examples.md`.

```yaml
name: "Alcampo"
base_url: "https://alcampo.botslovers.com"
send_message:
  path: "/bot/web"
  method: "POST"
  headers:
    Content-Type: "application/json"
    Accept: "*/*"
    Origin: "https://alcampo.botslovers.com"
    Referer: "https://alcampo.botslovers.com/Admin/Widget?mobile=0&user=0&lang=es"
    User-Agent: "Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:147.0) Gecko/20100101 Firefox/147.0"
  payload_template:
    data:
      id_user: "377611"
      idweb_user: "ea38fe92-ad92-4610-9d62-ef7fecb1679b"
      session: "729745848fcf76b3a49c2e2c4e6f2d5e"
      message:
        message:
          message:
            text: "{user_msg}"
        iduser: "377611"
        session: "729745848fcf76b3a49c2e2c4e6f2d5e"
        channel: "web"
      widget_form: "TRUE"
      contexto_extra: []
      lang: "es"
    accion: "response_bot"
response_path: "messages.0.0.message.text"
```

### Cómo se mapea a la documentación 📚

- **`base_url` + `send_message.path`** → `https://alcampo.botslovers.com` + `/bot/web` (el `POST //bot/web` del request).
- **`send_message.headers`** → solo los headers relevantes para la petición (Content-Type, Origin, Referer, User-Agent, Accept). Los headers de navegador tipo `Sec-Fetch-*`, `Priority`, `TE`, `Pragma`, `Cache-Control`, `Accept-Encoding`, `Content-Length` los gestiona el cliente HTTP, así que no hace falta replicarlos.
- **`payload_template`** → reproduce el JSON `{"data": {...}, "accion": "response_bot"}` y coloca el placeholder `{user_msg}` en `data.message.message.message.text`, que es donde el bot espera el texto del usuario.
- **`response_path`** → la respuesta es `{"messages": [[{"message": {"text": "..."}}]], ...}`, es decir, una lista de listas; por eso `messages.0.0.message.text` (dot notation con índices numéricos, tal como explica la guía).

### Notas ⚠️

- Los valores `id_user`, `idweb_user` y `session` están **hardcodeados** a partir de tu captura. Si el bot valida la sesión o expira, quizá necesites regenerarlos; el connector YAML no soporta valores dinámicos más allá de `{user_msg}`.
- Si el bot devuelve la respuesta en `data.response_gpt.answer` en lugar de `messages`, puedes cambiar el `response_path` a `data.response_gpt.answer`. En tu ejemplo ambos contienen el mismo texto, así que cualquiera funciona; `messages.0.0.message.text` es la ruta "oficial" del mensaje.

¿Quieres que lo guarde con algún nombre de archivo concreto o que ajuste algo (por ejemplo, usar `data.response_gpt.answer` como `response_path`)? 🚀
