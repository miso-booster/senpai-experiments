## What's broken and how to fix it

### 1. `llm.temperature` must be a number, not a word
`temperature: low` isn't valid — it needs a float between 0 and 1 (or higher). Use something like `0.0` for deterministic behavior.

### 2. `chatbot.output` types: `str` and `money` aren't valid
The valid primitive types are `int`, `float`, `string`, plus `time(...)`, `date(...)`, and `list[...]`. Custom types like `money` only work if you've defined a `types/money.yml` file in your project. Since I can't see one, safest is to use `string` (or `float` if you want a numeric value).

### 3. Two output fields are missing `type`
`seat_price` and `care_bike` have no `type` — every output field needs one.

### 4. `conversation.number: 5` with no variables
That's fine on its own (a fixed integer is allowed), but since your goals have no `{{variables}}`, running 5 conversations will just repeat the same script. Not an error, just a heads-up. If you want variety, add variables; otherwise `number: 1` is more sensible.

### 5. `goal_style` is missing
Not strictly required, but without it the conversation has no defined end condition. I'd recommend adding `all_answered` so it stops once all outputs are collected (this matches what your original `qa.yml` did).

## A couple of extra tips 💡

- **Want numeric prices?** If you'd rather extract prices as numbers (useful for rules later), define a custom `money` type in `types/money.yml` and then `type: money` will work. Otherwise `string` is perfectly fine for QA-style checks.
- **`is_starter: false`** means the bot speaks first. Your original had `true` — double-check which one matches your bot's actual behavior, otherwise the conversation may start awkwardly.
- **`interaction_style: [default]`** is valid but redundant — you can omit the field entirely if you want natural behavior.
