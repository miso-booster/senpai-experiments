## YAML Connector

```yaml
name: "SAIC Málaga"
base_url: "https://api.1millionbot.com"
send_message:
  path: "/api/public/messages"
  method: "POST"
  headers:
    Content-Type: "application/json"
    Authorization: "64e5d1af081211d24e2cfecd"
  payload_template:
    conversation: "6977595c744ccf01954b8797"
    sender_type: "User"
    sender: "6977595c3e4824018e496b0c"
    bot: "64e5d1af081211d24e2cfec8"
    language: "es"
    url: "https://saic.malaga.eu/"
    message:
      text: "{user_msg}"
response_path: "response.0.text"
```

## Notas importantes 👀

**Sobre los headers:** dejé solo los mínimos necesarios (`Content-Type` y `Authorization`). No incluí `Origin` ni `Referer` porque son headers específicos de navegador y no forman parte del mínimo requerido. Si la API los exige estrictamente, avísame y los añadimos.

**Sobre el `response_path`:** apunta a `response.0.text`, que es donde vive el texto de respuesta del bot:
```yaml
name: "Ada UAM"
base_url: "https://api.1millionbot.com"
send_message:
```

Esto extrae exactamente `"<p>¡Buenos días!<br><br>¿En qué puedo ayudarte?</p>"`.

## ⚠️ Un detalle sobre "quitar las etiquetas HTML"

Aquí tengo que ser honesto contigo: **el connector YAML por sí solo no puede eliminar las etiquetas HTML** del texto de respuesta. El campo `response_path` únicamente navega el JSON y extrae el valor tal cual — en este caso, el texto llegará con las etiquetas `<p>` y `<br>` incluidas.

Para devolver texto plano sin HTML necesitarías un paso de limpieza posterior en el código que consume el connector (por ejemplo, con una función que elimine las etiquetas del string). El YAML no tiene una opción nativa para "strip HTML".
