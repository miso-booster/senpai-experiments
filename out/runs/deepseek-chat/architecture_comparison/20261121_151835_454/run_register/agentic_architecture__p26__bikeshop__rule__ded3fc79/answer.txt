## ❌ What's wrong with the current rule

```yaml
name: check_tune_up_price
description: Checks if the tune-up price is equal to $50.
conversations: 2
when: conv[0].tune_up_price == 50
if: conv[0].tune_up_price is not None
then: "The tune-up price is $50."
```

1. **`when` is doing the actual check** — `when` is a *filter* to select comparable conversations, not the assertion. Putting the price equality there means the rule only "applies" to conversations that already pass, so it can never fail. The real check must live in `oracle` (or `if`/`then`).
2. **`then` is a plain string** — `then` must be a **boolean Python expression**, not a sentence. `"The tune-up price is $50."` is a truthy string, so it always passes. The human-readable message belongs in `yields` (or `on-error`).
3. **`conversations: 2` is wrong** — this is a single-conversation check, so it should be `conversations: 1`. With `2`, the engine expects a metamorphic pair and `conv[0]`/`conv[1]` comparisons.
4. **`== 50` on a `money` field** — `tune_up_price` is typed `money` in the profiles, so it's a string like `"$50"` or `"50 USD"`. Comparing it directly to the integer `50` won't work. You need `extract_float(...)` (and optionally `currency(...)`).
5. **`if`/`then` are redundant here** — since you want a simple "price equals $50" check, a single `oracle` is cleaner. The `if: ... is not None` guard is better expressed inside the oracle.

## ✅ Fixed rule

```yaml
name: check_tune_up_price
description: Checks that the tune-up price equals $50 (profile bike_service_and_repair_inquirer / bike_repair_and_maintenance_scheduler).
conversations: 1
active: true
oracle: conv[0].tune_up_price is not None and extract_float(conv[0].tune_up_price) == 50
yields: f"Expected tune-up price of $50, got {conv[0].tune_up_price}"
```
