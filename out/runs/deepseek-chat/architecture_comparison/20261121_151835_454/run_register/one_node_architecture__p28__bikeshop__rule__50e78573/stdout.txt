Absolutely! 😊 That's a great check to have — and good news: Sensei-check already ships a helper made exactly for this: `responds_in_same_language()`. It verifies that the assistant's replies match the language the user is speaking, so you don't have to hardcode any language yourself.

Here's a clean, ready-to-use rule for your bikeshop project:

```yaml
name: chatbot_responds_in_same_language
description: The chatbot replies in the same language the user is using
conversations: 1
active: true
oracle: responds_in_same_language() is True
yields: f"The chatbot did not respond in the same language as the user"
```

A couple of friendly notes 👀:

- This is a **global rule** — it doesn't depend on any `chatbot.output` field, so it works across all your profiles (including `language_issue.yml` and `user_sim_bikesqa.yml`, which mixes Spanish).
- The helper is **LLM-backed**, so expect tiny variability. If you want to be extra strict about a specific language, you can pair it with `language(chatbot_phrases) == 'ENG'` — but `responds_in_same_language()` is usually the more flexible choice.

Want me to also add a companion rule that flags when the bot *fails* to switch languages (e.g., for your `language_issue` profile)? Just say the word! 🚲
