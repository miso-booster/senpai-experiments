## What is an oracle? 🔮

In Sensei-check, an **oracle** is simply the **condition that a rule checks** — the actual test assertion. Think of it as the "expected truth" that Sensei-check verifies against your generated conversations.

You can write it in two ways:

### 1️⃣ A single `oracle:` expression

This is a boolean Python expression that must evaluate to `True` for the rule to pass. It's perfect for **single-conversation** checks or **global** checks.

```yaml
name: only_talks_about_pizzas
description: The chatbot only talks about pizzas
conversations: 1
oracle: only_talks_about('pizza orders, drink orders, information on delivery of pizzas, information about the pizza shop')
```

Here, the oracle is `only_talks_about(...)` — if it returns `True`, the rule passes. ✅

### 2️⃣ An `if` / `then` pair (for metamorphic relations)

For **metamorphic rules** (comparing 2+ conversations), you often use `if`/`then` instead. Together they *form* the oracle — the relation that must hold:

```yaml
name: more_toppings_cost_more
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

The `if`/`then` reads like a law: *"If conversation 0 has more toppings, then it must cost more."* That's the oracle. 🍕💰

---

## Quick mental model 🧠

| Piece | Role |
|-------|------|
| `when:` | **Filter** — which conversations are eligible to be compared |
| `oracle:` **or** `if:`/`then:` | **The check itself** — what must be true |
| `yields:` / `on-error:` | Optional **message** shown when the check fails |

So in short: **the oracle is the "what should be true" part of a rule** — the heart of the test. Everything else (`when`, `conversations`, `yields`) supports it. 💡
