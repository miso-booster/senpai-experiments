## ❌ What's wrong with the current rule

```yaml
name: check_tune_up_price
description: Checks if the tune-up price is equal to $50.
conversations: 2
when: conv[0].tune_up_price == 50
if: conv[0].tune_up_price is not None
then: "The tune-up price is $50."
```

1. **`conversations: 2` is wrong for this check.** You're only inspecting `conv[0]`, so this isn't a metamorphic (2-conversation) rule — it's a single-conversation oracle. It should be `conversations: 1`.
2. **`then:` is a plain string, not an expression.** In the DSL, `then:` must be a boolean Python expression (e.g. `extract_float(conv[0].price) == 50`). A quoted sentence like `"The tune-up price is $50."` is not evaluable — that text belongs in `yields:` (the error message), not `then:`.
3. **`when:` is doing the check instead of filtering.** `when:` is a *filter* to select eligible conversations, not the assertion. The actual assertion should live in `oracle:` (or `if`/`then`).
4. **Comparing a `money`/`currency` field directly to `50` won't work reliably.** `tune_up_price` is typed `money` in your profiles, so it's a string like `"$50"` or `"50 USD"`. You need `extract_float(...)` to parse the number (docs: "Prefer numeric comparisons on parsed values").
5. **`if`/`then` is the wrong shape here.** There's no implication to express — you just want a straight assertion, so `oracle:` is the right choice.

Both have a `tune_up_price` field, so the rule works for either. Here's the corrected rule:

```yaml
name: check_tune_up_price
description: Checks that the tune-up price is $50 (profile-bound to bike tune-up profiles exposing tune_up_price).
conversations: 1
when: conv[0].tune_up_price is not None
oracle: extract_float(conv[0].tune_up_price) == 50
yields: f"Expected tune-up price of $50, got {conv[0].tune_up_price}"
```
