Here's the connector for the Alcampo bot 🍕🤖 — I've mapped the nested payload and pointed `response_path` at the first message text in the response:

```yaml
name: "Alcampo"
base_url: "https://alcampo.botslovers.com"
send_message:
  path: "/bot/web"
  method: "POST"
  headers:
    Content-Type: "application/json"
    Accept: "*/*"
    Accept-Language: "en-US,en;q=0.9"
    Origin: "https://alcampo.botslovers.com"
    Referer: "https://alcampo.botslovers.com/Admin/Widget?mobile=0&user=0&lang=es"
    Sec-GPC: "1"
    Sec-Fetch-Dest: "empty"
    Sec-Fetch-Mode: "cors"
    Sec-Fetch-Site: "same-origin"
    Pragma: "no-cache"
    Cache-Control: "no-cache"
  payload_template:
    data:
      id_user: "377611"
      idweb_user: "ea38fe92-ad92-4610-9d62-ef7fecb1679b"
      session: "729745848fcf76b3a49c2e2c4e6f2d5e"
      message:
        message:
          message:
            text: "{user_msg}"
        iduser: "377611"
        session: "729745848fcf76b3a49c2e2c4e6f2d5e"
        channel: "web"
      widget_form: "TRUE"
      contexto_extra: []
      lang: "es"
    accion: "response_bot"
response_path: "messages.0.0.message.text"
```

A couple of quick notes to keep in mind 👀:

- **`response_path`** — the reply lives at `messages[0][0].message.text`, so the dot path is `messages.0.0.message.text`. If the bot ever returns multiple bubbles, you may want to adjust this (or handle it in code) to grab the last one.
- **Session / user IDs** — I kept the values from your sample request. If the bot expects a fresh `session` per run, you'd need to generate one dynamically (the static YAML connector can't rotate it on its own).
- **Headers** — I included the meaningful ones (`Content-Type`, `Origin`, `Referer`, etc.) and dropped hop-by-hop/transport-only ones like `Host`, `Content-Length`, `Connection`, `TE`, `Accept-Encoding`, and `Priority`, since those are handled by the HTTP client.
