Here's a profile that starts with a custom pizza request and then switches to a predefined menu pizza partway through. It keeps the `price`, `time`, and `order_id` output names from your existing pizza profiles so any profile-bound rules you already have keep working.

```yaml
test_name: "pizza_order_custom_then_predefined"

llm:
  temperature: 0.8
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: >
    You are a customer ordering a pizza over the phone. You start by asking
    for a fully custom pizza with your own chosen size and toppings, but
    halfway through the conversation you change your mind and decide to order
    a predefined pizza from the menu instead.
  context:
    - personality: personalities/conversational-user.yml
    - your name is Jon Doe
    - "You are indecisive: you first want a custom pizza, then switch to a menu pizza."
  goals:
    - "I'd like a {{size}} custom pizza with {{toppings}}"
    - "Actually, forget the custom one — I'll take a {{pizza_type}} pizza instead"
    - "{{cans}} cans of {{drink}}"
    - how long is the pizza going to take to arrive
    - how much will it cost

    - size:
        function: pairwise()
        type: string
        data:
          - small
          - medium
          - big
          - extra large

    - toppings:
        function: pairwise()
        type: string
        data:
          - cheese
          - mushrooms
          - pepperoni
          - ham
          - olives

    - pizza_type:
        function: forward()
        type: string
        data:
          - Margherita
          - Pepperoni
          - Four Cheese
          - Vegetarian
          - Hawaiian

    - cans:
        function: forward(drink)
        type: int
        data:
          min: 1
          max: 4
          step: 1

    - drink:
        function: forward()
        type: string
        data:
          - Sprite
          - Coca-Cola
          - Orange Fanta

chatbot:
  is_starter: false
  fallback: "I'm sorry it's a little loud in my pizza shop, can you say that again?"
  output:
    - price:
        type: currency
        description: "The final price of the pizza order"
    - time:
        type: time("hh:mm:ss")
        description: "Estimated time until the pizza is ready / arrives"
    - order_id:
        type: string
        description: "The order identifier"
    - final_pizza:
        type: string
        description: "The pizza the order was finally placed with (should be the predefined menu pizza, not the custom one)"

conversation:
  number: 2
  goal_style:
    steps: 6
    max_cost: 0.15
  interaction_style:
    - change your mind
    - random:
        - make spelling mistakes
        - long phrases
```

### What it does & how it maps to the docs (`sensei-chat-guide.md`)

- **Change of mind is built in two ways** 🎯
  - The **goal sequence** explicitly goes custom → predefined: the second goal starts with *"Actually, forget the custom one…"*.
  - The **`change your mind` interaction style** (§5) reinforces this — the docs describe it as *"useful in conversations when the user has to provide information, such as toppings on a pizza"*, which is exactly your scenario.
- **Variables** (`size`, `toppings`, `pizza_type`, `cans`, `drink`) are declared in `user.goals` with matching `{{…}}` usage, per §4.1/§9.
- **`pairwise()`** on `size` and `toppings` covers combinations efficiently (§9 best practice), while `forward()` chains `cans` on `drink` and iterates `pizza_type`.
- **`chatbot.output`** (§6) keeps your existing `price`, `time`, `order_id` fields and adds **`final_pizza`** so a rule can later verify the bot actually placed the *predefined* pizza (not the abandoned custom one). This is the contract rules read as `conv[i].final_pizza`.
- **`goal_style.steps: 6`** gives enough turns for the custom request, the switch, drinks, and the time/price questions; `max_cost` caps spend per §5.

### A couple of things worth confirming 🙋
1. **`final_pizza`** is a new output field — if you already have profile-bound rules on the pizza profiles, they won't be affected, but if you want a rule checking the switch, this field is what it'll read. Want me to draft that rule next?
2. The `personality: personalities/conversational-user.yml` reference matches your other pizza profiles — just make sure that file exists in your project (the predefined profile uses `personalities/conversational-user.yml`, the custom one uses `conversational-user.yml`).
