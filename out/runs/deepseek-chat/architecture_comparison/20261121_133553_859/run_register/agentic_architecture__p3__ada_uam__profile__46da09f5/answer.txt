## 🔍 Problemas encontrados

1. **`user.goals` mal formado (el más grave).** Las variables `identificador_id_uam` y `user_account` están declaradas *dentro* de la lista de goals, pero con una indentación rota: `type`, `data`, etc. quedaron colgando como si fueran items de la lista de goals. Además, la variable `identificador_id_uam` **no tiene su clave declarada** (falta `identificador_id_uam:` antes de `type: string`). Según la guía (§4.1), cada `{{variable}}` debe declararse como un mapping con su nombre exacto.

2. **Falta `user.role`.** Es opcional, pero muy recomendable para darle contexto al simulador. Lo añadí.

3. **`chatbot.output` con duplicados conceptuales.** Tienes `contact_info` y `contact_information` (dos campos para lo mismo) y `password_setup_link` vs `password_change_steps`. No es un error de sintaxis, pero conviene consolidar para que las reglas no se confundan. Los dejé pero te lo señalo abajo.

4. **`conversation.goal_style.steps: 30`.** Es válido (no hay tope duro documentado para `steps` fijo), pero es muy alto para 5 conversaciones. Lo dejé como pediste, solo lo menciono.

5. **`llm` sin `model_prov`.** Opcional (la guía dice que si se omite se usan defaults), pero lo añadí como `openai` para que sea explícito y consistente con `gpt-4o-mini`.

## 📝 Resumen de cambios

| Cambio | Motivo (según `sensei-chat-guide.md`) |
|---|---|
| Añadida clave `identificador_id_uam:` | Cada `{{variable}}` debe declararse con su nombre exacto (§4.1). |
| Corregida indentación de `type`/`data` | Las variables son mappings dentro de `goals`, no items sueltos (§4.1, §4.3). |
| Añadido `function: random()` a ambas variables | Sin `function` no se define cómo se elige el valor en cada conversación (§4.4). |
| Añadido `user.role` | Recomendado para dar contexto al simulador (§3, §7). |
| Añadido `model_prov: openai` | Explicitar el proveedor del modelo (§3). |
| `fallback` en una sola línea | El `\n` literal no se interpreta en YAML plano; ahora es texto limpio. |

## ⚠️ Sugerencias opcionales (no las apliqué para no cambiar tu diseño)

- **Consolidar campos duplicados** en `chatbot.output`: `contact_info` vs `contact_information`, y `password_setup_link` vs `password_change_steps`. Si vas a escribir reglas, nombres únicos y estables ayudan mucho (§2.1.2).
- **`steps: 30`** es alto; si quieres conversaciones más cortas, considera `random steps: 10` o `all_answered` con `limit`.
