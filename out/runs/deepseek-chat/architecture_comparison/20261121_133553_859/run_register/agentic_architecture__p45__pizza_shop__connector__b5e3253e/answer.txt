### What I did and why

- **Docs used:** `custom-connector-guide.md` and `connector-examples.md`.
- **Headers:** kept only the two that actually matter for the API call — `Content-Type: application/json` and `Authorization`. I dropped `Host`, `Origin`, and `Referer`, since those are browser/transport-level headers and not needed (the guide's MillionBot example only uses `Content-Type` + `Authorization`).
- **Payload:** mapped 1:1 from your request body, with `message.text` set to the `{user_msg}` placeholder as required by the docs.
- **Response:** `response_path: "response.0.text"` extracts the first element of the `response` array, matching the documented dot-notation behaviour (`results.0.content` style).

### ⚠️ One thing to flag about "HTML tags removed"

The connector DSL (per `custom-connector-guide.md`) only supports **extracting** a value via `response_path` — there's **no documented option to strip HTML** from the extracted text. So the raw value returned would be:

```
<p>¡Buenos días!<br><br>¿En qué puedo ayudarte?</p>
```

I don't want to invent an undocumented field like `strip_html: true`, so I left it out. A couple of options:

1. **Handle it downstream** — in your SENSEI rules, use the documented text helpers to normalise/compare content rather than relying on exact HTML.
2. **Check with me** — if your version of the connector supports a post-processing option, tell me the exact field name and I'll add it.
