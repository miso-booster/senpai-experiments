Great question! 😊 Let me walk you through which fields in a Sensei profile are **optional** versus which ones you really need.

## The short answer

In a Sensei profile, the **only truly mandatory** pieces are the ones that give Sensei something to simulate and somewhere to talk to. Everything else has sensible defaults or is purely for convenience.

## Field-by-field breakdown

### 🔴 Required (you need these)

| Field | Why |
|-------|-----|
| `user.role` | Tells the simulator *who* it is |
| `user.goals` | Gives the simulator *what to do* (at least one goal) |
| `chatbot.output` | Defines what gets extracted at the end (needed for rules to read `conv[i].field`) |

> Note: `chatbot.output` is technically optional for a *run*, but if you want Sensei-check rules to inspect fields, it becomes essential. Treat it as required in practice.

### 🟢 Optional (defaults apply or it's just convenience)

| Field | What happens if you omit it |
|-------|-----------------------------|
| `test_name` | A default name is used |
| `llm` | Defaults are applied (model, temperature) and format defaults to `text` |
| `llm.format` | Defaults to `text` |
| `llm.format.config` | Only needed when `type: speech` |
| `user.language` | Defaults to English |
| `user.context` | No extra persona/constraints added |
| `chatbot.is_starter` | Defaults to `false` |
| `chatbot.fallback` | No fallback text injected (but strongly recommended to avoid loops!) |
| `conversation.number` | Defaults apply |
| `conversation.max_cost` | No run-wide cost cap |
| `conversation.goal_style` | Defaults apply |
| `conversation.goal_style.max_cost` | No per-conversation cap |
| `conversation.interaction_style` | Natural/default behavior |
| `active` (on rules, not profiles) | — |

## A quick mental model 🧠

Think of it like ordering at a restaurant:
- **Required** = what you're eating and who you are (role + goals + what to extract).
- **Optional** = the ambiance, the music, the lighting — nice to have, but the kitchen still works without them.

## ⚠️ One important caveat

Even though `chatbot.fallback` is optional, **please set it** to your bot's *real* fallback message. Without it, the simulator can get stuck in endless loops — and nobody wants that! 😅
