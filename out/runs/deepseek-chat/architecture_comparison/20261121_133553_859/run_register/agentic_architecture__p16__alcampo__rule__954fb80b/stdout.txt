## The rule (rule-first design, per §3.2 of `sensei-check-doc.md`)

```yaml
name: lactose_free_availability_consistency
description: >
  Checks that lactose-free product availability is reported consistently.
  If the chatbot confirms lactose-free products are available, it must also
  name at least one lactose-free brand or product; if it says they are not
  available, it must not list any lactose-free brand.
conversations: 1
active: true
oracle: |
  (
    'available' in str(lactose_free_availability).lower()
    and str(lactose_free_availability).lower().find('not available') == -1
    and len(str(lactose_free_cheese_brands).strip()) > 0
  ) or (
    'not available' in str(lactose_free_availability).lower()
    and str(lactose_free_cheese_brands).strip() in ('', 'None')
  )
yields: |
  f"Lactose-free availability='{lactose_free_availability}' but brands='{lactose_free_cheese_brands}'"
```

## How it maps to a profile
This rule assumes a profile whose `chatbot.output` provides these fields (they already exist in `dietary_needs_and_special_products_inquiry.yaml`):

| Field | Type | Purpose |
|---|---|---|
| `lactose_free_availability` | `string` | Whether lactose-free products are available |
| `lactose_free_cheese_brands` | `string` | Brands/products named for lactose-free items |
