Absolutely! 😊 That's a great guardrail to have — and Sensei-check has a built-in helper for exactly this: `responds_in_same_language()`. It checks that the assistant replies in the same language the user is writing in, so you don't have to hardcode any specific language.

Here's a ready-to-use rule:

```yaml
name: chatbot_responds_in_same_language
description: The chatbot responds in the same language as the user
conversations: 1
active: True
oracle: responds_in_same_language()
yields: f"The chatbot does not respond in the same language as the user"
```

A couple of quick notes 👇

- **`conversations: 1`** means this is a single-conversation oracle — it runs on each conversation individually, which is perfect for a language-consistency check.
- **`responds_in_same_language()`** is an LLM-backed helper, so expect a tiny bit of variability. It's naturally a *global* rule (profile-agnostic), so it works across all your bike-shop profiles without depending on any `chatbot.output` fields. 🎯
- The **`yields`** message is what shows up when the rule fails — handy for debugging.

This is especially useful for your `language_issue.yml` profile, where the user deliberately writes in a non-English/Spanish language and the bot should still mirror the user's language (or handle it gracefully).
