## 🔍 Problemas detectados

1. **`user.goals` mal formado (el más grave):** Mezclaste las metas (strings) con las declaraciones de variables, pero la variable `identificador_id_uam` **no tiene su clave declarada**. Tienes:
   - Pedir información sobre el proceso de recuperación del {{identificador_id_uam}} si lo he olvidado.
   - Consigue el código de activación necesario para cambiar la contraseña de {{user_account}}.
       type: string
       data:
       - '123456789'
       ...
   Aquí `type`/`data` quedaron colgando de la meta-string, y falta la clave `identificador_id_uam:` como mapping. Además `user_account` aparece declarada **dos veces** (una vez mal pegada y otra bien).

2. **`{{user_account}}` se usa en una meta** ("cambiar la contraseña de {{user_account}}"), pero según la guía, las variables declaradas deben usarse en los prompts — eso está bien — pero el orden/estructura estaba roto.

3. **`chatbot.output` con `type: string` para todo:** Funciona, pero para campos como `activation_code` o `identificador_id_uam` conviene revisar si quieres tipos más específicos. No es un error, solo una mejora opcional.

4. **`conversation.goal_style.steps: 30`:** La guía indica que `steps` fijo es válido, pero si usas `random steps: M` debe ser `M ≤ 20`. Con `steps: 30` fijo no hay problema, pero es alto para 5 conversaciones. Lo dejo pero te lo señalo.

5. **Falta `user.role`:** No es obligatorio, pero la guía lo recomienda para dar contexto al simulador. Es opcional.

6. **`llm.model_prov` ausente:** Opcional (hay defaults), pero si usas `gpt-4o-mini` conviene añadir `model_prov: openai` para evitar ambigüedad.

| Cambio | Motivo (según `sensei-chat-guide.md`) |
|---|---|
| Añadí la clave `identificador_id_uam:` como mapping con `function`/`type`/`data` | Las variables deben declararse como mapping propio, no colgando de un string (§4.1, §4.4) |
| Eliminé la declaración duplicada de `user_account` | Solo debe declararse una vez, con nombre exacto (§9) |
| Añadí `function: random()` a ambas variables | La guía recomienda declarar la función de selección (§4.4) |
| Añadí `user.role` | Recomendado para dar contexto al simulador (§3) |
| Añadí `model_prov: openai` | Evita ambigüedad de proveedor con `gpt-4o-mini` (§3, §11) |
| Unifiqué el `fallback` en una sola línea | Los `\n` literales no se interpretan como saltos en YAML plano; mejor texto limpio |
