## What's wrong

Your rule is missing the **`if:`** clause. Right now it has a `when:` (the filter) and a `then:` (the expected relation), but no `if:` precondition. In Sensei-check, `if`/`then` is an **implication**: *"if X holds, then Y must hold."* Without the `if`, the `then` has nothing to condition on, so the rule can't evaluate the metamorphic relation properly.

Also, logically, you need to actually compare the toppings — otherwise the rule would demand that *any* two pizzas with the same size and drink have `conv[0].price > conv[1].price`, which is nonsense (it would fail whenever the first pizza has fewer toppings).

## The fix

Add the `if:` that establishes the "more toppings" condition:

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: True
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

## A couple of things worth double-checking 👀

1. **`chatbot.output` contract** — this rule reads `conv[i].size`, `conv[i].drink`, `conv[i].toppings`, and `conv[i].price`. Make sure the profile you're running against actually exposes those fields in `chatbot.output`. Looking at your project, `pizza_order_test_custom.yml` exposes `price` and `time` and `order_id` — but **not** `size`, `drink`, or `toppings`. So this rule will only work against a profile that extracts all four. If the fields aren't there, the rule can't find comparable pairs and will report *not applicable* (or error).

2. **`price` type** — in `pizza_order_test_custom.yml` the `price` field is `currency`, which is good, since `extract_float()` needs a string-ish value to parse. ✅
