Hey there! 😊 Happy to help you build that profile. Quick heads-up before the YAML: for `conversation.number` to be derived from a pairwise matrix, you need **at least two variables using `pairwise()`** — which your request already covers. I've set `number: combinations(pairwise)` so Sensei computes the count from the matrix automatically.

A couple of design notes:
- The rude/impatient vibe goes in `role` + `context` (there's a `personalities/rude-user` reference in your project already — I reused it).
- I kept `chatbot.output` aligned with fields your existing rules already reference (`size`, `toppings`, `drink`, `price`) so `more_toppings_cost_more` and `same_number_of_toppings_cost_the_same` stay compatible. 👌

```yaml
test_name: "rude_impatient_pizza_order"

llm:
  temperature: 0.8
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: >
    You are a rude, impatient customer ordering pizza. You are in a hurry and
    have zero patience for slow or unclear responses. You snap at the bot,
    demand things be done fast, and get annoyed if it asks too many questions.
    Keep it short, blunt, and pushy — but still place a complete order.
  context:
    - personality: personalities/rude-user
    - "You are ordering on your lunch break and only have a few minutes."
    - "You hate small talk and want the bot to get straight to the point."
    - "If the bot is slow or vague, tell it to hurry up."
  goals:
    - "Demand a {{pizza_type}} pizza, {{size}} size, right now."
    - "Tell them to add {{toppings}} and stop wasting your time."
    - "Bark that you want {{number}} cans of {{drink}}, fast."
    - "Ask how much it costs and how long it'll take — and make it quick."
    - pizza_type:
        function: pairwise()
        type: string
        data: [Margarita, Pepperoni, Hawaiian, Vegetarian, Four cheese]
    - size:
        function: pairwise()
        type: string
        data: [small, medium, large]
    - toppings:
        function: forward()
        type: string
        data: [cheese, mushrooms, pepperoni, olives]
    - drink:
        function: forward()
        type: string
        data: [Coke, Sprite, Fanta]
    - number:
        function: forward(drink)
        type: int
        data:
          min: 1
          max: 4
          step: 1

chatbot:
  is_starter: false
  fallback: "I'm sorry, I did not get what you said. I can help you ordering predefined or custom pizzas, and then drinks."
  output:
    - size:
        type: string
        description: "Pizza size chosen (small / medium / large)"
    - toppings:
        type: list[string]
        description: "List of toppings on the pizza"
    - drink:
        type: string
        description: "Drink chosen"
    - number:
        type: int
        description: "Number of drinks ordered"
    - price:
        type: currency
        description: "Final price of the order"
    - order_id:
        type: string
        description: "Order identifier"

conversation:
  number: combinations(pairwise)
  goal_style:
    all_answered:
      export: false
      limit: 20
    max_cost: 0.8
  interaction_style:
    - long phrases
    - random:
        - make spelling mistakes
        - single questions
```

A few things worth flagging so nothing surprises you later 👀:

- **`combinations(pairwise)`** — this pulls the conversation count from the pairwise matrix generated by `pizza_type` × `size`. If you'd rather cap it (e.g. 60% of the matrix), swap to `combinations(0.6, pairwise)`.
- **`number` uses `forward(drink)`** — it's nested so each drink gets its own 1–4 range, which keeps the order combos sensible.
- **`chatbot.output` fields** (`size`, `toppings`, `drink`, `price`) match what your active rules `more_toppings_cost_more` and `same_number_of_toppings_cost_the_same` expect — so those rules will keep working against this profile. ✅
- **`price` is typed `currency`** so `extract_float(...)` and `currency(...)` helpers behave nicely in rules.
