Absolutely! 😊 That's a great guardrail to have — and Sensei-check has a built-in helper made exactly for this: `responds_in_same_language()`. It checks that the assistant replies in the same language the user is writing in, so you don't need to hardcode any specific language.

Here's a clean, ready-to-use rule:

```yaml
name: chatbot_responds_in_same_language
description: The chatbot always replies in the same language the user is using
conversations: 1
active: True
oracle: responds_in_same_language()
yields: f"The chatbot does not respond in the same language as the user"
```

A couple of quick notes 👇

- **`conversations: 1`** → this is a single-conversation oracle, so it runs per conversation. That's perfect here since language consistency is a per-dialog property.
- **`responds_in_same_language()`** is LLM-backed, so allow for a tiny bit of variability — but it's the right tool for the job.
- **`yields`** gives you a friendly failure message when the rule breaks.

This is a **global rule** (profile-agnostic) — it doesn't depend on any `chatbot.output` fields, so it'll work across all your bike shop profiles, including `language_issue.yml` and `user_sim_bikesqa.yml` (which uses Spanish!). 🚴
