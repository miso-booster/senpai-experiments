Let's dig into this rule. The good news: it's *almost* right — it's missing one key piece.

## 🐛 Why it's not working

Your rule:

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: True
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

There are two problems:

**1. There's no `if:` — so `then:` has no trigger.** ❌
In the DSL, `then:` is the *consequence* of an `if:` precondition (see `sensei-check-doc.md` §4, "Option B: if/then relation"). Without an `if:`, there's no "more toppings" condition being tested — the rule has nothing to imply. The canonical example in the docs is:

```yaml
name: toppings_monotonicity
description: Adding more toppings to a custom pizza costs more (same size/drink/qty)
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink and conv[0].number == conv[1].number
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Your version dropped the `if:` line, so the metamorphic relation is incomplete.

**2. The `when:` filter is too loose (missing `number`/quantity).** ⚠️
`when:` is supposed to hold *everything else* equal (ceteris paribus — `sensei-check-doc.md` §6.2, §9). If the two conversations differ in pizza quantity, a price difference could come from quantity, not toppings → false failures. The docs' canonical version also pins `conv[0].number == conv[1].number`.

## ✅ The fix

Here's the corrected rule (structure per `sensei-check-doc.md` §5.1 / `rules-examples.md`):

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more (same size, drink and quantity)
active: True
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink and conv[0].number == conv[1].number
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

**What changed & why:**
- ➕ Added `if: len(conv[0].toppings) > len(conv[1].toppings)` — this is the metamorphic trigger that was missing.
- ➕ Added `conv[0].number == conv[1].number` to `when:` — controls the quantity confounder.
- ✏️ Updated `description` to mention the profile/scenario it targets (best practice, `sensei-check-doc.md` §3.3 step 5).
