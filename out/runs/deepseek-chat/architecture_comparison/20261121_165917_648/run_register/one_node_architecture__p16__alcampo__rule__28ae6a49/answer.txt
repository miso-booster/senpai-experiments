Here's a solid starting rule:

```yaml
name: lactose_free_availability_confirmed
description: >
  Checks that when the user asks about lactose-free products, the assistant
  confirms their availability (or clearly states they are unavailable) instead
  of ignoring the question. Targets a future profile exposing
  `lactose_free_availability` and `lactose_free_products` in chatbot.output.
conversations: 1
active: true
when: lactose_free_availability is not None or lactose_free_products is not None
oracle: |
  (lactose_free_availability is not None and len(str(lactose_free_availability)) > 0) \
  or (lactose_free_products is not None and len(lactose_free_products) > 0)
yields: |
  f"Assistant did not confirm lactose-free availability. Got: {lactose_free_availability} / {lactose_free_products}"
```

And if you'd rather check it **semantically** (more robust to phrasing), here's a variant using the `semantic_content` helper:

```yaml
name: lactose_free_availability_semantic
description: >
  Verifies the assistant's lactose-free availability answer semantically
  mentions whether products are available. Expects a profile exposing
  `lactose_free_availability` in chatbot.output.
conversations: 1

when: lactose_free_availability is not None

```

A couple of quick notes so this lands smoothly 👇

- **Field contract:** for these to work, a future profile must expose `lactose_free_availability` (string) and optionally `lactose_free_products` (string or `list[string]`) in its `chatbot.output`. If you rename them later, update the rule to match.
- **`when` guard:** the filter keeps the rule from firing on conversations that never touched lactose-free topics — avoids false positives.
