## The rule

```yaml
name: lactose_free_availability_consistency
description: >
  Rule-first design (no profile yet). Checks that when the user asks about
  lactose-free products, the chatbot confirms availability and reports the
  same availability status for the same product across comparable conversations.
  Requires a future profile exposing: product_name, lactose_free_available,
  lactose_free_brands, lactose_free_price.
active: true
conversations: 2
when: conv[0].product_name == conv[1].product_name
if: conv[0].lactose_free_available is not None and conv[1].lactose_free_available is not None
then: conv[0].lactose_free_available == conv[1].lactose_free_available
yields: |
  f"Lactose-free availability for '{conv[0].product_name}' is inconsistent: "
  f"{conv[0].lactose_free_available} vs {conv[1].lactose_free_available}"
```

And a companion single-conversation sanity check (same field contract):

```yaml
name: lactose_free_availability_reported
description: >
  Rule-first design (no profile yet). When the user asks about a lactose-free
  product, the chatbot must report an availability status and, if available,
  at least one brand. Requires a future profile exposing: product_name,
  lactose_free_available, lactose_free_brands.
active: true
conversations: 1
when: conv[0].product_name is not None
oracle: |
  conv[0].lactose_free_available is not None and (
    conv[0].lactose_free_available is False
    or len(conv[0].lactose_free_brands) > 0
  )
yields: |
  f"No lactose-free availability info for '{conv[0].product_name}' "
  f"(available={conv[0].lactose_free_available}, brands={conv[0].lactose_free_brands})"
```
