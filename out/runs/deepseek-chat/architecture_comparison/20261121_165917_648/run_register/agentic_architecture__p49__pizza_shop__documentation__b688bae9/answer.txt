## What the docs actually describe

**Metamorphic (pairwise-style) rules** are the closest concept. Instead of a single-conversation oracle, you compare **pairs (or tuples) of conversations** that meet a selection filter, and assert how outputs should relate. The mechanism is:

- `conversations: 2` (or more) → tells Sensei-check the rule needs N conversations.
- `when: <expr>` → filters for *comparable* conversations (the "ceteris paribus" cohort), e.g. same size/drink/qty.
- `if: <expr>` / `then: <expr>` → the relation to check across `conv[0]`, `conv[1]`, etc.
- Or a single `oracle: <expr>` over `conv[*]`.

Example from `sensei-check-doc.md`:

```yaml
name: toppings_monotonicity
description: Adding more toppings costs more (same size/drink/qty)
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink and conv[0].number == conv[1].number

then: extract_float(conv[0].price) > extract_float(conv[1].price)
```
