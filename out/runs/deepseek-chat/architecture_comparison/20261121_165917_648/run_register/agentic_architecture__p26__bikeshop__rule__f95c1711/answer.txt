Hey! I checked it against the rules docs (`sensei-check-doc.md` and `rules-examples.md`) and your project profiles — and nope, the rule as written won't work. Here's the breakdown 👇

## What's wrong

1. **`when:` is used as the assertion.** In the DSL, `when:` is a *conversation filter* (it selects which conversations the rule applies to), not the check itself. Your actual check must live in `oracle:` (or in `then:` of an `if`/`then` pair).
2. **`if:` / `then:` are misused.** `then:` must be a **Python expression** that evaluates to a boolean — you put a plain string (`"The tune-up price is $50."`), which is not a check. Also, `if:`/`then:` is meant for implications (precondition → expected relation), not for a single absolute assertion.
3. **`conversations: 2` is unnecessary.** This is a single-conversation check, so it should be `conversations: 1`. With `2` you'd be forcing a metamorphic pairing that doesn't exist here.
4. **`conv[0].tune_up_price == 50` is fragile.** `tune_up_price` is typed `money` in your profiles, so the extracted value is a string like `"$50"` or `"50 USD"`. Comparing it directly to the int `50` will fail. The docs recommend parsing with `extract_float(...)` (and optionally checking `currency(...)`).
5. **Missing `active:` flag** — optional, but good practice to be explicit.

I found two profiles that expose `tune_up_price`:

Both have `tune_up_price`, so this rule works for either:

```yaml
name: check_tune_up_price
description: Checks that the tune-up price is $50 (profile-bound to bike tune-up profiles exposing tune_up_price).
active: true
conversations: 1
oracle: extract_float(tune_up_price) == 50 and currency(tune_up_price) == 'USD'
yields: f"Expected a $50 tune-up price, got {tune_up_price}"
```

| Before | After | Reason |
