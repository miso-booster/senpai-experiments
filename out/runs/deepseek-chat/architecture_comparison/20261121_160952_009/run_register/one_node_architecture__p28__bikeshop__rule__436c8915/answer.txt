Absolutely! 😊 That's a great guardrail to have — and the good news is Sensei-check has a built-in helper for exactly this: `responds_in_same_language()`. It checks that the assistant replies in the same language the user is writing in, so you don't need to hardcode any language.

Here's a clean, ready-to-use rule:

```yaml
name: chatbot_responds_in_same_language
description: The chatbot replies in the same language the user is writing in
conversations: 1
active: true
oracle: responds_in_same_language() is True
yields: f"The chatbot does not respond in the same language as the user"
```

A few friendly notes 👇

- **`conversations: 1`** — this is a single-conversation oracle, so it runs per conversation. That's perfect for a language-consistency guardrail.
- **`responds_in_same_language()`** is LLM-backed, so allow for a tiny bit of variability — but it's the most robust way to check this without pinning a specific language.
- **`yields`** gives you a helpful message when the rule fails, which makes debugging way nicer.

This rule pairs beautifully with your `language_issue` profile (where the user speaks a non-English/Spanish language) — it'll catch cases where the bot slips into the wrong language instead of asking the user to switch. 🚴‍♀️
