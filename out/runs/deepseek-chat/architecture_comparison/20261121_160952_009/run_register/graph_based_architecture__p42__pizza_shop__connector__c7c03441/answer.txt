## 🔍 Qué está fallando

**1. `base_url` incorrecto**
Tu YAML apunta a `https://api.bot.com`, pero el request real va a `api.1millionbot.com`. ¡Ese es el primer bloqueo!

**2. `path` incorrecto**
Tú tienes `/api/messages`, pero el endpoint real es `/api/public/messages`.

**3. Falta el header `Authorization`**
El servidor espera `Authorization: 64e5d1af081211d24e2cfecd`. Sin él, la API te rechazará la petición.

**4. Faltan campos en el `payload_template`**
El body real incluye `conversation`, `sender_type`, `sender`, `bot` y `url`. Tu plantilla solo manda `language` y `message.text`, así que la API no sabe con qué bot ni conversación hablar.

**5. `response_path` apunta al sitio equivocado**
Tienes `request.text`, que devuelve **tu propio mensaje** (el eco de lo que enviaste). La respuesta del bot está en `response.0.text` — fíjate en el JSON de respuesta:

```json
{
  "request": { "text": "hola" },
  "response": [ { "text": "<p>¡Buenos días!...</p>" } ]
}
```

## ✅ Connector corregido

```yaml
name: "Connector"
base_url: "https://api.1millionbot.com"
send_message:
  path: "/api/public/messages"
  method: "POST"
  headers:
    Content-Type: "application/json"
    Authorization: "64e5d1af081211d24e2cfecd"
  payload_template:
    conversation: "6977595c744ccf01954b8797"
    sender_type: "User"
    sender: "6977595c3e4824018e496b0c"
    bot: "64e5d1af081211d24e2cfec8"
    language: "es"
    url: "https://saic.malaga.eu/"
    message:
      text: "{user_msg}"
response_path: "response.0.text"
```

## 💡 Un par de notas amistosas

- El `response_path: "response.0.text"` es el que ya usas en tu connector **Ada UAM** — ¡misma familia de API (1millionbot)! Así que este patrón te resultará familiar 😄
- El texto de respuesta viene con HTML (`<p>...</p>`). Si quieres mostrarlo limpio en tu interfaz, tendrás que renderizarlo como HTML o limpiar las etiquetas.
- Los valores de `conversation`, `sender` y `bot` son específicos de esa sesión/bot de Málaga. Si vas a reutilizar el connector con otro bot, recuerda cambiarlos.
