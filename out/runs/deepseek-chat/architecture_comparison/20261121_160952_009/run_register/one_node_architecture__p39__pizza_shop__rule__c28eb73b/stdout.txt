Hey there! 😊 Happy to help you build that metamorphic rule.

Quick heads-up before the YAML: for this rule to work, your profile's `chatbot.output` needs to expose a `drink` field (so the rule can tell whether a drink was added) and a `price` field (so we can compare totals). I noticed your `pizza_and_drink_order_placement` profile exposes `total_cost` rather than `price` — so if that's the profile you're targeting, you'll want to swap `price` → `total_cost` in the rule below. I'll keep `price` as the field name since that matches the pizza examples, but just flagging it 👀.

Here's the rule — it compares two conversations with the same pizza configuration, where one has a drink and the other doesn't, and asserts the price difference is exactly $2:

```yaml
name: drink_costs_two_extra
description: Adding a drink to an otherwise identical order costs exactly 2 dollars more
conversations: 2
when: conv[0].size == conv[1].size and conv[0].toppings == conv[1].toppings and conv[0].number == conv[1].number
if:   conv[0].drink is not None and conv[1].drink is None
then: abs((extract_float(conv[0].price) - extract_float(conv[1].price)) - 2) < 0.01
```

A couple of notes so it behaves the way you expect 💡:

- **`when`** keeps the pizza side identical (size, toppings, quantity) so the only thing that changes is the drink — that's the *ceteris paribus* magic of metamorphic testing.
- **`if`/`then`** reads like a law: *if* one order has a drink and the other doesn't, *then* the price gap should be $2.
- I used `abs(...) < 0.01` instead of `== 2` to be safe against tiny floating-point rounding wobbles.
- If your profile uses `total_cost` instead of `price`, just rename it in the `then` clause.
