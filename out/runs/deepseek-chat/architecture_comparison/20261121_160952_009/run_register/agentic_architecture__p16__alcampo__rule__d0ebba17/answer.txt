```yaml
name: lactose_free_availability_consistency
description: >
  For lactose-free product inquiries, the chatbot must report availability
  consistently: if a product is marked as available, it must also be flagged
  as lactose-free and have a non-empty availability status. Rule-first design;
  assumes a future profile exposing product_name, is_lactose_free,
  is_available and availability_status.
active: true
conversations: 1
when: is_lactose_free == True
if: is_available == True
then: availability_status is not None and availability_status != ''
yields: |
  f"Lactose-free product {product_name} reported available but availability_status is empty"
```

### What this checks
- **Scope (`when`)**: only conversations where the product is actually lactose-free (`is_lactose_free == True`).
- **Relation (`if`/`then`)**: if the bot says the product is available, then it must also provide a concrete availability status (not empty/null). This catches the classic bug where a bot claims "yes, we have it" but never gives a real stock/availability answer.
