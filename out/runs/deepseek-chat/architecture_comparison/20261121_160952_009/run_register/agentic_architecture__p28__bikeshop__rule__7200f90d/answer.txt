Here's a quick rundown of what I did and why 😊

## What this rule does
- **`responds_in_same_language()`** is a built-in helper that checks whether the assistant's replies match the language the user is writing in. It returns `True` when they match, so the oracle passes.
- **`conversations: 1`** → this is a single-conversation oracle (it checks each conversation individually).
- **`yields`** gives a friendly failure message when the check fails.
- **`active: True`** → the rule runs by default.

## Why it's a general rule (not profile-bound)
This rule is **profile-agnostic** — it relies only on the generic `responds_in_same_language()` helper and doesn't reference any `chatbot.output` fields. So it works across **any** profile, including ones that use `interaction_style: change language: [...]` to test multilingual behaviour. No need to tie it to a specific profile. ✅

## Docs I relied on
- `sensei-check-doc.md` — helper library table (`responds_in_same_language`) and the profile-bound vs. global rule distinction.
- `rules-examples.md` — the canonical `chatbot_responds_in_same_language` example I adapted.

## A couple of notes 💡
- This helper is **LLM-backed**, so expect minor variability — it's great for catching UX regressions but not a hard deterministic guarantee.
- If you'd rather assert a *specific* language (e.g., always English), you could instead use `language(chatbot_phrases) == 'ENG'` — just let me know and I can whip that up too.
