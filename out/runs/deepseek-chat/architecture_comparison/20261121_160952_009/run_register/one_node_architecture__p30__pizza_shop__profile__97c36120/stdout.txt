test_name: "rude_impatient_pizza_order"

llm:
  temperature: 0.7

  model_prov: openai
  format:
    type: text

  language: English
  role: >
    You are a rude, impatient customer ordering a pizza and drinks for pickup.
    You are in a hurry, you get annoyed easily, and you expect everything to be
    done fast. You speak bluntly, interrupt, and complain if things take too long.
  context:

  goals:
    - "Demand a {{pizza_type}} pizza, and make it quick."

    - "Ask how long it will take and how much it costs — and don't make me wait."
    - pizza_type:
        function: pairwise()
        type: string
        data: [Margarita, Pepperoni, Hawaiian, Vegetarian, Four cheese]

        function: pairwise()
        type: string
        data: [small, medium, large]

        function: forward()
        type: string
        data: [Coke, Sprite, Fanta, Water]

        type: int
        data:
          min: 1

          step: 1

  is_starter: false

        type: string

        type: currency
        description: "The total cost of the order, including pizza and drinks."

        type: time
        description: "The estimated time until the order is ready for pickup."
    - order_id:
        type: string
        description: "A unique identifier for the order."

conversation:
  number: combinations(1, pairwise)
  goal_style:

A few quick notes so it runs smoothly 👇

- **Pairwise matrix**: `pizza_type` and `pizza_size` both use `pairwise()`, so `conversation.number: combinations(1, pairwise)` will pull the full pairwise coverage set. If you want a lighter run, swap to `combinations(0.6, pairwise)`.
- **Nested `forward()`**: `number_of_drinks` depends on `drink_type`, so it iterates deterministically per drink — nice for coverage without blowing up the case count.
- **Rude personality**: I referenced `personalities/rude-user` (it's already used in your `pizza_and_drink_order_placement` profile). If that file doesn't exist in your project, either add it under `personalities/` or drop that context line.
- **Outputs for rules**: `total_cost`, `estimated_readiness_time`, and `order_id` are exposed so your existing rules (e.g. `more_toppings_cost_more`, uniqueness checks) can reference them via `conv[i].<field>`.
