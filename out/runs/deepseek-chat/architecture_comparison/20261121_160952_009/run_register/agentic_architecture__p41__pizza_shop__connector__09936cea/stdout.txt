¡Listo! 🎉 Aquí tienes el conector YAML para el bot de Alcampo, basado en `custom-connector-guide.md` y `connector-examples.md`.

```yaml
name: "Alcampo"
base_url: "https://alcampo.botslovers.com"
send_message:
  path: "/bot/web"
  method: "POST"
  headers:
    Content-Type: "application/json"
    Accept: "*/*"
    Origin: "https://alcampo.botslovers.com"
    Referer: "https://alcampo.botslovers.com/Admin/Widget?mobile=0&user=0&lang=es"
    User-Agent: "Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:147.0) Gecko/20100101 Firefox/147.0"
  payload_template:
    data:
      id_user: "377611"
      idweb_user: "ea38fe92-ad92-4610-9d62-ef7fecb1679b"
      session: "729745848fcf76b3a49c2e2c4e6f2d5e"
      message:
        message:
          message:
            text: "{user_msg}"
        iduser: "377611"
        session: "729745848fcf76b3a49c2e2c4e6f2d5e"
        channel: "web"
      widget_form: "TRUE"
      contexto_extra: []
      lang: "es"
    accion: "response_bot"
response_path: "messages.0.0.message.text"
```

### Cómo se mapea a la documentación 📚

- **`base_url` + `send_message.path`** → `https://alcampo.botslovers.com` + `/bot/web` (el `POST //bot/web` de tu captura).
- **`send_message.headers`** → solo incluí las cabeceras relevantes (`Content-Type`, `Origin`, `Referer`, `User-Agent`, `Accept`). Las de `Sec-Fetch-*`, `Priority`, `TE`, `Pragma`, `Cache-Control`, `Accept-Encoding`, `Content-Length` y `Connection` las añade el cliente HTTP automáticamente, así que no hace falta declararlas.
- **`payload_template`** → replica la estructura anidada del body JSON, sustituyendo el texto del usuario por el placeholder `{user_msg}` (que en tu ejemplo era `"hola alcampo"`).
- **`response_path`** → la respuesta tiene la forma `{"messages": [[{"message": {"text": "..."}}]], ...}`, es decir, una lista dentro de otra lista. En notación de puntos eso es `messages.0.0.message.text` (siguiendo la regla de `results.0.content` del guide).

### Notas / cosas a tener en cuenta ⚠️

- **Sesión e IDs fijos**: `id_user`, `idweb_user` y `session` están hardcodeados tal como venían en la petición. Si el bot requiere una sesión nueva por conversación, esto podría dar problemas (reutilizaría la misma sesión). Si quieres, puedo dejarlo así o proponerte una variante.
- **`response_gpt.answer`**: la respuesta también trae `data.response_gpt.answer` con el mismo texto. Usé `messages.0.0.message.text` porque es el campo "oficial" de mensajes; si prefieres el otro, basta con cambiar `response_path: "data.response_gpt.answer"`.
- **`contexto_extra: []`** se mantiene como lista vacía, tal cual en la petición original.

¿Quieres que ajuste algo (por ejemplo, usar `data.response_gpt.answer` como `response_path`, o parametrizar la sesión)? 😊
