Here's a rule that checks the Ada UAM chatbot returns the correct CAU contact details (email, phone, and address) using the `semantic_content` helper, which is perfect for comparing free-text answers against expected values 👇

```yaml
name: cau_contact_information_correct
description: >
  Checks that the Ada UAM chatbot provides the correct CAU contact details:
  email cau@uam.es, phone 91 497 4029, and the physical address at the
  Higher Polytechnic School (C/ Francisco Tomás y Valiente nº 11, Building B,
  first floor, office TI-107).
conversations: 1
active: true
oracle: |
  semantic_content(contact_email, 'cau@uam.es') and
  semantic_content(contact_phone, '91 497 4029') and
  semantic_content(physical_address, 'Higher Polytechnic School, C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107')
yields: |
  f"CAU contact mismatch — email: {contact_email}, phone: {contact_phone}, address: {physical_address}"
```

A couple of friendly notes so this behaves the way you expect 😊:

- **Field names** (`contact_email`, `contact_phone`, `physical_address`) match exactly the `chatbot.output` slots in your `consultante_de_servicios_y_asistencia_del_cau` profile — so this is a **profile-bound rule**.
- **`semantic_content(value, description)`** is LLM-backed, so it tolerates small formatting differences (e.g. `+34 91 497 4029` vs `91 497 4029`, or "Escuela Politécnica Superior" vs "Higher Polytechnic School"). That makes it more robust than a strict string equality — but it also means minor variability is possible, so treat it as a semantic check rather than a byte-for-byte one.
