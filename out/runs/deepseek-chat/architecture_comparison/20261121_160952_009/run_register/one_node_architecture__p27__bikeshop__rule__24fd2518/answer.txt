¡Buena idea! 😊 Esa regla encaja perfecto como una **regla metamórfica de 2 conversaciones**: si en ambas conversaciones se propone la *misma fecha* para una cita, el asistente no debería aceptar la segunda (es decir, en la segunda conversación debe negarse o indicar que no puede aceptarla).

Un detalle importante antes del YAML: tu proyecto tiene perfiles como `appointment.yml` que exponen `confirmed_date`, `confirmed_time` y `confirmed_service` en `chatbot.output`. La regla de abajo asume que existe un campo tipo `confirmed_date` (o similar) en el perfil objetivo. Si tu perfil usa otro nombre, solo hay que ajustarlo en `when`/`if`/`then`. 👇

```yaml
name: duplicate_date_is_rejected
description: >
  Si dos conversaciones proponen la misma fecha de cita, el asistente no debe
  aceptar la segunda (debe negarse o indicar que no puede aceptarla).
conversations: 2
when: conv[0].confirmed_date == conv[1].confirmed_date
if: conv[0].confirmed_date is not None
then: conv[1].confirmed_date is None
on-error: >
  f"El asistente aceptó dos veces la misma fecha: {conv[0].confirmed_date} y {conv[1].confirmed_date}"
```

### Cómo funciona 🧠
- **`conversations: 2`** → regla metamórfica que compara un par de conversaciones.
- **`when`** → solo compara pares donde la fecha propuesta/confirmada coincide (cohorte comparable).
- **`if`/`then`** → si la primera conversación confirmó esa fecha, la segunda **no** debería confirmarla (debe quedar vacía/`None`).
- **`on-error`** → mensaje claro cuando falla, mostrando ambas fechas.

### Alternativa si quieres comprobar la *negativa explícita* 🗣️
Si tu bot no deja el campo vacío sino que responde con un texto tipo *"no puedo aceptar esa fecha"*, puedes usar el helper `utterance_index`:

```yaml
name: duplicate_date_is_rejected_explicitly
description: >
  Si dos conversaciones proponen la misma fecha, el asistente debe indicar
  explícitamente que no puede aceptar la segunda.
conversations: 2
when: conv[0].confirmed_date == conv[1].confirmed_date
if: conv[0].confirmed_date is not None
then: utterance_index('assistant', 'cannot accept that date') > 0
```

### Notas rápidas ✍️
- Ajusta `confirmed_date` al nombre real del campo en el `chatbot.output` del perfil que quieras validar (por ejemplo, si usas `appointment.yml`, ese campo ya existe ✅).
- Si el perfil no guarda la fecha propuesta por el usuario sino solo la confirmada, quizá te convenga añadir un campo tipo `requested_date` en `chatbot.output` para que la regla sea más robusta.
- Recuerda que los helpers como `utterance_index` son LLM-backed, así que puede haber pequeñas variaciones en la detección del texto.
