I spotted the issue right away — your `chatbot:` block got swallowed into `user:` 😅. Also, `export: 1` should be a boolean, and `type: str` should be `type: string` for consistency.

What I changed 👇

- **Moved `is_starter`, `fallback`, and `output` back under a proper `chatbot:` block** — this was the main structural bug.
- **`export: 1` → `export: false`** — it's a boolean flag, and `1` is ambiguous (also, exporting a verification dataframe wasn't your intent here).
- **`custom_pizza_pricing.type: str` → `string`** — `str` isn't a valid output type; use `string` (or `money`/`float` if you want to extract a numeric price later).
- **Trimmed the fallback text** — the `\nFor troubleshooting...` part is a LangChain error artifact, not your bot's real fallback. Keeping it clean avoids confusing the simulator.

One friendly tip 💡: if you plan to write rules against `custom_pizza_pricing` (e.g., price monotonicity), consider changing its type to `money` so `extract_float()` works nicely on it. Want me to draft a matching rule for that? 😊
