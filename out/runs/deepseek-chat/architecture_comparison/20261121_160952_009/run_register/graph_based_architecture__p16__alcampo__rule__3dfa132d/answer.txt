## The rule

```yaml
name: lactose_free_availability
description: >
  Rule-first design (no profile yet). Checks that when a user asks about a
  lactose-free product, the assistant confirms availability and exposes a
  matching availability flag. A future profile must expose chatbot.output
  fields: product_name (string), lactose_free (bool), available (bool).
conversations: 1
if:   conv[0].lactose_free is True
then: conv[0].available is True and utterance_index('assistant', 'available') > 0
on-error: f"Lactose-free product '{conv[0].product_name}' was not confirmed as available."
```

## Why it's written this way

- **`conversations: 1`** — this is a single-conversation oracle (not metamorphic), since we're checking one dialog's outcome. ✅
- **`if` / `then`** — reads like a law: *"If the product is lactose-free, then it must be marked available and the assistant must actually say so."* That's the metamorphic mindset applied cleanly. 🎯
- **`utterance_index('assistant', 'available') > 0`** — this is the LLM-backed helper that confirms the assistant *mentioned* availability somewhere in the dialogue, not just in the extracted output. Nice safety net for UX regressions.
- **`on-error`** — gives a friendly, specific failure message using `conv[0].product_name`.

## ⚠️ Important: the fields are assumptions

Since there's no profile yet, the fields `product_name`, `lactose_free`, and `available` are **placeholders I invented**. Per the guide's rule-first guidance:

> *"The rule still assumes that a future profile will expose certain outputs. You should clearly document which `chatbot.output` fields a profile must provide for the rule to work."*

So when you create the profile later, its `chatbot.output` **must** include something like:

```yaml
test_name: "product_info_profile"

user:
  language: English
  role: "You are a customer asking about a product's details, including whether it is lactose-free and currently available."
  context:
    - "You care about lactose content due to dietary preferences."
    - "You want to know if the product is in stock before deciding."
  goals:
    - "Ask about the {{product_name}}"
    - "Ask whether the {{product_name}} is lactose-free"
    - "Ask whether the {{product_name}} is currently available"
    - product_name:
        function: random()
        type: string
        data: [milk, cheese, yogurt, butter]

chatbot:
  is_starter: false
  fallback: "Sorry, could you rephrase that?"
  output:
    - product_name:
        type: string
        description: Name of the product being discussed
    - lactose_free:
        type: bool
        description: Whether the product is lactose-free
    - available:
        type: bool
        description: Whether the product is currently in stock

conversation:
  number: 2
  goal_style:
    steps: 5
  interaction_style:
    - random:
      - long phrases
      - make spelling mistakes
```

If you rename any of these later (e.g. `in_stock` instead of `available`), just remember to update the rule to match. 🔄
