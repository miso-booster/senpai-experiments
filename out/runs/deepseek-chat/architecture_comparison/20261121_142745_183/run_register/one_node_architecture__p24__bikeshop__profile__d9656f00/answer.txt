- **`money` type**: your existing profiles (e.g. `qa.yml`, `bike_service_and_repair_inquirer.yaml`) already use `type: money` for prices, so I kept that for consistency. If your project doesn't define a `money` custom type in `types/`, swap it for `currency` or `string`.
- **`single question` style**: matches your other pricing/Q&A profiles and keeps each request clean and testable — great for checking that the bot answers each item accurately without drifting into unrelated services.
- **No appointments or advanced topics**: the `context` explicitly steers the user away from those, so the bot's scope adherence is what gets exercised.
