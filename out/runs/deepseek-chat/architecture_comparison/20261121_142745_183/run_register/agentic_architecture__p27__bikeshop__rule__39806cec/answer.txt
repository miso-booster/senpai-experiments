## ⚠️ One important design question

Your request is: *"if we tell the assistant the same date twice, it must refuse to accept the second one."*

There are two ways to interpret this, and they lead to different rule designs:

1. **Within a single conversation** — the user gives a date, then repeats the same date later in the same conversation, and the bot should refuse the duplicate. This is a **single-conversation rule** (`conversations: 1`), but it needs the profile to expose something like a list of dates mentioned / a "duplicate rejected" signal — which `appointment.yml` currently does **not** have.

2. **Across two conversations** — two separate conversations with the same date, and the bot should not confirm both (i.e., the second should be refused). This is a **metamorphic rule** (`conversations: 2`) and works with the existing `confirmed_date` field.

Also note: the current profile's `ap_date` uses `forward(service)` over only 2 dates, so duplicate-date pairs across conversations are possible but the profile doesn't explicitly generate "same date twice" scenarios.
