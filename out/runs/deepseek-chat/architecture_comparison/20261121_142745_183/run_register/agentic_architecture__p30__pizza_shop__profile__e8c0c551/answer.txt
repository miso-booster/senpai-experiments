### What's going on here 🧐

- **Rude & impatient user** — captured in `user.role` and `user.context` (blunt, dismissive, wants speed, no please/thank you).
- **4 goals** — order pizza, ask for a drink, ask about timing, ask for the price. Each uses `{{variables}}`.
- **4 variables** — `size`, `toppings`, `drink`, `delivery_mode` (plus a `total_price` helper variable used in the last goal).
- **2 pairwise functions** — `size` and `toppings` both use `pairwise()`. Per the docs, **two pairwise variables are exactly what's needed** to build a pairwise-coverage matrix, so `conversation.number: combinations(0.6, pairwise)` derives the conversation count from that matrix (60% of it here — bump to `combinations` or `combinations(1, pairwise)` for full coverage).
- **`chatbot.output`** — defines the extractable fields (`order_id`, `total_price`, `estimated_time`, `pizza_size`, `toppings`) so you can later write profile-bound rules referencing `conv[i].total_price`, etc.

A couple of notes:
- I used `combinations(0.6, pairwise)` to keep the run lean; change the fraction if you want more coverage.
- The `total_price` variable is just a wording helper (price/total/bill) — it's distinct from the `total_price` output field, which is what gets extracted. If that naming overlap feels confusing, I can rename the variable to something like `price_word`.
