Since you want a **profile-agnostic global rule** (not tied to any specific `chatbot.output` schema), the cleanest approach is to use the LLM-backed `utterance_index` helper to check whether the assistant actually mentions promotions somewhere in the dialogue. That way it works across all your Alcampo profiles without depending on a specific field name.

Here's a rule that checks the chatbot provided info about current promotions:

```yaml
name: chatbot_provides_promotions_info
description: The chatbot provides information about current promotions when asked
conversations: 1
active: true
oracle: utterance_index('assistant', 'current promotions or discounts') > 0
yields: f"The chatbot did not provide information about current promotions"
```

A couple of quick notes so it behaves the way you expect 👀:

- **`utterance_index('assistant', ...)`** returns the turn index where the assistant mentions the topic (LLM-backed), so `> 0` means "it was mentioned at some point." This keeps it generic — no `chatbot.output` fields required.
- If you'd rather make it **conditional** (only check when the user actually asked about promotions), you can wrap it with `if`/`then`:

```yaml
name: chatbot_provides_promotions_info
description: If the user asks about promotions, the chatbot provides promotion info
conversations: 1
active: true
if: utterance_index('user', 'asking about promotions or discounts') > 0
then: utterance_index('assistant', 'current promotions or discounts') > 0
yields: f"The chatbot did not provide information about current promotions"
```
