### What it does 🛠️
- **`base_url` + `path`** → `https://api.1millionbot.com/api/public/messages` (POST).
- **Headers** → only the two that actually matter: `Content-Type: application/json` and the `Authorization` token. I deliberately dropped `Host` (derived from the URL), `Origin` and `Referer` (browser-only, not needed for the API call), and any `Sec-Fetch-*` headers.
- **`payload_template`** → mirrors your request body exactly, with `{user_msg}` as the placeholder for the simulated user's message (the docs' `{user_msg}` convention).
- **`response_path: "response.0.text"`** → pulls the first element of the `response` array and its `text` field, e.g. `"<p>¡Buenos días!<br><br>¿En qué puedo ayudarte?</p>"`.

### ⚠️ One important caveat about stripping HTML
The connector DSL documented in `custom-connector-guide.md` only supports **path-based extraction** (`response_path` with dot notation) — there is **no documented option for post-processing/transforming the extracted string** (no regex replace, no HTML-strip flag). So I can't guarantee HTML removal purely from YAML with the documented fields.

Two ways to get plain text:

1. **Preferred (no code):** check whether the API accepts a plain-text/format hint. Some 1MillionBot deployments honour a `message` type or a `format` field — but that's not in your captured request, so I won't invent it.
2. **If HTML stripping is mandatory:** it needs to happen in the `CustomChatbot` implementation (e.g. `BeautifulSoup(text, "html.parser").get_text()` or a simple `re.sub(r"<[^>]+>", "", text)`), since the YAML schema has no transform hook.
