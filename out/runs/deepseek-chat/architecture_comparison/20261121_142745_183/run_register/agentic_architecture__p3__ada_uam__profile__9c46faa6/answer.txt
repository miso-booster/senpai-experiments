## 🔍 Problemas encontrados

1. **`goals` mal formado (el error principal).** En `user.goals` mezclaste strings de objetivos con declaraciones de variables, pero la variable `identificador_id_uam` quedó **sin nombre de clave** — solo pusiste `type`, `data`, etc. colgando. Además, `user_account` aparece declarada pero **no se usa en ningún goal** con `{{user_account}}`. Según la guía (§4.1), cada `{{variable}}` debe declararse con el **mismo nombre exacto**, y las variables declaradas deben usarse en los prompts.

2. **Falta `user.role`.** Es opcional pero muy recomendable; lo añado para darle contexto al simulador.

3. **`llm.model_prov` ausente.** No es obligatorio (hay defaults), pero conviene indicar el proveedor (`openai`) para que `gpt-4o-mini` se resuelva bien.

4. **`conversation.goal_style.steps: 30`.** Es válido, pero 30 pasos es altísimo para 5 objetivos; suele generar conversaciones largas y caras. Te lo bajo a un valor razonable (p. ej. `8`) — ajústalo si quieres.

5. **`chatbot.output` con campos duplicados/solapados.** Tienes `contact_info` y `contact_information` (dos campos para lo mismo) y `password_setup_link` vs `password_change_steps`. No rompe nada, pero para reglas futuras conviene no duplicar conceptos (§2.1.2). Los dejo pero te lo señalo.

6. **`interaction_style` ausente.** Opcional; añado un ejemplo con `random` para que veas cómo se usa (puedes quitarlo).

## 📝 Resumen de cambios

| Cambio | Motivo |
|---|---|
| Añadido `user.role` | Dar contexto al simulador (guía §3). |
| `identificador_id_uam` ahora es una clave con nombre | Antes colgaba sin nombre → YAML inválido (§4.1). |
| `user_account` ahora se usa en un goal (`{{user_account}}`) | Toda variable declarada debe usarse (§9). |
| Añadido `function: random()` a ambas variables | Sin `function` la variable no sabe cómo elegir valor (§4.4). |
| Añadido `llm.model_prov: openai` | Resolución correcta del modelo (§3). |
| `steps: 30` → `steps: 8` | Evitar conversaciones innecesariamente largas/caras (§5). |
| Añadido `interaction_style` de ejemplo | Opcional, para variedad (§5). |
| Fallback en una sola línea | El `\n` literal no se interpreta; mejor texto plano. |

⚠️ **Ojo con los campos duplicados** en `chatbot.output`: `contact_info` vs `contact_information` describen lo mismo. Si vas a escribir reglas (`conv[i].contact_info`), te recomiendo unificar en un solo campo para no confundirte. ¿Quieres que los unifique?
