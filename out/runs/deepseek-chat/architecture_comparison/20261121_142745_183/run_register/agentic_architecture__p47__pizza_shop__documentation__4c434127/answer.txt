# Metamorphic rules in Sensei-check 🧪

Based on `sensei-check-doc.md` (and the examples in `rules-examples.md`), here's the idea:

## The core idea
A **metamorphic rule** is a Sensei-check rule that compares **two or more conversations** (a pair or tuple) instead of judging a single answer in isolation. Rather than checking an *absolute* expected answer (the classic "oracle problem"), it checks a **relation** between conversations: *"when the input changes in this way, the output should change (or stay the same) in that way."*

That's why it's called *metamorphic*: you hold most things equal, vary one dimension, and assert how the result must move.

## How it's expressed in YAML
- `conversations: N` with **N ≥ 2** (or `all` for global checks).
- `when:` — an optional filter that selects **comparable cohorts** (the *ceteris paribus* conditions, e.g. same size and drink).
- Then the relation itself, in one of two forms:
  - `oracle:` — a single boolean expression over `conv[0]`, `conv[1]`, …
  - `if:` / `then:` — an implication, which reads like a law: *"if X changes this way, then Y should change that way."*

Conversations are accessed via the `conv` collection: `conv[0].price`, `conv[1].toppings`, etc.

## Canonical example
> Same size, drink and quantity → more toppings must cost more.

```yaml
name: toppings_monotonicity
description: Adding more toppings to a custom pizza costs more (same size/drink/qty)
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink and conv[0].number == conv[1].number
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

## Typical relations you can check
- **Monotonicity** — more toppings ⇒ higher price; larger size ⇒ not cheaper.
- **Invariance** — same configuration ⇒ same price.
- **Consistency** — comparable dialogs respond in the same language.
- **Global properties** across *all* conversations (e.g. `is_unique('order_id')`).

## How it ties to profiles
The fields you compare (`size`, `toppings`, `price`, …) are **not arbitrary** — they come from a SENSEI Chat profile's `chatbot.output`. So a metamorphic rule is usually **profile-bound**: every `conv[i].field` must match a real output field of the target profile. The pizza names in the docs are just illustrative; in your project you'd swap in your own fields (e.g. `total_amount`, `pickup_time`).

## Quick contrast
| Rule type | `conversations` | Checks |
|---|---|---|
| Single-conversation oracle | `1` | absolute condition on one dialog |
| **Metamorphic** | `2+` | relation between dialogs |
| Global | `all` | property over the whole batch |
