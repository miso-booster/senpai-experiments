## 🐞 What's off in your rule

Based on `sensei-check-doc.md` and `rules-examples.md`:

1. **Typo:** `descriptin:` → should be `description:`.
2. **`when:` uses `conv[i].user_request`** — but `user_request` is **not** a field in the profile's `chatbot.output`. That reference will fail. The `when:` filter should only use real output fields (or be dropped).
3. **`if:` is used without `then:`** — the docs say `if`/`then` is an implication pair. A lone `if:` isn't a valid relation. For a "both fields must be present" check, the right construct is a single `oracle:`.
4. **`conversations: 2`** — a metamorphic rule needs a `when:` that selects *comparable pairs*. Since your intent is really "the bot provides these two pieces of info," a **single-conversation oracle** (`conversations: 1`) is the cleaner fit.

## ✅ Working rule

```yaml
name: customer_service_contact_info
description: Ensure the chatbot provides correct contact options and information for customer service inquiries.
conversations: 1
active: true
oracle: conv[0].contact_options is not None and conv[0].customer_service_number is not None
yields: "Missing contact info: contact_options={conv[0].contact_options}, customer_service_number={conv[0].customer_service_number}"
```

**What changed & why:**
- Fixed the `description` typo.
- Switched to a single-conversation `oracle` (no `when`/`if`/`then` needed) — this is the documented pattern for "these outputs must be filled."
- Removed the invalid `conv[i].user_request` reference (not in `chatbot.output`).
- Added a `yields:` message (per `rules-examples.md`) so failures are readable — kept it as a plain quoted string so the YAML stays valid.
