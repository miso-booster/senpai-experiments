Hey! 😊 Great question. Based on `sensei-chat-guide.md`, here's the breakdown of what's **not mandatory** in a profile.

## Explicitly optional (the docs call them out)

- **`llm`** — the whole block is optional. From the FAQ: *"Do I have to define `llm`? No. If omitted, defaults are applied (e.g., model and temperature) and the format defaults to text."* So you only add it when you need overrides or `speech` mode.
- **`llm.format.config`** — only needed when `format.type: speech`.
- **`context` entries with `personality:`** — the docs mark it as *optional*; you can also just use freeform strings in `context`.
- **`conversation.max_cost`** — optional cap for the whole run.
- **`goal_style.max_cost`** — optional per-conversation cost cap.
- **`goal_style.all_answered.limit`** — optional safety stop (defaults to 30 if omitted).
- **`goal_style.all_answered.export`** — optional flag (defaults to false).
- **`interaction_style`** — you can choose one, many, or use `default`; it's a "choose from here" list rather than a hard requirement.

## Practically optional / situational

- **`user.context`** — not required; it's supporting info for the simulated user.
- **`user.goals` variable declarations** — only needed if you actually use `{{variables}}` in your goal strings. Plain-string goals need no declarations.
- **`chatbot.output`** — only needed if you want extraction (e.g., for Sensei-check rules). If you're not validating outputs, you can skip it.
- **`conversation.number`** — the docs describe it as a control; you'd normally set it, but it's not framed as a hard requirement like `test_name`.

## What looks effectively mandatory

- **`test_name`** — the profile's identity.
- **`user.language`** and **`user.role`** — the core of the simulated user.
- **`user.goals`** — the actual things the user wants to do.
- **`chatbot.is_starter`** and **`chatbot.fallback`** — the docs strongly recommend a real fallback ("Put real bot fallback text in `chatbot.fallback` to avoid endless loops").

⚠️ One caveat: the guide describes the anatomy and gives an FAQ, but it doesn't include an explicit "required vs optional" schema table. So for anything not explicitly flagged as optional, I'd treat it as expected-but-verify.
