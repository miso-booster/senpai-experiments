## What's off 🔍

1. **`conversations: 2` is unnecessary.** You're only inspecting a single conversation (`conv[0]`). Metamorphic rules need 2+ conversations; a simple "price equals $50" check is a **single-conversation oracle**, so it should be `conversations: 1`.

2. **`when: conv[0].tune_up_price == 50` is doing the check in the wrong place.** `when:` is a *filter* — it selects which conversations the rule applies to. If you filter on `== 50`, you're only ever running the rule on conversations that already pass, which makes the check meaningless (it can never fail). The actual assertion belongs in `oracle:` (or `then:`).

3. **`then:` is a plain English string, not an expression.** Sensei-check expects a **Python expression** that evaluates to `True`/`False`. `"The tune-up price is $50."` is just a string literal — it's always truthy, so the rule would always "pass" regardless of the actual price. 🚩

4. **`conv[0].tune_up_price` must exist in the profile's `chatbot.output`.** Make sure your SENSEI Chat profile actually exposes a `tune_up_price` field — otherwise the rule can't read it.

## Fixed version ✅

```yaml
name: check_tune_up_price
description: Checks that the tune-up price equals $50.
conversations: 1
oracle: extract_float(conv[0].tune_up_price) == 50
```

### What I changed and why

| Change | Reason |
|--------|--------|
| `conversations: 2` → `1` | Only one conversation is inspected; this is a single-conversation oracle. |
| Removed `when: conv[0].tune_up_price == 50` | That was the assertion, not a filter. Filtering on it would make the rule unable to fail. |
| Removed `if: ... is not None` | Redundant — `extract_float(...) == 50` already handles it. If the field is `None`, the comparison simply fails, which is what you want. |
| `then: "The tune-up price is $50."` → `oracle: extract_float(conv[0].tune_up_price) == 50` | Replaced the string literal with a real boolean expression. |
| Wrapped in `extract_float(...)` | In case the price comes back as text like `"$50.00"` or `"50 USD"`, this parses the number reliably. |
