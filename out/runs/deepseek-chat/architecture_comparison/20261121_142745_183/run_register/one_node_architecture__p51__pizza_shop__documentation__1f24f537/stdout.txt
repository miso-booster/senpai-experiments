Hey there! 😊 Great question — connectors are basically the **bridge** between Sensei and your chatbot. They tell Sensei *where* to send the simulated user's messages and *how* to read the bot's replies back. Let me break it down 👇

## What connectors are for

A connector is a YAML file that describes how to talk to a chatbot's API **without writing any code**. Sensei uses it to:

- Send each simulated user message to the bot (via `send_message`)
- Extract the bot's reply from the JSON response (via `response_path`)

So instead of hardcoding an integration, you just describe the HTTP call and the response shape. 🎯

## The fields

| Field | Description | Required |
|-------|-------------|----------|
| `name` | Friendly name for your chatbot | No |
| `base_url` | Base URL of the chatbot API | ✅ Yes |
| `send_message.path` | API endpoint path (appended to `base_url`) | ✅ Yes |
| `send_message.method` | HTTP method (`POST`, `GET`, `PUT`, `DELETE`) | No (default: `POST`) |
| `send_message.headers` | Custom headers (e.g., `Authorization`) | No |
| `send_message.payload_template` | JSON structure with the `{user_msg}` placeholder | ✅ Yes |
| `response_path` | Dot-separated path to extract the bot's reply from the JSON response | ✅ Yes |

## A couple of quick notes 💡

- **`{user_msg}`** is the magic placeholder — that's where the simulated user's message gets injected into your payload.
- **`response_path`** uses dot notation to walk the JSON, e.g.:
  - `"message"` → `response["message"]`
  - `"data.text"` → `response["data"]["text"]`
  - `"results.0.content"` → `response["results"][0]["content"]`

Here's a minimal example so you can see it all together:

```yaml
name: "Echo Bot"
base_url: "https://postman-echo.com"
send_message:
  path: "/post"
  method: "POST"
  payload_template:
    message: "{user_msg}"
response_path: "json.message"
```

And if your bot needs auth, just drop it in `headers`:

```yaml
name: "Secure Bot"
base_url: "https://api.mychatbot.com"
send_message:
  path: "/chat/send"
  method: "POST"
  headers:
    Authorization: "Bearer your-api-key"
    Content-Type: "application/json"
  payload_template:
    query: "{user_msg}"
    session_id: "user123"
response_path: "response.text"
```
