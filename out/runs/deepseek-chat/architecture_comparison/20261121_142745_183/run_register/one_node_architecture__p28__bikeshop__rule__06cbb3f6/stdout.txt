Absolutely! 😊 This is a classic **global rule** — it doesn't depend on any specific `chatbot.output` field, so it works across all your bike shop profiles. Sensei-check has a built-in helper called `responds_in_same_language()` that does exactly what you want.

Here's a ready-to-use rule:

```yaml
name: chatbot_responds_in_same_language
description: The chatbot replies in the same language the user is writing in
conversations: 1
active: True
oracle: responds_in_same_language()
yields: f"The chatbot does not respond in the same language as the user"
```

A couple of friendly notes 👀:

- **`conversations: 1`** means it's checked per conversation — each dialog is validated on its own.
- **`responds_in_same_language()`** is LLM-backed, so it may have minor variability. It compares the language of the user's utterances with the chatbot's replies.
- This is especially handy for your `language_issue.yml` and `user_sim_bikesqa.yml` profiles (the latter uses Spanish!), where language switching is part of the test.

If you'd rather check a **fixed language** (e.g., "the bot must always answer in English"), you can use the `language()` helper instead:

```yaml
name: chatbot_answers_in_english
description: The chatbot always answers in English
conversations: 1
active: True
oracle: language(chatbot_phrases) == 'ENG'
yields: f"The chatbot did not answer in English"
```
