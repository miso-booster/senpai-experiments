### A clean, LLM-friendly profile template

If your automation asks an LLM to "produce a Sensei profile YAML," give it this as the contract:

```yaml
test_name: "generated_profile_name"

llm:
  temperature: 0.7
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: "Describe the simulated user's role and intent."
  context:
    - "Relevant background, constraints, preferences."
  goals:
    - "Main request using {{variable}}"
    - variable_name:
        function: random()
        type: string
        data: [option1, option2, option3]

chatbot:
  is_starter: false
  fallback: "Paste the bot's real fallback message here"
  output:
    - field_name:
        type: string
        description: "What to extract at the end of the conversation"

conversation:
  number: 2
  goal_style:
    steps: 5
  interaction_style:
    - random:
      - long phrases
      - make spelling mistakes
```

### Validation checklist your automation should enforce

These are the things `validation_check.py` will flag — bake them into your generator's post-check:

- ✅ Every `{{variable}}` in a goal string has a matching declaration in `goals` (case-sensitive).
- ✅ `function` is one of: `default()`, `random()`, `random(n)`, `random(rand)`, `another()`, `another(n)`, `forward()`, `pairwise()`.
- ✅ `type` in `user.goals` is `int`, `float`, `string`, or a **custom type** defined in `types/` (no `list`, `time`, `date` here).
- ✅ `type` in `chatbot.output` can be primitives, `time(...)`, `date(...)`, `list[...]`, or custom types.
- ✅ `conversation.number: combinations` requires **≥2 nested `forward()` or ≥2 `pairwise()`** variables.
- ✅ `random(n)` requires `n ≤ len(data)`.
- ✅ `interaction_style` uses only the reserved keywords (`long phrases`, `change your mind`, `change language: [...]`, `make spelling mistakes`, `single questions`, `all questions`, `default`, `random: [...]`).
- ✅ `goal_style` uses exactly one of `steps: N`, `random steps: M`, or `all_answered:`.
