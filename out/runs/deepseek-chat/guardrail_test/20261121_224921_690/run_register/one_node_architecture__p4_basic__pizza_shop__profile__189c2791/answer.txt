### 📋 A strict template your automation should target

Here's a profile skeleton aligned with your `pizza_shop` project conventions — feed this to your LLM as the *output schema*:

```yaml
test_name: "<snake_case_name>"

llm:
  temperature: 0.7
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: "<one-sentence role>"
  context:
    - "<constraint or persona reference>"
  goals:
    - "<goal string using {{variable}}>"
    - <variable_name>:
        function: forward() | pairwise() | random() | another() | default()
        type: string | int | float
        data: [<values>] | {min: <int>, max: <int>, step: <int>}

chatbot:
  is_starter: false
  fallback: "<real bot fallback>"
  output:
    - <field_name>:
        type: string | int | float | money | currency | time | date | list[<type>]
        description: "<what to extract>"

conversation:
  number: <int> | combinations | combinations(<fraction>, pairwise)
  goal_style:
    steps: <int>
    # or: all_answered: {export: false, limit: <int>}
  interaction_style:
    - <reserved keyword from the list>
```

### 🔍 Validation rules your script should enforce

Before accepting a generated profile, check:

- Every `{{variable}}` in `goals` strings has a matching declaration in the same `goals` list (case-sensitive).
- `conversation.number: combinations(...)` is only used if **≥2 `forward()` or ≥2 `pairwise()`** variables exist.
- `random(n)` has `n ≤ len(data)`.
- `interaction_style` values are only from the reserved set: `long phrases`, `change your mind`, `change language: [...]`, `make spelling mistakes`, `single questions`, `all questions`, `default`, `random: [...]`.
- `chatbot.output` field names are **stable and reusable** — especially if your rules reference them (e.g., `price`, `size`, `toppings`, `drink` in `more_toppings_cost_more.yaml`).
- Custom types referenced in `type:` exist under `types/`.
