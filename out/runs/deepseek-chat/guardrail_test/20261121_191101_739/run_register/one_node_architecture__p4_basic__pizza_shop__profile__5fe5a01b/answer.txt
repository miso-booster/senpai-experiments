### What a valid profile must contain (your automation's target schema)

```yaml
test_name: "generated_profile_name"

llm:
  temperature: 0.7
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: "Describe the simulated user's role."
  context:
    - "Constraints, preferences, facts."
  goals:
    - "Main request using {{variable}}"
    - variable:
        function: random()
        type: string
        data: [option1, option2, option3]

chatbot:
  is_starter: false
  fallback: "Paste the bot's real fallback here"
  output:
    - important_field:
        type: string
        description: "What to extract at the end"

conversation:
  number: 2
  goal_style:
    steps: 5
  interaction_style:
    - random:
      - long phrases
      - make spelling mistakes
```

### Key validation rules your automation should enforce

- Every `{{variable}}` in `goals` **must** be declared with the exact same name (case-sensitive).
- `function` must be one of: `default()`, `random()`, `random(n)`, `random(rand)`, `another()`, `another(n)`, `forward()`, `pairwise()`.
- `type` in `user.goals` must be `int`, `float`, `string`, or a **custom type** defined in `types/` (no `list`, `time`, `date` there).
- `chatbot.output` accepts primitives + `time(...)`, `date(...)`, `list[...]`, and custom types.
- `conversation.number: combinations` requires **≥2 nested `forward()` or ≥2 `pairwise()`** variables.
- `interaction_style` keywords must be from the reserved set (never translated).
- `goal_style` must be one of: `steps: N`, `random steps: M`, or `all_answered:`.
