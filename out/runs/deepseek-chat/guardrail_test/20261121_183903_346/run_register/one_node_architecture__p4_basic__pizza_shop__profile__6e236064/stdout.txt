### 1. What your automation must guarantee (the "valid profile" contract)

A generated profile is valid when it satisfies these rules from the Sensei Chat docs:

- **Top-level keys** are only: `test_name`, `llm`, `user`, `chatbot`, `conversation`.
- **`user.goals`**: every `{{variable}}` used in a goal string has a matching declaration in the same list (case-sensitive).
- **Variable declarations** must have `function`, `type`, and `data`. `type` must be `int`, `float`, `string`, or a custom type defined in `types/`.
- **`function`** must be one of: `default()`, `random()`, `random(n)`, `random(rand)`, `another()`, `another(n)`, `forward()`, `forward(dep)`, `pairwise()`.
- **`conversation.number`**: if `combinations` / `combinations(p)` is used, at least **two nested `forward()`** or **two `pairwise()`** variables must exist.
- **`interaction_style`** values must be from the reserved keyword set (never translated, never invented).
- **`chatbot.output`** types must be valid: primitives, `time(...)`, `date(...)`, `list[type]`, or a custom type.
- **`chatbot.fallback`** should be the bot's *real* fallback text.

### 3. How to validate generated profiles (this is the part your script should call)

The docs give you a built-in validator — your automation should run it on every generated profile and reject/regenerate on failure:

```bash

  --profile /abs/path/to/project/profiles/generated_profile.yml \
  --output  /abs/path/to/output \
  --combined-matrix \
  --verbose
```

It returns a JSON with format errors plus CSVs of the value-combination matrices — perfect for an automated pass/fail gate in your pipeline.
