## A solid template your LLM should target

Here's a minimal, valid profile your automation can use as the "target shape" — feed this to your LLM as the output contract:

```yaml
test_name: "generated_profile"

llm:
  temperature: 0.7
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: "Describe the simulated user's role."
  context:
    - "Relevant background, constraints, preferences."
  goals:
    - "Main request using {{variable}}"
    - variable:
        function: random()
        type: string
        data: [option1, option2, option3]

chatbot:
  is_starter: false
  fallback: "Paste the bot's real fallback here"
  output:
    - important_field:
        type: string
        description: "What to extract at the end"

conversation:
  number: 2
  goal_style:
    steps: 5
  interaction_style:
    - random:
      - long phrases
      - make spelling mistakes
```

## Validation rules to bake into your script

These are the checks that catch most LLM-generated profile bugs:

- ✅ Every `{{variable}}` in goal strings has a matching declaration in `goals` (case-sensitive).
- ✅ Every declared variable is actually used in at least one goal string.
- ✅ `function` is one of: `default()`, `random()`, `random(n)`, `random(rand)`, `another()`, `another(n)`, `forward()`, `forward(dep)`, `pairwise()`.
- ✅ `type` in `user.goals` is only `int`, `float`, `string`, or a **custom type** (no `list`, `time`, `date` here!).
- ✅ `type` in `chatbot.output` can be `int`, `float`, `string`, `time(...)`, `date(...)`, `list[...]`, or custom.
- ✅ `random(n)` → `n ≤ len(data)`.
- ✅ `conversation.number: combinations(...)` requires **≥2 nested `forward()` or ≥2 `pairwise()`** variables.
- ✅ `interaction_style` uses only reserved keywords: `long phrases`, `change your mind`, `change language: [...]`, `make spelling mistakes`, `single questions`, `all questions`, `default`, `random: [...]`.
- ✅ `goal_style` is exactly one of: `steps: N`, `random steps: M`, or `all_answered: {...}`.
