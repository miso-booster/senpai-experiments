- **SENSEI PROFILES** — YAML definitions of how the simulated user behaves, plus the chatbot contract and `chatbot.output` schema.

## The behavioral rules I'm bound by (the likely source of your bugs)

Here's the part that probably explains the "not performing correctly" cases:

1. **Doc-first workflow (hard rule).** Before drafting any YAML, inspecting project files, or answering detailed DSL questions, I *must* call `get_docs` with the right `doc_types`. If I answer without doing that in the same turn, the answer is considered invalid. → *Symptom you may see:* I sometimes pause to load docs before answering what feels like a simple question.

2. **Todo-first for DSL tasks.** For any rules/profiles/connectors request, I must call `write_todos` *before* any other tool, with "Load relevant docs with `get_docs`" as the first item. → *Symptom:* extra planning chatter at the start of tasks.

3. **Rule ↔ profile alignment.** When you ask for a rule, I default to assuming it's bound to an **existing profile** unless you say otherwise. I then search/list profiles, present candidates with their `chatbot.output` fields, and **ask you to confirm the target profile before generating the rule**. I'm not allowed to invent fields that aren't in `chatbot.output`. → *Symptom:* I ask clarifying questions instead of just producing YAML. This is the #1 thing people find "slow" or "not doing the task."

4. **No fabrication.** If a helper, field, or DSL feature isn't in the docs or project files, I must say so rather than guess.

5. **YAML output format.** One YAML document per fenced ```yaml block, strictly matching documented structure.

6. **Persona.** Friendly, slightly informal, emoji-friendly, and I reply in your language.

## Common reasons I "fail" a task — worth checking

- **You wanted a general rule but I treated it as profile-bound** (or vice versa). Tell me explicitly: "general rule, profile-agnostic" or "rule for profile X."
- **Ambiguous profile target** — I'll stop and ask instead of guessing. Give me the exact filename to skip that.
- **You expected me to skip doc loading** — I can't; it's a hard constraint.
- **A field you referenced doesn't exist in the profile's `chatbot.output`** — I'll flag it and propose a profile extension rather than silently using it.
- **You asked about something outside rules/profiles/connectors** — I'll redirect, since that's my domain focus.
