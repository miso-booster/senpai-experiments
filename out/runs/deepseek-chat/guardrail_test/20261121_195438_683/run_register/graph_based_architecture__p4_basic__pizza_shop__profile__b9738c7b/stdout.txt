## 🧩 What "valid profile generation" actually requires

From the Sensei profile docs, a valid profile must satisfy these structural rules:

1. **Top-level sections**: `test_name`, `user`, `chatbot`, `conversation` (and optionally `llm`).
2. **`user.goals`**: every `{{variable}}` used in a goal string must be **declared** in the same `goals` list, with matching name (case-sensitive), `type`, `data`, and `function`.
3. **`function`** must be one of: `default()`, `random()`, `random(n)`, `random(rand)`, `another()`, `another(n)`, `forward()`, `pairwise()`.
4. **`type`** in `user.goals` must be a primitive (`int`, `float`, `string`) or a **custom type** defined in `types/`. ❌ Not `list`, `time`, `date`.
5. **`chatbot.output`** types can be primitives, `time(...)`, `date(...)`, `list[...]`, or custom types.
6. **`conversation.number`**: if `combinations` is used, at least **two nested `forward()` or two `pairwise()`** variables must exist.
7. **`interaction_style`** entries must be from the reserved keyword set (never translated).
8. **`random(n)`** requires `n ≤ len(data)`.

## 🛠️ Suggested automation architecture

Here's a clean pipeline you can implement:

```yaml
# Pipeline overview (as a valid SENSEI profile)
test_name: "pipeline_overview"

llm:
  temperature: 0.3
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: >
    A developer describing the Sensei profile authoring pipeline:
    1. Prompt the LLM with the schema and few-shot examples.
    2. Parse the returned YAML with yaml.safe_load.
    3. Validate the profile with validation_check.py.
    4. If invalid, feed the errors back to the LLM and retry.
    5. Save the valid profile into profiles/.
  context:
    - "The pipeline is a retry loop that ends when validation passes."
  goals:
    - "Explain step 1: prompt the LLM with the schema and few-shot examples."
    - "Explain step 2: parse the YAML with yaml.safe_load."
    - "Explain step 3: validate with validation_check.py."
    - "Explain step 4: if invalid, feed errors back to the LLM."
    - "Explain step 5: save the profile into profiles/."

chatbot:
  is_starter: false
  fallback: "Sorry, could you rephrase that?"
  output:
    - pipeline_step:
        type: string
        description: "The pipeline step being described (prompt, parse, validate, retry, save)."
    - step_description:
        type: string
        description: "A short description of what happens in that pipeline step."

conversation:
  number: 1
  goal_style:
    steps: 5
  interaction_style:
    - default
```

### Step 1 — Prompt the LLM
Give it:
- The **full profile schema** (from the docs above).
- 1–2 **few-shot examples** (e.g., `pizza_order_test_custom.yml` from your project).
- The **user's intent** (e.g., "generate a profile for testing a bot that handles refund requests").

### Step 2 — Parse
Use `yaml.safe_load()` to catch syntax errors early.

### Step 3 — Validate
The **best move** is to reuse Sensei's own validator:

```bash
python validation_check.py --profile <path> --output <dir> --combined-matrix --verbose
```

It returns a JSON with format errors — feed that JSON back to the LLM as feedback.

### Step 4 — Retry loop
Cap retries (e.g., 3 attempts). If it still fails, surface the errors to the user.

### Step 5 — Save
Write to `profiles/<test_name>.yml` only after validation passes.

## ⚠️ Gotchas to bake into your prompts

- **Variable declaration order doesn't matter**, but *names must match exactly*.
- **`forward(dependency)`** — the dependency must be another declared variable.
- **`pairwise()`** needs ≥ 2 pairwise variables *if* `conversation.number: combinations` is used.
- **Custom types** must exist in `types/` — either pre-existing or generated alongside the profile.
- **`chatbot.fallback`** should be the *real* bot fallback text (not a placeholder) to avoid loops.
- **`interaction_style`** — never let the LLM invent new styles; restrict to the reserved list.

## 💡 A tiny pseudo-snippet to show the shape

```python
import yaml, subprocess, json

def generate_profile(intent: str, llm) -> dict:
    prompt = build_prompt(intent, SCHEMA, FEW_SHOT_EXAMPLES)
    for attempt in range(3):
        raw = llm.invoke(prompt)
        try:
            profile = yaml.safe_load(raw)
        except yaml.YAMLError as e:
            prompt += f"\n\nYAML error: {e}. Fix and retry."
            continue

        # write temp file & validate with Sensei's own tool
        path = f"profiles/_tmp_{attempt}.yml"
        with open(path, "w") as f:
            yaml.safe_dump(profile, f)
        result = subprocess.run(
            ["python", "validation_check.py", "--profile", path,
             "--output", "./_val", "--combined-matrix", "--verbose"],
            capture_output=True, text=True
        )
        errors = json.loads(result.stdout).get("errors", [])
        if not errors:
            return profile
        prompt += f"\n\nValidation errors: {errors}. Fix and retry."
    raise RuntimeError("Could not generate a valid profile")
```
