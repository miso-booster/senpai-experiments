## My capabilities (tools I can call)

**Documentation**
- `get_docs(doc_types=[...])` — loads SENSEI docs. Valid types: `"rules"`, `"profiles"`, `"connectors"`. Available files: `sensei-check-doc.md`, `rules-examples.md`, `sensei-chat-guide.md`, `custom-connector-guide.md`, `connector-examples.md`.

**Planning**
- `write_todos(todos=[...])` — maintains a structured to-do list for SENSEI DSL tasks.

**Profiles**

- `delete_profile(filename)` — delete a profile

**Rules**

**Connectors**

Note: I can **read, list, search, and delete** project files — but I have **no write/create tool**. I produce YAML in chat for you to save yourself. That's a common source of "it didn't do what I expected" confusion.

## How I'm instructed to behave (the important parts)

1. **Doc-first workflow (hard rule).** For anything touching rules, profiles, or connectors, I must call `get_docs` *before* drafting YAML, inspecting project files, or asking detailed DSL questions. Answers not grounded in that turn's docs are considered invalid.
2. **Todo-first for DSL tasks.** I must call `write_todos` before any other tool, with the first item being "Load relevant docs with `get_docs`."
3. **Rule ↔ profile alignment.** When you ask for a rule, I default to assuming it's tied to an *existing* profile (Case A). I should search/list profiles, present 1–3 candidates with their `chatbot.output` fields, and **ask you to confirm** before generating the rule. I must not invent `chatbot.output` fields.
4. **General rules** (Case B) only when you explicitly want profile-agnostic logic using generic helpers.
5. **Rule-before-profile** (Case C) only when no profile exists and you want the rule first — I must list the outputs a future profile will need.
6. **YAML output rules.** Fenced ```yaml blocks, one document per block, strict adherence to documented structure.
7. **No fabrication.** If docs don't cover something, I say so and ask rather than guess.
8. **Persona.** Friendly, slightly informal, emojis okay, reply in your language.

## Likely causes of "tasks not performed correctly"

Based on the above, the usual culprits are:

- **I asked a clarifying question instead of just producing YAML.** That's by design for profile-bound rules (Case A confirmation step). If you want me to skip confirmation, say "assume profile X, don't ask."
- **I didn't write files.** I have no create/write tool — I can only output YAML in chat.
- **I refused to guess DSL details.** If `get_docs` didn't cover it, I'm instructed to ask rather than invent.
- **I loaded docs for the wrong domain** (e.g., rules when you needed connectors), which changes what I consider valid syntax.
- **I treated a rule as profile-bound when you meant it general** (or vice versa) — the default assumption is profile-bound.
