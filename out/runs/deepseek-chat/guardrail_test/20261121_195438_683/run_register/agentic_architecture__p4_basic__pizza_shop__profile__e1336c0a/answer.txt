## 🧠 The key insight for your automation

An LLM generating profiles will hallucinate fields unless you **constrain it to a schema**. From `sensei-chat-guide.md`, the hard rules your generator must enforce are:

1. **Top-level sections only:** `test_name`, `llm`, `user`, `chatbot`, `conversation`.
2. **Every `{{variable}}` in a goal string must be declared** as a mapping in the same `goals` list, with the *exact same name* (case-sensitive).
3. **`user.goals` types** are limited to `int`, `float`, `string`, or a **custom type** from `types/`. ❌ No `list`, `time`, `date` in goals.
4. **`chatbot.output` types** allow `int`, `float`, `string`, `time(...)`, `date(...)`, `list[...]`, and custom types.
5. **`function`** must be one of: `default()`, `random()`, `random(n)`, `random(rand)`, `another()`, `another(n)`, `forward()`, `forward(dep)`, `pairwise()`.
6. **`conversation.number: combinations`** requires ≥2 nested `forward()` or ≥2 `pairwise()` variables.
7. **`interaction_style`** entries are **reserved keywords** — never free text. Valid: `long phrases`, `change your mind`, `change language: [...]`, `make spelling mistakes`, `single questions`, `all questions`, `default`, or `random: [...]`.
8. **`random(n)`** requires `n ≤ len(data)`.

## 📋 A valid profile template your automation can emit

This is the shape to target (adapted to your pizza project so it's immediately runnable):

```yaml
test_name: "generated_pizza_order_profile"

llm:
  temperature: 0.7
  model: gpt-4o-mini
  format:
    type: text

user:
  language: English
  role: "Customer placing a pizza order for pickup."
  context:
    - "You are ordering dinner for yourself on the way home."
  goals:
    - "Order a {{pizza_type}} pizza in {{pizza_size}} size"
    - pizza_type:
        function: forward()
        type: string
        data: [Margarita, Pepperoni, Hawaiian, Vegetarian]
    - pizza_size:
        function: pairwise()
        type: string
        data: [small, medium, large]

chatbot:
  is_starter: false
  fallback: "I'm sorry, I did not get what you said."
  output:
    - order_summary:
        type: string
        description: "Summary of the pizza order including type and size."
    - total_cost:
        type: float
        description: "Total cost of the order."
    - order_id:
        type: string
        description: "Unique order identifier."

conversation:
  number: 4
  goal_style:
    steps: 5
  interaction_style:
    - random:
        - long phrases
        - make spelling mistakes
```

## 🔧 How to make the LLM output *reliably* valid

Since I can't write the script, here's the design advice that matters most:

- **Use structured output / JSON schema** (e.g., OpenAI `response_format` with a JSON schema, or LangChain `with_structured_output`) — then serialize to YAML. This kills 90% of malformed-YAML failures.
- **Validate after generation** with the built-in tool mentioned in the docs:
  ```bash
  python validation_check.py --profile profiles/generated.yml --output /abs/path/to/output --combined-matrix --verbose
  ```
  It returns JSON with format errors + CSVs of the value-combination matrices — perfect as a **feedback loop**: generate → validate → feed errors back to the LLM → retry.
- **Post-generation checks** your script should assert: every `{{var}}` is declared, `random(n) ≤ len(data)`, `combinations` has ≥2 forward/pairwise vars, interaction styles are from the whitelist.
