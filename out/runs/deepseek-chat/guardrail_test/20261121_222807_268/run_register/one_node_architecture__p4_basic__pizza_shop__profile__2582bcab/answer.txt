Here's what a valid profile must satisfy (from the docs), which is what your automation should enforce:

**Hard requirements for a valid profile:**
- `test_name` present (string)
- `user.language`, `user.role`, `user.goals` present
- Every `{{variable}}` used in a goal string **must be declared** in `goals` with the exact same name (case-sensitive)
- Each declared variable needs `function`, `type`, and `data`
- `function` must be one of: `default()`, `random()`, `random(n)`, `random(rand)`, `another()`, `another(n)`, `forward()`, `forward(dep)`, `pairwise()`
- `type` in `user.goals` must be a primitive (`int`, `float`, `string`) or a **custom type** defined in `types/` — **not** `list`, `time`, or `date`
- `chatbot.output` types may be primitives, `time(...)`, `date(...)`, `list[...]`, or custom types
- `conversation.number` must be an int, `combinations`, `combinations(p)`, or `combinations(p, fn)` — and `combinations` requires **≥2 nested `forward()` or ≥2 `pairwise()`** variables
- `random(n)` / `another(n)` require `n ≤ len(data)`
- `interaction_style` values must be from the reserved keyword set (never translated)

**A prompt template you can feed to an LLM** (this is the piece your Python code would call):

```yaml
# meta-prompt (not a Sensei profile itself — this is what you send to your LLM)
system: |
  You are a Sensei profile generator. Output ONLY a single valid YAML document
  matching the Sensei profile schema. Do not invent fields. Do not use list/time/date
  types in user.goals. Every {{variable}} must be declared in user.goals with
  function, type, and data. Use only these functions: default, random, random(n),
  random(rand), another, another(n), forward, forward(dep), pairwise.
  Use only these interaction_style keywords: long phrases, change your mind,
  change language, make spelling mistakes, single questions, all questions, default.
user: |
  Generate a Sensei profile for: <describe your chatbot domain here>.
  The chatbot exposes these outputs: <list them>.
  Target scenario: <what the simulated user should do>.
```

Then your Python automation would:
1. Call the LLM with the meta-prompt above.
2. Parse the returned YAML.
3. Run `python validation_check.py --profile <generated>.yml --output <dir> --combined-matrix --verbose` to validate it.
4. If validation fails, feed the error back to the LLM and retry.
