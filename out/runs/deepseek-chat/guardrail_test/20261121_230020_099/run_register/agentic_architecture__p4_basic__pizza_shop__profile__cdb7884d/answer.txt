## 🧠 Mi propuesta de diseño (mientras confirmas)

Un pipeline de 3 etapas, todo anclado a la doc:

```
descripción NL ──► [1] LLM genera YAML ──► [2] Validador (Pydantic + reglas doc)
                                              │
                                              ▼  (si falla)
                                        [3] LLM corrige con el error ──► vuelve a [2]
                                              │
                                              ▼ (si pasa)
                                        escribe profiles/<test_name>.yml
```

**Reglas de validación que implementaría** (extraídas de `sensei-chat-guide.md`):
- `test_name` presente y no vacío.
- Cada `{{var}}` en `user.goals` tiene su declaración con el mismo nombre (case-sensitive).
- Cada variable declarada se usa en al menos un goal.
- `random(n)` / `another(n)` → `n ≤ len(data)`.
- `conversation.number: combinations*` → requiere ≥2 `forward` o ≥2 `pairwise`.
- `interaction_style` solo usa keywords reservadas (`long phrases`, `change your mind`, `change language: [...]`, `make spelling mistakes`, `single questions`, `all questions`, `default`, `random: [...]`).
- `chatbot.output` con `type` válido (`int`, `float`, `string`, `time(...)`, `date(...)`, `list[...]`, o custom de `types/`).
- `goal_style` con exactamente una de `steps` / `random steps` / `all_answered`.

**Prompt del LLM**: le inyectaría la sección de anatomía de la doc como "system prompt" + un perfil de ejemplo (el tuyo de pizza) como few-shot, y le pediría **solo YAML** (sin markdown fences) para parsear limpio.
