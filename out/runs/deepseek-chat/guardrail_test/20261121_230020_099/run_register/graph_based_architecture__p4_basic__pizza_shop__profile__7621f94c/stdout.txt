**2. The validation rules your automation must respect**
If your LLM generates profiles, these are the invariants you'll want to enforce (they're the same ones `validation_check.py` checks):

- Every `{{variable}}` in a goal string **must** be declared in `user.goals` with the *exact same name* (case-sensitive).
- Every declared variable **should** be used in at least one goal prompt.
- `random(n)` requires `n ≤ len(data)`.
- `pairwise()` needs **at least 2** pairwise-assigned variables to be meaningful.
- `conversation.number: combinations` requires **≥2 nested `forward()` or ≥2 `pairwise()`** variables.
- `interaction_style` values must be **exact reserved keywords** (never translated): `long phrases`, `change your mind`, `change language`, `make spelling mistakes`, `single questions`, `all questions`, `default`, or `random: [...]`.
- Custom types referenced in `goals`/`output` must exist as YAML files in `types/`.
- `time(...)`, `date(...)`, `list[...]` are valid in `chatbot.output` but **not** in `user.goals`.

**3. How to validate generated profiles**
