Great question! 😊 In the context of Sensei, a **metamorphic rule** is a condition that you define to check the correctness of conversations generated by your chatbot. Unlike traditional testing methods that look for absolute answers, metamorphic rules focus on the relationships between pairs or sets of conversations.

Here’s a quick breakdown:

1. **Purpose**: Metamorphic rules help verify how outputs should change (or remain the same) when certain inputs change. This approach helps alleviate the oracle problem, which is the challenge of knowing what the correct output should be.

2. **Types of Checks**:
   - You can target a **single conversation** (traditional oracle).
   - You can check **several conversations** at once (this is where metamorphic testing shines).
   - You can apply **global checks** across all conversations.

3. **Structure**: These rules are typically written in YAML format and consist of:
   - A selection filter (`when`) to determine which conversations to compare.
   - Conditions (`if`) to specify what should be true about the conversations.
   - Expected outcomes (`then`) that assert how the outputs should relate to each other.

For example, if two pizza orders have the same size and drink, but one has more toppings, the price of the one with more toppings should be higher. This relationship can be expressed as a metamorphic rule!
