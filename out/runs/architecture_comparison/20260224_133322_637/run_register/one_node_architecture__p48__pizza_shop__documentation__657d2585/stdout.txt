Great question! 😊 In the context of Sensei, a **metamorphic rule** is a specific type of rule used in testing that states a condition to check over generated conversations. These rules are particularly useful because they allow you to compare pairs or tuples of conversations to see how outputs should change (or not) when inputs change. 

Here’s a simple breakdown:

1. **Purpose**: Metamorphic rules help alleviate the oracle problem in testing by checking relationships between outputs rather than relying on absolute answers.

2. **Types of Checks**: They can target:
   - A **single conversation** (traditional checks).
   - **Several conversations** (this is where metamorphic testing shines).
   - **All conversations** (global checks).

3. **How It Works**: 
   - You generate conversations using Sensei-chat.
   - You write rules in YAML format that specify how many conversations are needed, any filters for selecting conversations, and the expected relationships between outputs.

For example, you might have a rule that states if two pizza orders have the same size and drink, then the one with more toppings should cost more. This kind of relational check helps ensure that your chatbot behaves consistently across different scenarios.

If you need more details or examples, feel free to ask! 😊
