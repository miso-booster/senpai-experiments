Your rule is a great start! However, there are a couple of things to adjust to ensure it works correctly. Let's take a look at it and make the necessary changes.

### Issues with the Rule
1. **Use of `when` and `oracle`:** The `when` clause is used to filter conversations based on certain conditions, while the `oracle` should be a condition that checks the expected outcome. In your case, you're repeating the same checks in both `when` and `oracle`, which is not necessary.

2. **Correct Structure:** The `oracle` should generally assert what you expect to be true after the conditions in `when` are met. 

### Revised Rule
Here’s a corrected version of your rule:

```yaml
name: check_cau_information
description: Checks that the CAU provided correct information about contact details.
conversations: 1
when: conv[0].contact_email == 'cau@uam.es' and conv[0].contact_phone == '91 497 4029' and conv[0].physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
oracle: True
```

### Explanation
- **`name`:** This is the identifier for your rule, which is clear and descriptive.
- **`description`:** It explains what the rule is checking, which is great for understanding its purpose.
- **`conversations`:** This indicates that the rule will evaluate one conversation.
- **`when`:** This condition checks if the CAU's provided contact details match the expected values. If this condition is true, it means the information is correct.
- **`oracle`:** Instead of repeating the checks, we simply set this to `True`. This means that if the `when` condition is satisfied, we expect the information to be correct.

### Summary
The revised rule now properly checks the conditions and asserts that they are true without redundancy. This structure makes it easier to understand and maintain. If the `when` condition is met, the rule will pass, indicating that the CAU provided the correct information! 😊
