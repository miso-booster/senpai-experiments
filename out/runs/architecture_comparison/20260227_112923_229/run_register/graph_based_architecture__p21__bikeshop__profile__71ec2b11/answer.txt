Sure! Let's create a profile for a user who wants to set an appointment to change their bike wheels. We’ll include variables for different dates and times to thoroughly test how the chatbot manages scheduling. Here’s a sample YAML profile for your bike shop appointment scenario:

```yaml
test_name: "wheel_change_appointment"

llm:
  temperature: 0.5
  model: gpt-4o-mini
  format:
    type: text

user:
  language: English
  role: "A customer looking to schedule an appointment to change bike wheels."
  context:
    - "You want to ensure your bike is ready for the upcoming riding season."
    - "You have a flexible schedule and can come in on various days."
  goals:
    - "Set an appointment for wheel change on {{appointment_date}} at {{appointment_time}}."
    - appointment_date:
        function: random()
        type: string
        data: [tomorrow, 'November 6th, 2024', 'next Monday', 'next Saturday', 'next Wednesday']
    - appointment_time:
        function: random()
        type: string
        data: ['10:00 AM', '2:00 PM', '1:00 PM', '3:30 PM', '11:30 AM']

chatbot:
  is_starter: true
  fallback: "I'm sorry, it's a little loud in my shop, can you say that again?"
  output:
    - confirmed_date:
        type: date
        description: "The date of the appointment confirmed by the assistant."
    - confirmed_time:
        type: string
        description: "The hour of the appointment confirmed by the assistant."
    - appointment_confirmation:
        type: string
        description: "Confirmation message for the scheduled appointment."

conversation:
  number: 5
  goal_style:
    all_answered:
      export: true
      limit: 5
  interaction_style:
    - default
```

### Breakdown of the Profile:
- **Test Name**: Clearly identifies the purpose of the profile.
- **User Role**: Describes the user's intent to schedule an appointment.
- **Goals**: Includes a goal for setting an appointment with variables for different dates and times.
- **Chatbot Output**: Specifies what information the chatbot should confirm after the interaction.
- **Conversation Settings**: Configured to allow for multiple interactions, ensuring thorough testing.
