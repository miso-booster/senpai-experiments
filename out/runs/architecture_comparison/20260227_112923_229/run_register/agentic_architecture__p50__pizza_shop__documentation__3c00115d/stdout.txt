The **pairwise function** in the context of Sensei-check is used for **metamorphic testing**, which involves comparing pairs of conversations to assert how outputs should change (or not) when inputs change. Here's a breakdown of how it works:

### Key Concepts

1. **Metamorphic Rules**:
   - These rules allow you to check relationships between pairs of conversations rather than absolute correctness.
   - They help alleviate the oracle problem by focusing on how outputs relate to each other based on varying inputs.

2. **Conversation Selection**:
   - You can specify filters to select which pairs of conversations to compare using the `when` clause.
   - The `conversations` field must be set to at least 2 for pairwise comparisons.

3. **Relation Checking**:
   - You can define conditions using `if` and `then` to specify expected relationships between the outputs of the selected conversations.
   - For example, if one conversation has more toppings than another, its price should be higher.

### Example Structure

Here's a simplified example of a metamorphic rule that checks if adding more toppings to a pizza increases the price:

```yaml
name: toppings_monotonicity
description: More toppings increase total price
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

### Breakdown of the Example

- **Name and Description**: Clearly state what the rule is checking.
- **Conversations**: Indicates that this rule applies to pairs of conversations.
- **When Clause**: Filters conversations to ensure they are comparable (same size and drink).
- **If Clause**: Checks a specific condition (more toppings in the first conversation).
- **Then Clause**: Asserts the expected outcome (the price of the first conversation should be higher).

### Benefits of Pairwise Testing

- **Efficiency**: It allows for checking multiple conditions across different conversations without needing a full oracle for each conversation.
- **Robustness**: Helps ensure that the chatbot behaves consistently across various scenarios.

This approach is particularly useful in conversational AI testing, where the outputs can vary widely based on user inputs.
