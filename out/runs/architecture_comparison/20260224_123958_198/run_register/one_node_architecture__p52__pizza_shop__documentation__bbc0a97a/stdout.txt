Connectors in the context of chatbot testing are used to define how your chatbot communicates with an external API. They allow you to send messages to the chatbot and receive responses, enabling you to test and validate the chatbot's behavior in a controlled environment.

### Key Fields in a Connector

Here are the main fields typically found in a connector configuration:

1. **name**: A friendly name for your chatbot, which helps identify it.

2. **base_url**: The base URL of the chatbot's API. This is where all API requests will be sent.

3. **send_message**:
   - **path**: The specific endpoint path that will be appended to the base URL for sending messages.
   - **method**: The HTTP method used for the request (e.g., POST, GET). If not specified, POST is the default.
   - **headers**: Any custom headers that need to be included in the request (e.g., Authorization).
   - **payload_template**: The structure of the JSON payload sent with the request, including placeholders like `{user_msg}` for dynamic content.

4. **response_path**: A dot-separated path used to extract the chatbot's reply from the JSON response. This specifies how to navigate through the response structure to get the relevant data.

### Example of a Simple Connector

Here's a quick example of what a connector might look like:

```yaml
name: "Echo Bot"
base_url: "https://postman-echo.com"
send_message:
  path: "/post"
  method: "POST"
  payload_template:
    message: "{user_msg}"
response_path: "json.message"
```

This configuration would send a message to the Echo Bot API and expect to receive the same message back in the response.
