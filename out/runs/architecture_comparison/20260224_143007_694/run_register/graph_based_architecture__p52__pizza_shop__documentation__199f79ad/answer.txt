Connectors are used to facilitate communication between your chatbot and external APIs or services. They allow your chatbot to send messages to and receive responses from these services, enabling it to perform tasks like fetching data, processing user requests, or interacting with other systems.

### Key Fields in Connectors

Here are the main fields typically found in a connector configuration:

1. **name**: A friendly name for your chatbot connector, which helps identify it.

2. **base_url**: The base URL of the chatbot API you are connecting to. This is the starting point for all API requests.

3. **send_message**: This section contains details about how to send messages to the chatbot API:
   - **path**: The specific endpoint path that will be appended to the base URL for sending messages.
   - **method**: The HTTP method to be used (e.g., POST, GET). If not specified, POST is usually the default.
   - **headers**: Any custom headers that need to be included in the request, such as authorization tokens or content types.
   - **payload_template**: The structure of the JSON payload that will be sent in the request. This often includes placeholders for dynamic content, like the user's message.

4. **response_path**: This field specifies the path to extract the chatbot's reply from the JSON response received from the API. It uses dot notation to navigate through the response structure.

### Example of a Connector Configuration

Here's a simple example of what a connector configuration might look like:

```yaml
name: "My Custom Bot"
base_url: "https://api.mychatbot.com"
send_message:
  path: "/chat"
  method: "POST"
  payload_template:
    message: "{user_msg}"
response_path: "response.text"
```

In this example:
- The connector is named "My Custom Bot."
- It connects to an API at `https://api.mychatbot.com`.
- Messages are sent to the `/chat` endpoint using a POST request, with the user's message included in the payload.
- The bot's response is extracted from the `response.text` field in the JSON response.
