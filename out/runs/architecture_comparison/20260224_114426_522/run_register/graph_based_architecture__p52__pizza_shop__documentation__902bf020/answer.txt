Connectors are used to facilitate communication between your chatbot and external APIs. They allow your chatbot to send messages and receive responses from various services, enabling it to interact with users in a more dynamic and versatile way. This is especially useful for chatbots that need to access real-time data, such as weather updates, booking systems, or any other service that requires external information.

### Key Fields in Connectors

Here are the main fields typically found in a connector configuration:

1. **name**: A friendly name for your chatbot connector. This is for identification purposes.

2. **base_url**: The base URL of the chatbot API that the connector will communicate with. This is the starting point for all API requests.

3. **send_message**: This section contains details about how to send a message to the chatbot API:
   - **path**: The specific endpoint path that will be appended to the base URL for sending messages.
   - **method**: The HTTP method to use for the request (e.g., POST, GET). If not specified, POST is the default.
   - **headers**: Any custom headers required for the API request, such as authorization tokens.
   - **payload_template**: The structure of the message being sent, which often includes placeholders for dynamic content (e.g., user messages).

4. **response_path**: A dot-separated path that specifies how to extract the bot's reply from the JSON response returned by the API. This helps in identifying where the relevant data is located in the response.

### Example Structure

Here’s a simple example of how a connector might be structured:

```yaml
name: "My Custom Bot"
base_url: "https://api.mychatbot.com"
send_message:
  path: "/chat"
  method: "POST"
  payload_template:
    message: "{user_msg}"
response_path: "response.text"
```

In this example:
- The connector is named "My Custom Bot".
- It communicates with the API at `https://api.mychatbot.com/chat`.
- It sends messages using the POST method and expects to extract the response from the `response.text` field in the JSON reply.
