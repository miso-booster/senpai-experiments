Great question! 😊 In the context of Sensei, a **metamorphic rule** is a specific type of rule used in **Sensei-check** that helps verify the correctness of conversations generated by your chatbot. 

Here's a simple breakdown:

1. **Purpose**: Metamorphic rules check how outputs should change (or remain the same) when inputs change. This is particularly useful for validating relationships between different conversations rather than just checking for absolute correctness.

2. **Types of Checks**: These rules can target:
   - A **single conversation** (traditional oracle checks).
   - **Several conversations** (this is where metamorphic testing shines).
   - **All conversations** (global checks).

3. **How It Works**: You write these rules in a YAML format, specifying:
   - How many conversations are needed.
   - Conditions for selecting eligible conversations (using filters).
   - The expected relationships between outputs based on the inputs.

For example, if you have two conversations where the size of a pizza is the same, a metamorphic rule could check that if one has more toppings, it should cost more.

This approach helps alleviate the "oracle problem" by focusing on the relationships between outputs rather than just checking if each individual output is correct.
