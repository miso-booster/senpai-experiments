```yaml

```

### What's Right

1. **Name and Description**: The name and description are clear and informative.
2. **Conversations**: You've set it to `1`, which is appropriate for a single-conversation check.

### What's Not Quite Right

The `when` condition and the `oracle` condition are essentially the same in this case. The `when` condition is supposed to filter conversations based on certain criteria, while the `oracle` should define what the expected outcome is.

### Suggested Fix

To make this rule effective, you should separate the filtering condition from the expected outcome. Here’s a revised version:

```yaml
name: check_cau_information
description: Checks that the CAU provided correct information about contact details.
conversations: 1
when: "True"  # Always check this conversation
oracle: conv[0].contact_email == 'cau@uam.es' and conv[0].contact_phone == '91 497 4029' and conv[0].physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
```

### Explanation

1. **`when: True`**: This means that the rule will always apply to the conversation being checked. In this case, you want to check if the provided contact details are correct, regardless of any other conditions.
  
2. **`oracle`**: This remains the same, as it correctly states what you expect to be true about the conversation's output.

### Summary

By setting `when` to `True`, you're allowing the rule to always check the correctness of the contact details provided by the CAU. This way, you can effectively validate whether the information is accurate or not! If you have any more questions or need further assistance, feel free to ask! 😊
