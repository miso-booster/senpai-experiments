The **pairwise function** in the context of SENSEI-check is part of the metamorphic testing approach, which allows you to compare pairs of conversations to assert how outputs should change (or not) when inputs change. Here’s a breakdown of how it works:

### Key Concepts

1. **Metamorphic Rules**: These rules compare pairs or tuples of conversations that meet a selection filter, asserting relationships between their outputs based on changes in inputs. This helps alleviate the oracle problem by checking relations rather than absolute answers.

2. **Conversation Selection**: When writing a metamorphic rule, you specify:
   - How many conversations are needed (usually at least two).
   - An optional filter (`when`) that selects eligible conversations.
   - The relation to check between the selected conversations.

3. **Structure of a Rule**:
   - **`when`**: A condition that filters the conversations based on their attributes.
   - **`if`**: A precondition that checks a specific condition on the selected conversations.
   - **`then`**: The expected relation that should hold true if the `if` condition is satisfied.

### Example

Here’s a simple example of a metamorphic rule using the pairwise function:

```yaml
name: toppings_monotonicity
description: More toppings on a pizza cost more (same size/drink)
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

### Explanation of the Example

- **Purpose**: This rule checks that if two pizzas have the same size and drink, the one with more toppings should cost more.
- **Conversations**: It requires two conversations to compare.
- **Conditions**:
  - The `when` clause ensures that both pizzas are compared under the same conditions (size and drink).
  - The `if` clause checks if the first pizza has more toppings than the second.
  - The `then` clause asserts that the price of the first pizza should be greater than that of the second.

### Benefits of Pairwise Testing

- **Efficiency**: It allows for testing multiple scenarios without needing to check every possible combination.
- **Coverage**: Helps ensure that the chatbot behaves consistently across different inputs and outputs.

This approach is particularly useful in validating conversational agents, ensuring that they respond correctly and consistently based on varying user inputs.
