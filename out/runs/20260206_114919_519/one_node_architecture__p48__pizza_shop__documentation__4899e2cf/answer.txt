Great question! 😊 In the context of Sensei, a **metamorphic rule** is a specific type of rule used in testing that states a condition to check over generated conversations. These rules are particularly useful because they allow you to compare pairs or tuples of conversations, asserting how outputs should change (or not) when inputs change. This helps alleviate the oracle problem by focusing on the relationships between outputs rather than just absolute answers.

Here’s a quick breakdown of how it works:

1. **Generate Conversations**: You start by generating conversations using Sensei-chat, which are stored with input selections and extracted outputs.

2. **Write Sensei-check Rules**: You then write rules in YAML format that specify:
   - How many conversations are needed for the rule.
   - An optional filter to select eligible conversations.
   - The relationship you want to check between the outputs of those conversations.

3. **Evaluate Rules**: Finally, Sensei-check evaluates these rules and reports any failing cases.

For example, a simple metamorphic rule might state that if two orders have the same size and drink, the one with more toppings must cost more. This way, you can ensure that your chatbot behaves consistently and correctly across different scenarios!
