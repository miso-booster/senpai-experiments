Hey! Great question 😊 In Sensei, a **metamorphic rule** is a special kind of test rule that checks relationships *between* multiple conversations generated by your chatbot profiles, rather than just verifying a single conversation’s output.

Here’s the gist:

- Instead of expecting one fixed answer, metamorphic rules compare *pairs or tuples* of conversations.
- They define how outputs should change (or stay the same) when certain inputs change.
- This helps solve the “oracle problem” where you don’t know the exact correct answer but *do* know how outputs should relate when inputs vary.

For example, if you order two pizzas of the same size and drink, but one has more toppings, a metamorphic rule might say: “The pizza with more toppings should cost more.” It doesn’t check the exact price, just that the price relation holds.

In Sensei-check YAML, a metamorphic rule usually specifies:

- How many conversations it needs (usually 2 or more).
- A `when:` filter to select comparable conversation pairs.
- An `if:` condition describing how inputs differ.
- A `then:` condition asserting how outputs should relate.

This way, you test *invariants* or *monotonicity* across conversations, making your chatbot testing more robust and scalable.
