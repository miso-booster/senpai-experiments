Hey! Great question 😊 In the context of **SENSEI Rules** (especially Sensei-check), an **oracle** is basically a condition or test that tells you whether a chatbot's behavior or output is correct for a given conversation or set of conversations.

Think of it like a "truth test" or "expected outcome" that you define in a rule. When Sensei runs your chatbot simulations, it checks these oracles to see if the chatbot responses meet your expectations.

Here’s a simple way to understand it:

- For a **single conversation**, an oracle might say:  
  *"The price extracted from the chatbot's response should be at least $10."*  
  This is a boolean condition checked on that one conversation.

- For **multiple conversations** (metamorphic rules), an oracle can express relations like:  
  *"If conversation A has more toppings than conversation B, then the price in A should be higher than in B."*  
  This compares outputs across conversations.

In Sensei-check YAML rules, you usually see oracles as:

```yaml
oracle: <python-expression>
```

or as an implication:

```yaml
if: <condition>
then: <expected outcome>
```

So, the oracle is your **formalized expectation** that the chatbot should satisfy, enabling automated validation of chatbot behavior.
