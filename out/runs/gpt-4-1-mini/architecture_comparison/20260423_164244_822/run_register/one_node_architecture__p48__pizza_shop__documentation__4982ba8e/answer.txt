In a SENSEI profile YAML, some fields are mandatory for the profile to work properly, while others are optional or have defaults.

Here’s a quick rundown of the **non-mandatory (optional) fields** in a profile:

### Optional fields in a profile

- **`llm` section:**
  - `temperature` (has a default if omitted)
  - `model` and `model_prov` (defaults apply if not specified)
  - `format` (defaults to `type: text` if omitted)
  
- **`user.context`**  
  - This is optional; you can omit it or leave it empty. It’s used for extra persona prompts or constraints.
  
- **`user.goals`**  
  - While usually you want goals, technically you could have an empty list or none, but then the simulation won’t have any user intents.

- **`chatbot.is_starter`**  
  - Defaults to `false` if omitted.

- **`chatbot.fallback`**  
  - Optional but recommended to avoid endless loops.

- **`chatbot.output`**  
  - Optional if you don’t need to extract structured outputs, but if you want to write Sensei-check rules, you should define it.

- **`conversation.max_cost`**  
  - Optional, used for cost capping.

- **`conversation.goal_style`**  
  - Optional; if omitted, defaults apply (usually fixed steps).

- **`conversation.interaction_style`**  
  - Optional; defaults to `default` user behavior if not specified.

- **`conversation.number`**  
  - Optional; defaults to 1 if not specified.

---

### Summary

The **only truly mandatory fields** to have a runnable profile are:

- `test_name` (or `name`) — to identify the profile.
- `user.language` and `user.role` — to define who the user is.
- `user.goals` — to specify what the user wants.
- `chatbot` with at least `is_starter` (default false) and ideally `fallback`.
- `conversation.number` (defaults to 1 if omitted).

Everything else is optional or has sensible defaults.
