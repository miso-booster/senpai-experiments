A metamorphic rule in Sensei is a type of validation rule that checks relationships or invariants across multiple conversations, rather than just verifying a single conversation in isolation. Specifically:

- It compares pairs or tuples of conversations that meet certain selection criteria (filters).
- It asserts how outputs should change or remain consistent when inputs change between these conversations.
- This approach helps address the oracle problem by checking *relations* between conversations instead of absolute expected outputs.

For example, a metamorphic rule might say:  
"If two pizza orders have the same size, drink, and quantity, then the one with more toppings should cost more."  
This rule compares two conversations (orders) and checks a monotonicity property on price relative to toppings.

Key points from the Sensei-check DSL documentation (`sensei-check-doc.md`):  
- Metamorphic rules require specifying how many conversations to compare (usually 2 or more).  
- You use `conv[i].field` syntax to refer to fields extracted from each conversation's output (which come from the profile's `chatbot.output`).  
- Rules can express conditions with `when` (filter), `if` (precondition), and `then` (expected relation), or a direct `oracle` boolean condition.  
- They are typically profile-bound, meaning the rule fields correspond to outputs defined in a specific SENSEI Chat profile.

In summary, metamorphic rules check *relations* across multiple conversations to validate consistent, logical behavior of the chatbot under varying inputs.
