Hey! Great question 😊 In the context of Sensei, a **metamorphic rule** is a special kind of test rule used in **Sensei-check** to verify chatbot behavior by comparing multiple conversations, rather than just checking a single conversation in isolation.

Here’s the gist:

- Instead of expecting one exact answer (which can be tricky for chatbots), metamorphic rules check *relations* between conversations.
- They look at pairs or tuples of conversations generated by Sensei-chat and assert how outputs should change (or stay the same) when inputs change in controlled ways.
- For example, if you order two pizzas that differ only in the number of toppings, a metamorphic rule might say: "If pizza A has more toppings than pizza B, then pizza A’s price should be higher."
- This approach helps overcome the “oracle problem” (not knowing the exact correct answer) by focusing on *invariants* or *monotonic relations* that should always hold.

Technically, a metamorphic rule in Sensei-check is written in YAML and specifies:

- How many conversations it needs (usually 2 or more).
- A filter (`when:`) to select comparable conversation pairs.
- A condition (`if:`) describing the input change.
- An expected relation (`then:`) about the outputs.

Example snippet:

```yaml
name: toppings_monotonicity
description: More toppings increase price
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

So, metamorphic rules let you test chatbot correctness *across* conversations by checking logical relations, making your tests more robust and meaningful! 🎯
