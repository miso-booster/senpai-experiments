Hey! Great question 😊 In Sensei, a **metamorphic rule** is a special kind of test rule used in **Sensei-check** to verify chatbot behavior by comparing multiple conversations, not just one.

Here’s the gist:

- Instead of checking if a single chatbot response is exactly right (which can be tricky), metamorphic rules look at **relations between two or more conversations** generated by the same profile but with controlled input variations.
- They assert how outputs **should change or stay the same** when certain inputs change. For example, if you order a pizza with more toppings, the price should go up.
- This helps solve the “oracle problem” (hard to know the exact right answer) by focusing on **invariants or monotonic relations** rather than absolute correctness.

In practice, a metamorphic rule:

- Specifies how many conversations it needs (usually 2 or more).
- Filters which conversation pairs to compare (using a `when:` condition).
- States the expected relation between outputs (using `if:` and `then:` or a boolean `oracle:`).

Example:  
If two pizza orders have the same size and drink, but one has more toppings, then its price should be higher.

```yaml
name: toppings_monotonicity
description: Adding more toppings to a pizza costs more (same size/drink)
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Here, `conv[i].field` refers to fields extracted from the chatbot output in the profile.

So, metamorphic rules are powerful checks that ensure your chatbot behaves consistently and logically across variations of user inputs. They’re a core part of Sensei’s testing magic! ✨
