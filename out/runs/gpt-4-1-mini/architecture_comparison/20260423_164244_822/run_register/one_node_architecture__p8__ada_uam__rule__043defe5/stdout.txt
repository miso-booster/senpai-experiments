### Is it okay?

- The **`when`** clause is used to filter conversations where the contact details exactly match the expected values.
- The **`oracle`** then checks the same exact condition.

This means: the rule only applies to conversations where the contact details already match the expected values, and then it checks that they match. So it will never fail because it only runs on conversations that already meet the condition.

### Why is this a problem?

- The `when` filter is too strict — it excludes any conversation where the contact details are incorrect.
- So the rule never catches errors because it only runs on "correct" conversations.
- The `oracle` is redundant with `when` here.

### How to fix it?

You want to check that in **all conversations**, the contact details are exactly those values. So:

- Remove or loosen the `when` filter (or remove it entirely).
- Use the `oracle` to check that the fields equal the expected values.
- Since this is a single-conversation rule, you can just check the fields directly.

```yaml
name: check_cau_information
description: Checks that the CAU provided correct information about contact details.
conversations: 1
oracle: conv[0].contact_email == 'cau@uam.es' and conv[0].contact_phone == '91 497 4029' and conv[0].physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
```
