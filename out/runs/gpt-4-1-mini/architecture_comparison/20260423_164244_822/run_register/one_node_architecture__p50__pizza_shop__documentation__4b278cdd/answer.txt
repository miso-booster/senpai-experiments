Hey! Great question 😊 In the context of Sensei-check rules, an **oracle** is basically a condition or a test that tells you whether a chatbot’s response (or a set of responses) is correct or meets your expectations.

Think of it like a judge that looks at the chatbot’s output and says: “Yep, that’s good!” or “Nope, something’s off here.” It’s a logical expression you write in the rule that evaluates to `True` if the chatbot behaves as expected, or `False` if it doesn’t.

For example, in a single-conversation rule, an oracle might check if the chatbot’s price output is above zero:

```yaml
oracle: extract_float(price) > 0
```

In metamorphic testing (comparing multiple conversations), the oracle can express relations between outputs, like:

```yaml
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Here, the oracle is the `if`/`then` condition saying: *If* one pizza has more toppings, *then* its price should be higher.

So, the oracle is the core logical check inside a Sensei rule that validates chatbot correctness or consistency.
