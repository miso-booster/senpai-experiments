A metamorphic rule in Sensei is a type of validation rule that checks relationships or properties across multiple conversations, rather than just verifying a single conversation's correctness. Specifically:

- It compares pairs or tuples of conversations that meet certain selection criteria.
- It asserts how outputs should change (or remain invariant) when inputs change between these conversations.
- This approach helps address the oracle problem by focusing on *relations* between conversations instead of absolute expected outputs.

For example, a metamorphic rule might say: "If two pizza orders have the same size and drink, then the order with more toppings should cost more." This rule would compare two conversations and check that the price relation holds.

Key points from the Sensei documentation (`sensei-check-doc.md`):

- Metamorphic rules require at least 2 conversations (`conversations: 2` or more).
- They use expressions like `conv[0].field` and `conv[1].field` to access fields extracted from each conversation's outputs.
- You can write rules with `if`/`then` conditions or a single boolean `oracle` expression.
- They are typically tied to a SENSEI Chat profile that defines the output fields being checked.

In summary, metamorphic rules validate *relations* across multiple conversations to ensure consistent and logical behavior of the chatbot under varying inputs.
