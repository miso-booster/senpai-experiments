Hey! Great question 😊 In the context of **Sensei-check rules**, an **oracle** is basically a condition or a test that checks whether a chatbot’s behavior (or output) is correct for a given conversation or set of conversations.

Think of it like a judge or a referee: it looks at the chatbot’s responses and decides if they meet the expected criteria.

More specifically:

- An **oracle** is a logical expression (usually written in Python-like syntax inside the rule YAML) that evaluates to `True` if the chatbot’s output is correct, or `False` if there’s a problem.
- It can apply to a **single conversation** (checking if a particular output is valid) or to **multiple conversations** (checking relationships between outputs, which is called metamorphic testing).
- In Sensei-check, you often see `oracle:` fields in rules that define these correctness conditions.

For example, a simple oracle might check that the chatbot’s price output is above zero:

```yaml
oracle: extract_float(price) > 0
```

Or a metamorphic oracle might compare two conversations:

```yaml
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Here, the oracle says: *If one pizza has more toppings than another, its price should be higher.*

So, in short: **an oracle is the test logic that verifies if the chatbot behaves as expected.** It’s the heart of the automated checking in Sensei-check rules!
