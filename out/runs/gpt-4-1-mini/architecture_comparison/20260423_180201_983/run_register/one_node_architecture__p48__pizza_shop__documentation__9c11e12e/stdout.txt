Hey! Great question about Sensei profiles 😊.

In a Sensei profile YAML, **not all fields are mandatory**. Here's a quick rundown of which fields you can safely omit and which you usually need:

### Mandatory or highly recommended fields:
- `test_name`: Identifies your profile/test run.
- `user.language`: The language of the simulated user.
- `user.role`: Describes the simulated user's role or behavior.
- `user.goals`: At least one goal is needed to guide the conversation.
- `chatbot.output`: Defines the fields to extract from the chatbot's replies (important for rules).
- `conversation.number`: How many conversations to run (can be a fixed number or combinations).
- `llm.model`: Usually needed to specify which model to use (defaults may apply if omitted).
- `conversation.goal_style`: How the conversation ends (steps, all_answered, etc.).

### Fields that are **optional**:
- `llm.temperature`: Has a default if omitted.
- `llm.model_prov`: Provider key; optional if defaults work.
- `llm.format`: Defaults to text if omitted.
- `user.context`: Optional extra context or personality prompts.
- `chatbot.is_starter`: Defaults to false if omitted.
- `chatbot.fallback`: Recommended but optional (helps avoid loops).
- `conversation.max_cost`: Optional cost cap.
- `conversation.interaction_style`: Optional; defaults to natural style if omitted.
- `conversation.goal_style.export`: Optional, controls CSV export.
- `user.goals` variables’ `function`, `data`, and `type` can have defaults or be omitted if simple.

---

### TL;DR:
You **must** define the core sections that drive the simulation and extraction (`test_name`, user language/role/goals, chatbot output, conversation number/goal_style).  
Other fields like temperature, fallback messages, interaction styles, or context are **optional** and have defaults or can be omitted.
