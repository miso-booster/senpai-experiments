Hey! Great question 😊 In Sensei, a **metamorphic rule** is a special kind of test rule that checks relationships **between multiple conversations** generated by your chatbot simulator, rather than just checking a single conversation’s output.

Here’s the gist:

- Instead of verifying if one conversation’s output is exactly correct (which can be tricky for chatbots), metamorphic rules compare **pairs or groups of conversations** that differ in controlled ways.
- They assert how the chatbot’s outputs **should change or stay the same** when certain inputs change.
- This helps solve the “oracle problem” (not knowing the exact right answer) by checking **invariants or monotonic relations** — for example, if you add more toppings to a pizza order, the price should not go down.

In practice, a metamorphic rule in Sensei:

- Specifies how many conversations it needs (usually 2 or more).
- Filters which conversations to compare using a `when:` clause (e.g., same pizza size).
- Defines a relation using `if:` and `then:` expressions to check expected behavior across those conversations.

Example: If two pizza orders have the same size and drink, but one has more toppings, then the price of that one should be higher.

```yaml
name: toppings_monotonicity
description: Adding more toppings to a custom pizza costs more (same size/drink)
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

So, metamorphic rules are powerful because they check **relations** across conversations, making testing more robust and meaningful for chatbots where exact answers vary.
