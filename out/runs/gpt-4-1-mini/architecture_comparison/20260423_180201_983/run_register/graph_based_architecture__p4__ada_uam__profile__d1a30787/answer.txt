¡Claro! 😊 Te puedo ayudar a crear un perfil Sensei para simular un usuario que busca soporte sobre el CAU (Centro de Atención a Usuarios) de la UAM y que extraiga la información clave que mencionas: número de teléfono, email, dirección física y horarios.

Aquí tienes un ejemplo de perfil YAML que puedes usar como base para ese propósito:

```yaml
test_name: "Soporte CAU - Información de contacto"

llm:
  temperature: 0.7
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: Spanish
  role: >
    Eres un usuario que necesita soporte del Centro de Atención a Usuarios (CAU) de la UAM.
    Quieres obtener información de contacto clara y precisa para poder comunicarte con ellos.
  context:
    - "Busco el número de teléfono, correo electrónico, dirección física y horarios de atención del CAU."
  goals:
    - "¿Cuál es el número de teléfono para contactar al CAU?"
    - "¿Me puedes proporcionar el correo electrónico del CAU?"
    - "¿Dónde está ubicada la oficina física del CAU?"
    - "¿Cuáles son los horarios de atención del CAU?"

chatbot:
  is_starter: false
  fallback: "Disculpa, no entendí tu pregunta. ¿Podrías reformularla o consultar nuestro catálogo de servicios?"
  output:
    - contact_phone:
        type: string
        description: "Número de teléfono del CAU"
    - contact_email:
        type: string
        description: "Correo electrónico del CAU"
    - physical_address:
        type: string
        description: "Dirección física del CAU"
    - service_hours:
        type: string
        description: "Horarios de atención del CAU"

conversation:
  number: 3
  goal_style:
    steps: 10
  interaction_style:
    - single questions
```

---

### Explicación rápida:

- **user.role** define el tipo de usuario que simula.
- **user.context** añade un poco más de detalle para guiar el LLM.
- **user.goals** son las preguntas que el usuario hará en la conversación, enfocadas en obtener los datos que quieres.
- **chatbot.output** define las variables que quieres extraer al final, con nombres claros y tipos `string`.
- **conversation.number** y **goal_style.steps** controlan la cantidad y duración de las conversaciones.
- **interaction_style: single questions** simula que el usuario hace preguntas una a una, ideal para este tipo de soporte.
