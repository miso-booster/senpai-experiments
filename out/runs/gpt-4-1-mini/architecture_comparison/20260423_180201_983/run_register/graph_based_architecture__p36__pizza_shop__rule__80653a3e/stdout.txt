Hey! I see the rule you shared is missing the crucial `if:` condition that triggers the `then:` check. In Sensei-check, for metamorphic rules comparing conversations, you usually want an `if`/`then` structure to say:

- **if** some input changes (e.g., more toppings),
- **then** the output should change accordingly (e.g., price increases).

Your current rule has `when:` (filter) and `then:` (assertion), but no `if:` condition specifying *what* input difference triggers the price comparison.

---

### How to fix it?

Add an `if:` condition comparing the number of toppings between the two conversations, like this:

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: true
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

---

### Why?

- `when:` filters pairs of conversations with the same size and drink (good!).
- `if:` checks if the first conversation has more toppings than the second.
- `then:` asserts the price should be higher in the first conversation.

Without the `if:`, the rule doesn't know when to apply the price comparison, so it won't work as intended.
