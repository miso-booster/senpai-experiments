Hey! 😊 Let's take a look at your rule `check_cau_information`.

---

### Your rule:

```yaml
name: check_cau_information
description: Checks that the CAU provided correct information about contact details.
conversations: 1
when: conv[0].contact_email == 'cau@uam.es' and conv[0].contact_phone == '91 497 4029' and conv[0].physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
oracle: conv[0].contact_email == 'cau@uam.es' and conv[0].contact_phone == '91 497 4029' and conv[0].physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
```

---

### What I see:

- You're using a **single conversation** rule (`conversations: 1`), which is perfect for checking fixed values.
- Your `when` condition is exactly the same as your `oracle` condition.
- The `when` clause is a filter to select conversations to which the rule applies.
- The `oracle` is the actual check that must hold true for those conversations.

---

### Why this is a problem:

- The `when` condition is meant to **select** conversations where the check applies, but you are using it to check the exact same values you want to verify.
- This means the rule only applies if the values are already correct, so it will never catch errors.
- If the contact info is wrong, the `when` condition will be false, so the rule is skipped and no error is reported.
- Essentially, your rule is saying: "Only check conversations where the info is exactly correct, and then assert that info is exactly correct" — which is redundant and ineffective.

---

### How to fix it:

- Remove the `when` clause or make it more general (or omit it entirely).
- The `oracle` should check that the fields equal the expected values.
- Since you want to check that the CAU provides the correct contact info, you want the rule to apply to **all** conversations (or at least those that have these fields).
- So, just write the `oracle` to assert the expected values.
- Optionally, you can add an `on-error` message to help debugging.

---

### Fixed version:

```yaml
name: check_cau_information
description: Checks that the CAU provided correct contact details.
conversations: 1
oracle: conv[0].contact_email == 'cau@uam.es' and conv[0].contact_phone == '91 497 4029' and conv[0].physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
on-error: >
  Contact info mismatch:
  email={{conv[0].contact_email}}, phone={{conv[0].contact_phone}}, address={{conv[0].physical_address}}
```

---

### Explanation:

- We removed the `when` clause so the rule applies to every conversation.
- The `oracle` asserts that the fields have the exact expected values.
- If any field is wrong, the rule fails and reports the actual values for easier debugging.
- This way, the rule will catch any incorrect contact info instead of skipping them.

---

If you want to be more defensive and only check conversations that have those fields present, you could do:

```yaml
name: contact_info_presence
description: Check that contact email, phone, and physical address are present
conversations: 1
when: conv[0].contact_email is not None and conv[0].contact_phone is not None and conv[0].physical_address is not None
oracle: "'contact_email' in data_output and 'contact_phone' in data_output and 'physical_address' in data_output"
```

But usually, if your profile exposes those fields, you can omit `when` and check always.
