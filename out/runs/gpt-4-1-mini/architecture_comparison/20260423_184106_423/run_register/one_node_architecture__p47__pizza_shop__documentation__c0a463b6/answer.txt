Hey! Great question 😊 In Sensei, a **metamorphic rule** is a special kind of test rule that checks relationships between multiple conversations generated by your chatbot simulations, rather than just checking a single conversation’s output.

Here’s the gist:

- Instead of verifying if one conversation’s output is exactly right (which can be tricky for chatbots), metamorphic rules compare **pairs or groups of conversations**.
- They define how outputs **should change or stay consistent** when certain inputs change.
- For example, if you order two pizzas that differ only in the number of toppings, the pizza with more toppings should cost more. A metamorphic rule can check this monotonicity across two conversations.
- This approach helps overcome the “oracle problem” (not knowing the exact correct answer) by focusing on **invariants or expected relations** between outputs.

In Sensei’s YAML rules, you specify:

- How many conversations to compare (usually 2 or more).
- A `when:` filter to select comparable conversation pairs.
- An `if:` condition describing the input difference.
- A `then:` condition describing the expected relation on outputs.

Example snippet:

```yaml
name: toppings_monotonicity
description: More toppings increase price
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Here, it checks that when two orders have the same size and drink, the one with more toppings costs more.

So, metamorphic rules are powerful for testing chatbots by checking **relationships across conversations** rather than absolute correctness in isolation.
