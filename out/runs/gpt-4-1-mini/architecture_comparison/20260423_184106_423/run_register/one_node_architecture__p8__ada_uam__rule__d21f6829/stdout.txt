### Is it okay?

- The rule uses `conversations: 1`, which is correct for a single-conversation oracle.
- The `when:` condition is filtering conversations where the fields exactly match those values.
- The `oracle:` repeats the same condition as `when:`.

**Problem:**

- The `when:` is a filter that selects conversations to apply the rule on. If you put the exact same condition as the oracle, then the rule only runs on conversations that already have the correct values, so it will never fail.
- Usually, `when:` is used to select conversations where the fields are present or meet some criteria, and the `oracle:` checks the actual correctness.
- Here, you want to check that the conversation's extracted fields equal those exact values. So the `when:` should be more general (e.g., check that the fields are not None), and the `oracle:` should check the equality.

---

### How to fix it?

Change the `when:` to check that the fields exist (are not None or empty), then the `oracle:` asserts the exact values.

Here's a fixed version:

```yaml
name: check_cau_information
description: Checks that the CAU provided correct information about contact details.
conversations: 1
when: conv[0].contact_email is not None and conv[0].contact_phone is not None and conv[0].physical_address is not None
oracle: conv[0].contact_email == 'cau@uam.es' and conv[0].contact_phone == '91 497 4029' and conv[0].physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
```

---

### Explanation:

- `when:` filters conversations that have the contact fields extracted (not None).
- `oracle:` asserts that the extracted fields match the expected CAU contact details exactly.
- This way, if the bot returns wrong or missing info, the rule will fail and report it.
- If you keep `when:` equal to the oracle, the rule never runs on incorrect data, hiding errors.
