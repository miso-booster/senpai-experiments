### What "pairwise" means in Sensei-check rules

- Sensei-check supports **metamorphic rules** that compare multiple conversations, often in pairs (2 conversations).
- The rules specify `conversations: 2` to indicate the rule applies to pairs of conversations.
- The rule then uses expressions like `conv[0].field` and `conv[1].field` to access fields from each conversation in the pair.
- The rule defines a condition that relates the two conversations, for example:
  - If the pizzas have the same size and drink, then the one with more toppings should cost more.
  - This is a pairwise comparison of two conversations to check a monotonicity or invariant property.

### How pairwise works conceptually

- The system generates many conversations.
- Sensei-check selects pairs of conversations that satisfy the `when:` filter.
- For each pair, it evaluates the `if:` condition on the first conversation vs the second.
- If the `if:` condition holds, it asserts the `then:` condition must also hold.
- If any pair violates this, the rule fails.

### Example from the docs

```yaml
name: toppings_monotonicity
description: Adding more toppings to a custom pizza costs more (same size/drink/qty)
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink and conv[0].number == conv[1].number
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

- This rule compares pairs of conversations (`conv[0]` and `conv[1]`).
- It filters pairs where size, drink, and number are equal.
- It checks that if one has more toppings, its price must be higher.
