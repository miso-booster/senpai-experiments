Hey there! 😊 In the context of Sensei, a **metamorphic rule** is a special kind of test rule used in **Sensei-check** to verify chatbot behavior by comparing multiple conversations, not just one.

Here’s the gist:

- Instead of checking if a single chatbot response is exactly right (which can be tricky for open-ended conversations), metamorphic rules check **relations** between outputs of two or more conversations.
- These rules say things like: *“If input A changes in this way, then output B should change in that way (or stay the same).”*
- For example, if you order two pizzas that differ only by the number of toppings, a metamorphic rule might assert that the pizza with more toppings should cost more.
- This approach helps solve the “oracle problem” — where it’s hard to know the exact correct answer — by focusing on **invariants or monotonic relationships** across conversations.

Technically, a metamorphic rule in Sensei-check is written in YAML and specifies:

- How many conversations it needs (usually 2 or more).
- A filter (`when:`) to select comparable conversations.
- A relation to check (`if:` / `then:` or `oracle:`) over those conversations’ extracted outputs.

So, metamorphic rules are about **checking consistency and logical relations across multiple chatbot interactions**, making testing more robust and meaningful.
