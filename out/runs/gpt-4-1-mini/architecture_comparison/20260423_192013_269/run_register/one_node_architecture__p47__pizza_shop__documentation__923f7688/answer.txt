Hey! Great question 😊 In the context of Sensei, a **metamorphic rule** is a special kind of test rule used in **Sensei-check** to verify chatbot behavior by comparing multiple conversations, rather than just checking a single conversation’s output.

Here’s the gist:

- Instead of just validating if one conversation’s output is correct, a metamorphic rule looks at **pairs or tuples of conversations** that differ in some controlled way.
- It asserts how the chatbot’s outputs **should relate** when the inputs change. For example, if you order a pizza with more toppings, the price should be higher.
- This helps overcome the “oracle problem” (where it’s hard to know the exact correct answer) by checking **relations or invariants** between outputs instead of absolute correctness.

In Sensei-check, you write these rules in YAML, specifying:

- How many conversations to compare (usually 2 or more).
- A filter (`when`) to select comparable conversations.
- The metamorphic relation itself, often expressed as an `if`/`then` condition or a boolean `oracle`.

For example, a classic metamorphic rule might say:

> If two pizza orders have the same size and drink, but one has more toppings, then its price must be higher.

This rule compares two conversations (`conv[0]` and `conv[1]`) and checks that the price increases with toppings.

So, metamorphic rules in Sensei are powerful tools to check **consistency and logical relations** across multiple chatbot interactions, making testing more robust and meaningful.
