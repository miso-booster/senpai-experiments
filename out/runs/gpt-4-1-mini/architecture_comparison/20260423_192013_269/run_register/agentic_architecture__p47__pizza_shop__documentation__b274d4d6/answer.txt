A metamorphic rule in Sensei is a type of validation rule that checks relationships or consistency across multiple conversations rather than just verifying a single conversation's output. Specifically:

- It compares pairs or tuples of conversations that meet certain selection criteria (filters).
- It asserts how outputs should change or remain invariant when inputs change between these conversations.
- This approach helps overcome the "oracle problem" by focusing on relations (e.g., monotonicity, consistency) rather than absolute expected outputs.

For example, a metamorphic rule might say: "If two pizza orders have the same size and drink, the one with more toppings should cost more." This rule compares two conversations and checks that the price output behaves monotonically with respect to toppings.

Metamorphic rules are written in YAML with fields like:

- `conversations: N` (N ≥ 2, number of conversations to compare)
- `when:` (filter to select comparable conversation pairs)
- `if:` (precondition on the conversations)
- `then:` (expected relation between conversations)
- or alternatively `oracle:` for a boolean condition over multiple conversations

They typically reference fields from the profile's `chatbot.output` using syntax like `conv[0].field_name` and `conv[1].field_name`.

This concept is detailed in the "sensei-check-doc.md" documentation, which includes examples and best practices for writing metamorphic rules.
