Hey! Great question about the `pairwise()` function in Sensei profiles 😊.

In Sensei, when you define user goals with variables, you often want to test many combinations of these variable values to cover different scenarios. But testing *all* possible combinations (the full Cartesian product) can explode exponentially and become too costly or slow.

That's where `pairwise()` comes in — it’s a smart way to reduce the number of test cases while still covering **every possible pair of variable values at least once**. This is called *pairwise testing* or *all-pairs testing*.

---

### How `pairwise()` works in Sensei profiles:

- You assign `function: pairwise()` to **two or more variables** in your `user.goals`.
- Sensei generates a set of conversations that cover **all pairs** of values between those variables.
- This means every combination of any two variables' values appears in at least one conversation.
- It drastically reduces the total number of conversations compared to full combinations but still catches most interaction bugs.

---

### Simple example:

Suppose you have two variables:

```yaml
- color:
    function: pairwise()
    type: string
    data: [red, blue, green]
- size:
    function: pairwise()
    type: string
    data: [small, medium, large]
```

Instead of generating 3 × 3 = 9 conversations (all combinations), `pairwise()` might generate only 4 or 5 conversations that cover every pair of `(color, size)` values at least once.

---

### Why use `pairwise()`?

- **Efficiency:** Fewer conversations to run → faster tests, less cost.
- **Coverage:** Still covers all pairs of input values → good defect detection.
- **Scalability:** Works well when you have many variables with many values.

---

### Important notes:

- You need at least **two variables** assigned `pairwise()` for it to work.
- You can mix `pairwise()` with other functions like `forward()` for nested or dependent iteration.
- If you want to cover *all* combinations, use `forward()` instead (but beware of combinatorial explosion).
