Hey! Great question 😊 In the context of **SENSEI RULES** (specifically Sensei-check), an **oracle** is basically the *test condition* or *assertion* that you write to check if your chatbot behaves correctly.

Think of it like a "truth test" for conversations generated by your chatbot simulator:

- It’s a **boolean expression** (true/false) that inspects the outputs of one or more conversations.
- If the oracle evaluates to **true**, the chatbot passed that test.
- If it’s **false**, it means the chatbot’s behavior might be wrong or inconsistent.

For example, an oracle might check that the price of a pizza is never below $10, or that if you add more toppings, the price should increase.

In Sensei-check rules, you often see oracles written like this:

```yaml
oracle: extract_float(price) >= 10
```

This means: "The extracted price from the chatbot’s output should be at least 10."

Or in metamorphic rules (comparing multiple conversations), you might see:

```yaml
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Here, the oracle is the **if/then** relation, checking that adding more toppings leads to a higher price.

---

So, in short: **an oracle is the rule’s condition that verifies if the chatbot’s output is correct or consistent.**
