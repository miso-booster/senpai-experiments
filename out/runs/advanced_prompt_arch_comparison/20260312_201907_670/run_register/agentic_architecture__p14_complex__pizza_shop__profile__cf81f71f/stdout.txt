### Profile Comparison

#### 1. **pizza_order_test_custom**
- **Role**: User ordering a pizza.
- **Goals**:
  - Order a custom pizza with size and toppings.
  - Order drinks (cans).
  - Inquire about opening and closing times.
  - Ask for the total cost.
- **Outputs**:
  - Price of the order.
  - Opening time.
  - Order ID.

#### 2. **pizza_and_drinks_information_seeker**
- **Role**: Customer seeking information about pizzas, drinks, prices, and shop hours.
- **Goals**:
  - Ask about available pizza types.
  - Ask about the price of a Margarita pizza.
  - Ask about available drinks and their prices.
  - Ask about the shop's operating hours.
  - Inquire about delivery options.
- **Outputs**:
  - List of pizza types.
  - Price of a Margarita pizza.
  - List of drinks and their prices.
  - Shop's operating hours.
  - Delivery availability.

### **Better Profile**
The **pizza_and_drinks_information_seeker** profile is better suited for a user who wants information about drinks, prices, and opening hours. It directly addresses the user's needs for information rather than focusing on placing an order.

### Rule Mapping and Suggestions
#### Existing Rules
The following rules are available in the project:
1. **conversation_lengths.yaml**: Checks if the number of turns equals the conversation length.
2. **more_toppings_cost_more.yaml**: Ensures that adding more toppings increases the cost.
3. **only_talks_about_pizza.yaml**: Ensures the chatbot stays on topic regarding pizzas.
4. **ordering_conversation_turns.yaml**: Checks the order of conversation turns.
5. **ordering_conversation_turns_assistant.yaml**: Checks if the assistant confirms the pizza order after the user orders.
6. **same_number_of_toppings_cost_the_same.yaml**: Checks if pizzas with the same number of toppings cost the same.

#### Rule Mapping
- **pizza_and_drinks_information_seeker** does not have direct mappings to the existing rules since they focus more on ordering and pizza specifics rather than information gathering.
