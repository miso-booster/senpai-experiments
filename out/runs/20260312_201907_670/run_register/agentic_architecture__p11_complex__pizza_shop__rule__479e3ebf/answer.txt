Let's check if the **pizza order test custom** profile works with the rules **more toppings cost more** and **same number of toppings cost the same**.

### Profile: pizza_order_test_custom
- **Outputs**:
  - `price`: The final price of the pizza order (type: currency)
  - `time`: Just the opening time (type: time)
  - `order_id`: My order ID (type: string)

### Rule 1: more_toppings_cost_more
- **Description**: Adding more toppings to a custom pizza costs more.
- **Active**: True
- **Conversations**: 2
- **Condition**:
  - **When**: `conv[0].size == conv[1].size and conv[0].drink == conv[1].drink`
  - **If**: `len(conv[0].toppings) > len(conv[1].toppings)`
  - **Then**: `extract_float(conv[0].price) > extract_float(conv[1].price)`

### Rule 2: same_number_of_toppings_cost_the_same
- **Description**: Pizzas with the same number of toppings cost the same.
- **Active**: False
- **Conversations**: 2
- **Condition**:
  - **When**: `conv[0].drink == conv[1].drink`
  - **If**: `conv[0].size == conv[1].size and len(conv[0].toppings) == len(conv[1].toppings)`
  - **Then**: `extract_float(conv[0].price) == extract_float(conv[1].price)`

### Compatibility Analysis
1. **Compatibility with `more_toppings_cost_more`**:
   - This rule is **active** and checks if the price increases when the number of toppings increases, which aligns well with the outputs defined in the profile. The rule references `price`, which is present in the profile's `chatbot.output`.

2. **Compatibility with `same_number_of_toppings_cost_the_same`**:
   - This rule is **inactive**. It checks if pizzas with the same number of toppings have the same price. However, since it is not active, it won't be evaluated during testing.

### Conclusion
- The **pizza_order_test_custom** profile is compatible with the **more toppings cost more** rule, as it actively checks the relationship between toppings and price.
- The **same number of toppings cost the same** rule is not currently active, so it won't affect the testing process.
