Great question! 😊 In the context of Sensei, a **metamorphic rule** is a specific type of rule used in **Sensei-check** that helps verify the correctness of conversations generated by the Sensei user simulator. 

Here's a simple breakdown:

1. **Purpose**: Metamorphic rules check how outputs should change (or not) when inputs change across pairs or tuples of conversations. This approach helps address the "oracle problem," which is the challenge of determining the correctness of outputs in a conversational AI context.

2. **Structure**: Each metamorphic rule states a condition that can target:
   - A **single conversation** (traditional oracle),
   - **Several conversations** (the essence of metamorphic testing),
   - Or **all conversations** (global checks).

3. **Evaluation**: These rules compare pairs of conversations that meet certain criteria (like having the same pizza size or drink) and assert relationships between their outputs. For example, if two pizzas have the same size and drink, the one with more toppings should cost more.

4. **YAML Format**: You write these rules in YAML format, specifying how many conversations are needed, any filters for selecting eligible conversations, and the relations to check.

Here's a quick example of a metamorphic rule:

```yaml
name: toppings_monotonicity
description: More toppings increases total price
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

In this example, if one pizza has more toppings than another of the same size and drink, it should have a higher price.
