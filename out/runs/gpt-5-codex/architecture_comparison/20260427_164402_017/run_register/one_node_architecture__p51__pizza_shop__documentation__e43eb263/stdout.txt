Hey there! 👋 Connectors are Sensei’s way of talking to your actual chatbot. Think of them as bridge blueprints: they describe *how* Sensei should send messages to your bot’s API and *where* to read the reply. Once you have a connector YAML, Sensei can run your profiles against the real service without extra coding. ✨

Each connector file is a small YAML spec made up of a few key fields:

- **`name`** *(optional)* — a friendly label so you recognize the connector.
- **`base_url`** *(required)* — the root URL of your chatbot’s API, e.g. `https://api.mychatbot.com`.
- **`send_message`** *(required)* — tells Sensei how to call the API:
  - `path` *(required)* — endpoint appended to the base URL (like `/chat`).
  - `method` — HTTP verb (defaults to `POST` if you skip it).
  - `headers` — any HTTP headers to send (auth tokens, content type, etc.).
  - `payload_template` *(required)* — JSON structure with `"{user_msg}"` where Sensei will inject the simulated user’s text.
- **`response_path`** *(required)* — dotted path to reach the bot’s answer inside the JSON response (`results.0.answer`, `data.message`, and so on).

With those pieces, you can point Sensei to virtually any chatbot API. Pretty handy, right? 😊 Let me know if you want help drafting or tweaking a connector!
