Hey there! Great question—`pairwise()` is one of those little Sensei superpowers that quietly saves tons of time 😊. Let me walk you through how it works in profiles.

### 🎯 What `pairwise()` does

When you have multiple variables in your `user.goals` (like pizza type, size, drink, etc.), trying every possible combination can blow up into a huge number of conversations. `pairwise()` steps in to cover **every possible pair of values** across the selected variables, without forcing a full Cartesian explosion.

Think of it like planning outfits: instead of wearing every single garment combo, you make sure every *shirt* has been paired with every *pair of pants* at least once. You explore all pairs, but skip redundant full outfits. Efficient and still thorough!

### 🔧 How to use it

- You can assign `function: pairwise()` to **multiple variables**. Sensei will then make sure that for **every pair of those variables**, each value combo appears in at least one conversation.
- It’s especially handy for wide option sets (size, crust, toppings, etc.).
- You need **at least two variables** using `pairwise()` for it to take effect.
- A cool bonus: if you set `conversation.number: combinations` (or `combinations(p)`), Sensei will automatically base the run on the matrix generated by those pairwise functions.

### 🧩 Example from your project

In your `pizza_order_test_custom.yml` profile, you do this:

```yaml
- size:
    function: pairwise()
    data: [small, medium, big, extra large]
- toppings:
    function: pairwise()
    data: [cheese, mushrooms, pepperoni]
```

That means Sensei will generate conversations so that **every size pairs with every topping at least once**, but it won’t repeat full combinations unnecessarily. Much leaner than exploring every possible setting across the other variables!

### 🌟 When to reach for `pairwise()`

Use it when:

- You have multiple variables that interact, and you want to test how each pair plays together.
- You care about: “Did we test every size+topping combo somewhere?”
- You want strong coverage without the full combinatorial overload.
