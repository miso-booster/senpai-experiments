Hey there! 👋 I noticed the original rule couldn’t run because it references `user_request`, which isn’t exposed in any of your profile outputs. Since the `customer_service_assistance` profile already extracts `contact_options` and `customer_service_number`, the easiest fix is to turn this into a single-conversation rule that simply checks those fields aren’t empty. Here’s a working version:

```yaml
name: customer_service_contact_info
description: Ensure the chatbot provides contact options and a customer service number.
conversations: 1
oracle: contact_options not in [None, ""] and customer_service_number not in [None, ""]
```
