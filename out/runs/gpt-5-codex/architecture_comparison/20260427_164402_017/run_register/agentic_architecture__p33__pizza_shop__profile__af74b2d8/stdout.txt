Here’s how I’d complete the `chatbot` section for your profile 😊. I followed the structure and guidance from **`sensei-chat-guide.md`**, especially the parts about setting `is_starter`, providing a real fallback, and making sure `chatbot.output` covers everything we’ll want to validate later.

```yaml
chatbot:
  is_starter: false
  fallback: "I'm sorry, could you clarify your question?"
  output:
    - pizza_types:
        type: list[string]
        description: "Pizza varieties the chatbot mentions as available."
    - margherita_price:
        type: string
        description: "Price quoted for a Margherita pizza (include currency)."
    - drink_options:
        type: list[string]
        description: "Drinks the shop offers."
    - drink_price_details:
        type: list[string]
        description: "Drink names with their prices or price ranges."
    - operating_hours:
        type: list[string]
        description: "Shop hours or schedule provided by the chatbot."
    - delivery_details:
        type: string
        description: "Whether delivery is available and any related notes."
```

### Why these fields?
- **`is_starter: false`** assumes the user opens the conversation, which aligns with an information-seeker persona.
- **`fallback`** gives the bot a natural recovery line, as the docs recommend.
- The **output fields** match each of your goals: pizzas, Margherita price, drinks (and their prices), operating hours, and delivery availability. I used `string`/`list[string]` so we don’t rely on extra custom types; if you already have a `currency` type defined, feel free to switch `margherita_price` (and even the drink prices) to that.

Let me know if you want to capture anything else from the bot’s replies or prefer a different schema!
