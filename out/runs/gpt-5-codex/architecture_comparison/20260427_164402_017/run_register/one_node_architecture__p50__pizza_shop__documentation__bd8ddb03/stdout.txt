In a Sensei rule, the **`oracle`** is the heart of the check—it’s the condition that must evaluate to `True` for the conversation (or set of conversations) to pass the rule. Think of it like the “truth detector” that compares what actually happened in the chatbot dialogue against what *should* happen according to your expectations.

- For a **single conversation rule**, `oracle` is usually a boolean expression over the fields exposed in `chatbot.output` (plus any helper functions you need).  
- For **metamorphic rules** that compare multiple conversations, you often use `when` to pick comparable cases and then either:
  - Define the metamorphic relation directly in `oracle`, or
  - Use `if`/`then` instead for a clearer implication-style structure (Sensei allows either, but `if`/`then` is recommended for complex comparisons).

Example (single conversation):

```yaml
oracle: data_collected() == True
```

This passes only if every slot defined in `chatbot.output` is filled.

So, whenever you see or write `oracle: ...`, you’re stating “Here’s the exact condition that must hold true for this rule.” Let me know if you’d like to see it in action with any of your project’s rules!
