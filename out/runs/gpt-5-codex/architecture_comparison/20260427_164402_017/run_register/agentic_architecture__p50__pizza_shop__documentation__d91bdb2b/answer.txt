Hey there! 😊 In Sensei-check rules, an **oracle** is simply the boolean condition the rule evaluates to decide whether a conversation (or set of conversations) passes or fails.

From the **`sensei-check-doc.md`** guide:
- You put the condition under the `oracle:` key when your rule is a straightforward “this should be true” statement.  
- Sensei-check evaluates that expression using the conversation data (e.g., slots exposed by the related profile, helper functions like `extract_float`, `language`, etc.).  
- If the expression returns `True`, the rule passes; if it returns `False`, the rule fails.

The **`rules-examples.md`** file shows quick snippets, for example:

```yaml
name: chatbot_does_not_repeat
conversations: 1
oracle: not repeated_answers(method='exact', threshold=1)
```

Here, the oracle checks that `repeated_answers(...)` is empty—i.e., the bot isn’t repeating itself. You can think of `oracle` as the rule’s “truth test.” Whenever your validation can be expressed as a single boolean, `oracle` is the right place for it.

If you need something more conditional (“if X happens, then Y must also happen”), you switch to the `if:` / `then:` form, but for single-shot checks the `oracle` key is the go-to. Let me know if you’d like to see more examples or how to combine it with profile outputs!
