Since there isn’t a profile yet, I went with a **rule-first design** and invented some placeholder output slots you can align with your future profile. Feel free to rename them later — just remember to keep the rule and the profile consistent.

Here’s a handy template:

```yaml
name: lactose_free_availability
description: Lactose-free products must surface an explicit availability status
conversations: 1
when: is_lactose_free is True
oracle: availability_status in ['in_stock', 'out_of_stock', 'limited']
```

### What this rule assumes
- **`is_lactose_free`** → boolean flag indicating whether the requested product is lactose-free.
- **`availability_status`** → normalized string describing availability (e.g., `in_stock`, `out_of_stock`, `limited`).

Once you design the matching SENSEI Chat profile, make sure its `chatbot.output` includes these slots (or equivalents such as `product_name`, `dietary_tags`, etc.), and update the rule to match the actual field names if they change. After that, you’ll be all set to catch any missing availability info for lactose-free items 🙌
