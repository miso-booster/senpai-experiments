Great question! In Sensei-check rules, an **oracle** is the logical condition that must evaluate to `True` for the rule to pass. Think of it as the “expected outcome” you’re asserting about a conversation (or a group of conversations).

When you write a rule in YAML, you’ll usually see an `oracle:` field like this:

```yaml
name: chatbot_does_not_repeat
description: The server does not repeat answers
conversations: 1
oracle: not repeated_answers(method='exact', threshold=1)
```

Here, the oracle checks whether the assistant avoided repeating itself. If the expression after `oracle:` is true, the rule passes; if not, the rule fails and Sensei-check will flag the conversation.

For metamorphic rules (those comparing multiple conversations), you can still use `oracle:` with a boolean expression, or you can split the logic into an `if:` / `then:` pair—whichever reads more naturally for the relation you want to enforce.

Hope that clears it up! Let me know if you’d like to see more examples or help crafting your own oracle 😊
