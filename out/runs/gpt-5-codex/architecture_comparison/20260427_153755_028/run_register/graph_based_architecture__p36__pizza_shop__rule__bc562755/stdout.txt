Without it, the checker doesn’t know *when* it should enforce `price[0] > price[1]`, so the rule either fails outright or behaves unpredictably.

Here’s how you can fix it:

1. **Restore the `if:` clause** — this tells Sensei-check to only compare prices when conversation 0 really has *more* toppings.
2. (Optional but recommended) **Match quantities too**, so you’re comparing apples to apples (or pizzas to pizzas 😉).

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: true
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink and conv[0].number == conv[1].number

then: extract_float(conv[0].price) > extract_float(conv[1].price)
```
