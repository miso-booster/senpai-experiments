Connectors are the “transport layer” between Chatbot Dojo’s simulator and the real chatbot API you want to test. Instead of writing Python code, you describe the HTTP request/response flow in a YAML file, and the platform uses that to send simulated user messages to your bot and read back its replies (per `custom-connector-guide.md` and `connector-examples.md`).

Key fields you’ll define:

- `name` (optional): A friendly label so you can recognize the connector in the UI/logs.
- `base_url` (required): The root URL for the chatbot API.
- `send_message` (required block) — tells Sensei how to call the API:
  - `path` (required): Endpoint path appended to `base_url`.
  - `method` (optional, default `POST`): HTTP verb.
  - `headers` (optional): Any custom headers (e.g., Authorization keys).
  - `payload_template` (required): JSON body template. Use `{user_msg}` wherever the user’s message should go; you can include any other fixed or contextual fields your API expects.
- `response_path` (required): Dot notation pointing to the chatbot’s reply inside the JSON response (e.g., `response.0.text`).

Those are the only core pieces you need to describe a connector; the docs also show real examples such as the “Metro Madrid” connector with custom headers and nested payloads (`connector-examples.md`). Once this YAML is in place, Chatbot Dojo can call your bot seamlessly during profile runs. Let me know if you’d like to walk through making one! 😊
