Hey there! 😊 In Sensei, a **metamorphic rule** is a guardrail you define in Sensei-check to verify how a chatbot behaves across **multiple conversations at once**—not just a single dialog.

Instead of asking “Was this one response correct?”, a metamorphic rule says something like: *“If two conversations have the same drink and pizza size but one adds extra toppings, the price shouldn’t go down.”* It compares the outputs from different runs (usually generated by a Sensei profile) and checks that a relationship you expect still holds.

A quick snapshot of the structure:

- `conversations: 2` (or more) tells Sensei-check you’re comparing multiple dialogs.
- `when:` filters the pairs/tuples you want to compare.
- `if:` describes the condition you’re examining.
- `then:` (or `oracle:`) enforces the expected relationship between their outputs.

So metamorphic rules are perfect for things like price monotonicity, language consistency across variations, or any property where *changing input X should (or shouldn’t) change output Y*. They’re super handy when there’s no single “correct” answer but you still know how results should relate.
