The `pairwise()` function lives in the **Sensei profile goals** section and it’s all about covering lots of combinations without blowing up the number of conversations you have to run.

### What `pairwise()` actually does
- Imagine you have several variables (like pizza size, crust type, drink choice).
- A full Cartesian grid of every combo would be huge. `pairwise()` is smarter: it builds a test set where **every pair of variables appears together at least once**.
- That means any two options (e.g., size + crust, size + drink, crust + drink) get exercised in some conversation, but you don’t need to test *all* possible triples.

### Why it’s handy
- It’s a sweet spot between coverage and cost: you still catch interactions between variables, but your run size stays manageable.
- Teams love it when they have lots of user inputs and want confidence that the bot handles mixed cases correctly.

### How to use it in a profile
Just assign it to two (or more) variables that you’d like to combine:

```yaml
- pizza_size:
    function: pairwise()
    type: string
    data: [small, medium, large]

- crust_type:
    function: pairwise()
    type: string
    data: [thin, regular, stuffed]

- drink:
    function: pairwise()
    type: string
    data: [cola, water, lemonade]
```

A few tips:
- You need **at least two variables** set to `pairwise()` for the magic to happen.
- Sensei will compute a pairwise coverage matrix behind the scenes and schedule just enough conversations to hit every pair once.
- If you mix `pairwise()` with other functions (like `forward()`), the combination logic will respect dependencies—so `forward(crust_type)` can depend on a pairwise-assigned variable.

Hope that clears things up! If you want to see how pairwise affects your conversation count, you can also run the **validation check** (it prints the generated matrix). Let me know if you’d like a walkthrough 😄
