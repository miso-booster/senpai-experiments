¡Hola! 😄 Me encanta que quieras crear un perfil Sensei para comprobar cómo responde el chatbot de la UAM cuando alguien necesita los datos de contacto del CAU. Aquí tienes una propuesta totalmente alineada con la guía de Sensei Profiles. Puedes copiarla tal cual en `profiles/soporte_cau_contacto.yaml` (o el nombre que prefieras):

```yaml
test_name: "Soporte CAU - Contacto rápido"

llm:
  temperature: 0.5
  model: gpt-4o-mini
  format:
    type: text

user:
  language: Spanish
  role: "Usuario que necesita contactar con el Centro de Atención a Usuarios (CAU) de la UAM para resolver dudas técnicas."
  context:
    - "Tienes un problema con los servicios digitales universitarios y necesitas hablar con el CAU cuanto antes."
    - "Quieres asegurarte de que cuentas con todos los datos de contacto para elegir el canal más conveniente."
  goals:
    - "Pedir el número de teléfono del CAU."
    - "Solicitar la dirección de correo electrónico para contactar con el CAU."
    - "Preguntar por la dirección física del CAU."
    - "Solicitar los horarios de atención del CAU."

chatbot:
  is_starter: false
  fallback: "¿Puedes reformular tu consulta? Si lo prefieres, visita el catálogo de servicios del CAU."
  output:
    - cau_phone:
        type: string
        description: "Número de teléfono del CAU"
    - cau_email:
        type: string
        description: "Correo electrónico del CAU"
    - cau_address:
        type: string
        description: "Dirección física del CAU"
    - cau_service_hours:
        type: string
        description: "Horario de atención del CAU"

conversation:
  number: 3
  goal_style:
    steps: 10
  interaction_style:
    - single questions
```

### ¿Por qué funciona bien este perfil?

- **Metas claras**: los objetivos se centran exactamente en los datos que quieres validar (teléfono, email, dirección, horario).
- **Salida alineada con las reglas**: en `chatbot.output` definimos los cuatro campos que luego podrás usar en Sensei-check como `conv[i].cau_phone`, etc.
- **Interacción sencilla**: `single questions` hace que el simulador pida cada dato de forma separada, ideal si quieres comprobar respuestas consistentes para cada canal de contacto.

Si te apetece añadir más realismo, puedes sumar un `personality` en el contexto o ajustar `goal_style.steps` para conversaciones más largas. Dime si quieres que lo adaptemos para otros escenarios (por ejemplo, usuarios nuevos o soporte fuera de horario). ¡Estoy aquí para ayudarte! 😊
