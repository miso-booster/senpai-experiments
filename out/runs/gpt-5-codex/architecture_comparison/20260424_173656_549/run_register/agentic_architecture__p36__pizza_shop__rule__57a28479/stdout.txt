The rule keeps firing even when the first conversation doesn’t actually have more toppings than the second one. In Sensei-check (see the metamorphic examples in `sensei-check-doc.md`), whenever you use a `then:` clause you also need an `if:` clause to spell out the precondition that triggers the comparison. Without it, every pair of conversations that matches the `when:` filter is forced to satisfy the “price must be higher” constraint, which naturally fails when the number of toppings is equal or lower.

Here’s the fixed version with the missing precondition added:

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: True
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

If your profile also exposes the quantity ordered (e.g., `conv[0].number`), consider extending the `when:` filter to keep that equal too, which is the pattern shown in the same doc. Let me know if you’d like help tightening the filter! 😊
