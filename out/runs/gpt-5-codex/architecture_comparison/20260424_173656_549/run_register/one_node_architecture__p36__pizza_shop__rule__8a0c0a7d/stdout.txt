Hey there! The rule was failing because it never checked that conversation 0 actually had *more* toppings than conversation 1. Without that precondition, Sensei-check will compare every pair of conversations with the same size/drink and expect the first one to be pricier—even when it doesn’t have extra toppings. Adding the `if:` clause fixes the logic so it only enforces the price increase when the toppings truly increase.

Here’s the corrected rule:

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: true
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Double-check that the profile feeding this rule exposes `size`, `drink`, `toppings`, and `price` in its `chatbot.output`. If any of those fields are named differently, align the rule accordingly. Let me know if you’d like help verifying that!
