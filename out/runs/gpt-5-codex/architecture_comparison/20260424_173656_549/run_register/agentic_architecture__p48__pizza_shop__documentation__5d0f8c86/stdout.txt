Here’s a quick rundown of what the docs say about optional pieces in a Sensei profile (see `sensei-chat-guide.md` for details):

### Top-level sections
- **`llm` block** – totally optional. Sensei has defaults, so only add it when you need custom model/temperature/format settings (FAQ explicitly says you don’t have to define it).
- **`conversation.interaction_style`** – you can leave it out; it just tweaks how the simulated user talks. If omitted, Sensei uses its natural/default interaction.
- **`conversation.max_cost`** – optional cap for the whole run. Skip it if you don’t need a budget guardrail.

### Inside `user`
- **`context` entries** – optional. You can supply none, plain strings, or personality references (`personalities/...`) as needed.
- **Variables in `goals`** – only declare the ones you actually use in the goal strings. Extra variable blocks aren’t mandatory.

### Inside `chatbot`
- **`fallback`** – while recommended (to prevent loops), the guide treats it as “put your bot’s real fallback here” rather than a strict requirement, so you can omit it if your bot handles errors another way.
- **`output` fields** – define only the fields you actually want to extract for later validation. There’s no minimum count enforced by the DSL.

### Inside `conversation.goal_style`
- **`max_cost`** (per conversation) – optional just like the global one.
- **`all_answered.export`** and **`all_answered.limit`** – optional extras in that specific mode; defaults apply if you leave them out.

So the bare minimum profile is basically `test_name`, a `user` block with at least one goal, `chatbot` with whatever outputs matter to you (possibly none if you just want raw transcripts), and a `conversation.number` plus some goal-style definition. Everything else is there for refinement and can be skipped until you need it. Let me know if you want an example of the slimmest valid profile!
