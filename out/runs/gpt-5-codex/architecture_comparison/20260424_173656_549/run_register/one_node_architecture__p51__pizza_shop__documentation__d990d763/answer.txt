**Sensei connectors** are the bridge between Sensei’s simulated users and your real chatbot. They describe—purely in YAML—how to send a message to your bot’s API and where to read the reply. This way, you can plug Sensei into almost any service without writing custom code.

Here’s a quick tour of the key fields you’ll find in a connector file:

| Field | What it does | Required? |
|-------|--------------|-----------|
| **`name`** | Friendly label for the connector (helps keep configs organized). | No |
| **`base_url`** | Root URL of your chatbot’s API. Every request will start here. | ✅ Yes |
| **`send_message.path`** | Endpoint path appended to the base URL (e.g. `/chat`). | ✅ Yes |
| **`send_message.method`** | HTTP method (`POST`, `GET`, etc.). Defaults to `POST` if you omit it. | No |
| **`send_message.headers`** | Any HTTP headers you need to pass (auth tokens, content type…). | No |
| **`send_message.payload_template`** | JSON body template. Use `{user_msg}` as a placeholder for the simulated user’s message. | ✅ Yes |
| **`response_path`** | Dot notation telling Sensei where the chatbot’s reply lives inside the JSON response (e.g. `data.message.text`). | ✅ Yes |

Once this YAML is in place, Sensei can send conversation turns through your connector, automatically fill `{user_msg}` with each user prompt, and extract the bot’s reply using the `response_path`.

If you’d like to see full examples, your project already ships with a few in `users/user_1/connectors/`, like `postman.yaml` (simple echo bot) and `metro-madrid.yml` (API with headers). They’re perfect references when you build your own connector.
