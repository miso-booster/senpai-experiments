### What connectors are for

In Sensei, **connectors** are the lightweight bridge between the simulator and your real chatbot. Instead of writing custom Python code, you just describe the chatbot’s API in a YAML file. Sensei then uses that configuration to send user messages, receive the bot’s replies, and keep the conversation flowing. Super handy when you want to plug in different bots quickly!

### Key fields you’ll see in a connector YAML

| Field | What it means |
|-------|---------------|
| `name` *(optional)* | A friendly label for the connector (helps you identify it). |
| `base_url` *(required)* | The root URL of your chatbot’s API. |
| `send_message` *(required block)* | Describes how to call the API. Inside you can set:<br>• `path` *(required)* – the endpoint to hit (appended to `base_url`).<br>• `method` *(optional, default `POST`)* – HTTP method to use.<br>• `headers` *(optional)* – any headers you need (think auth tokens, content type, etc.).<br>• `payload_template` *(required)* – JSON structure you want to send. Drop `{user_msg}` wherever the user’s message should go. |
| `response_path` *(required)* | The dot-separated path to the bot’s reply inside the JSON response. Example: `data.messages.0.text`. |

That’s the whole contract! With just those pieces, you can describe almost any chatbot API—whether it’s a quick echo service or a production bot with authentication and nested responses. If you ever need to store multiple connectors, just keep each YAML in your `users/<user_id>/connectors/` folder so you can swap between them.
