In Sensei profiles, the `pairwise()` function is a smart way to cover lots of variable combinations without exploding into hundreds of conversations. Think of it as planning a tasting where every pair of ingredients gets tried together at least once, but you don’t have to taste *every possible recipe*.

Here’s what it does:

- You declare `pairwise()` on two or more variables in `user.goals`.
- Sensei builds a minimal set of conversations so that **every possible pair** of values across those variables appears together at least once.
- This gives you strong coverage for interactions between variables (great for catching bugs) while keeping the total number of runs manageable.

For example, if you have:
- `pizza_type` (Margherita, Pepperoni, Veggie)
- `pizza_size` (Small, Medium, Large)
- `crust_type` (Thin, Regular)

Full combinations would be 3 × 3 × 2 = 18. With `pairwise()`, Sensei generates a much smaller set (say 7 or 8), but every pair like `(Margherita, Medium)` or `(Pepperoni, Thin crust)` appears somewhere. It’s similar to pairwise test design in traditional QA.

A couple of gotchas:
- You need **at least two variables** using `pairwise()`; otherwise Sensei can’t build the coverage matrix.
- If you mix `pairwise()` with other functions like `forward()` or `random()`, make sure the dependencies make sense. For instance, `forward(pizza_type)` can piggyback on a `pairwise()` variable.

In short: `pairwise()` = broader coverage, fewer conversations, still great at spotting issues in how two parameters interact 💡
