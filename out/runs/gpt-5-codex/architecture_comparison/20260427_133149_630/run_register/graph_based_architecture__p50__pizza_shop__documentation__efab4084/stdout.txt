Great question! In the context of **Sensei Rules** (the Sensei-check system), an **oracle** is simply the condition we write to decide whether a conversation—or a group of conversations—behaves correctly. Think of it like the “pass/fail” test for each scenario.

### How it works
- When you define a rule in Sensei-check, you can choose between two styles:
  1. **`oracle:`** — a single boolean expression that must be `True` for the rule to pass.
  2. **`if:` / `then:`** — an implication: *if* the precondition is met, *then* the expected relation must hold.

Each time Sensei evaluates a rule, it plugs in the conversation data (like `conv[0].price`, `language(chatbot_phrases)`, etc.) into that oracle expression. If the expression returns `True`, the rule passes. If it’s `False`, you get a failure report to investigate.

### Example (straight from the docs)
```yaml
oracle: only_talks_about('pizza orders, drink orders, information on delivery of pizzas, information about the pizza shop')
```
Here, the oracle checks that the assistant doesn’t drift off-topic. If the helper function returns `True`, the conversation is good. If not, the rule fails.

So, short version: **an oracle is the rule’s truth test**—the formal way we express what “correct behavior” looks like for the chatbot 😊.
