Here you go! 😊 Based on the guidance from `sensei-check-doc.md` and the examples in `rules-examples.md`, I drafted a single-conversation rule that assumes a future profile will expose the fields it references.

```yaml
name: lactose_free_availability
description: Verifies that lactose-free product requests are explicitly confirmed as available.
active: true
conversations: 1
if: lactose_free_requested
then: availability_status in ['available', 'in_stock', 'ready_for_pickup']
on-error: f"Lactose-free product {requested_product} was reported as {availability_status}."
```

### Assumed profile outputs
Because this is a rule-first design, the eventual profile should provide at least:
- `lactose_free_requested` (boolean) — whether the user asked for a lactose-free option.
- `availability_status` (string) — normalized status such as `available`, `in_stock`, or `ready_for_pickup`.
- `requested_product` (string) — used in the error message for clarity.

Once you stand up the profile, feel free to adjust the allowed availability values or the error message to match your own taxonomy. Let me know if you’d like help creating that profile too!
