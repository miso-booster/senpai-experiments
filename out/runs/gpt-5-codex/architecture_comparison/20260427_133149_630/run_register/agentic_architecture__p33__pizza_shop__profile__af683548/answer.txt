Here’s a `chatbot` section that lines up with the goals of your info-seeking user and follows the structure from `sensei-chat-guide.md` 😊. I’ve placed it inside your profile so you can copy/paste the whole block if that’s easier:

```yaml
test_name: pizza_and_drinks_information_seeker
llm:
  temperature: 0.3
  model: gpt-4o-mini
  format:
    type: text
user:
  language: English
  role: A customer seeking information about pizza types, prices, available drinks, and shop hours before potentially placing an order.
  context:
  - 'personality: personalities/skeptical-user'
  - You're planning a casual pizza night at home with friends this weekend and are considering ordering from a local pizzeria.
  - You want to gather all the necessary information before deciding what to order and whether to pick it up or have it delivered.
  - You have a variety of preferences among your friends, so you need to find options that cater to different tastes.
  goals:
  - Ask about the available pizza types.
  - Ask about the price of a Margarita pizza.
  - Ask about the available drinks and their prices.
  - Ask about the shop's operating hours.
  - Ask if they deliver.
chatbot:
  is_starter: false
  fallback: "Sorry, could you rephrase that?"
  output:
    - pizza_menu:
        type: list[string]
        description: "List of available pizza varieties the bot offers."
    - margarita_price:
        type: string
        description: "Quoted price for a Margarita pizza, including currency."
    - drinks_menu:
        type: list[string]
        description: "Available drinks with any prices mentioned."
    - operating_hours:
        type: string
        description: "Opening and closing hours provided by the bot."
    - delivery_option:
        type: string
        description: "Details on whether delivery is available and any conditions."
conversation:
  number: 3
  max_cost: 0.5
  goal_style:
    all_answered:
      export: false
      limit: 20
  interaction_style:
  - single question
```

Why these fields?

- `is_starter: false` keeps the user simulator in charge of kicking things off (per the guidance in `sensei-chat-guide.md`).
- The fallback message prevents loops if the bot doesn’t understand something.
- The `chatbot.output` schema captures every bit of info your scenario cares about—menu breadth, pricing, hours, and delivery details—so future rules can validate them.

If you want structured currency parsing later, you can add a `types/currency.yml` custom type (the guide has an example) and change `margarita_price` to `type: currency`. Let me know if you want help with that too!
