It’s failing because the rule is using a `then:` clause without an accompanying `if:`. In Sensei-check, `then:` must always be paired with `if:`—otherwise the rule tries to enforce the price comparison for **every** pair of conversations that pass the `when:` filter, even if toppings didn’t actually change. Here’s a corrected version that only applies the price constraint when one order truly has more toppings than the other:

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: true
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```
