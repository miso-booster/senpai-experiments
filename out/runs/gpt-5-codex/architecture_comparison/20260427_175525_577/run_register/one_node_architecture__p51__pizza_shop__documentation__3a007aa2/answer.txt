**Connectors** are Sensei’s way of telling the simulator *how* to talk to your real chatbot. Instead of writing Python code, you drop in a YAML file that describes the chatbot’s API—how to send messages, what headers to include, and where to find the reply in the JSON response. With that config in place, Sensei can run your profiles against any HTTP-based bot, whether it’s a public API or your own service.

Here are the key fields you’ll see in a connector YAML:

| Field | What it means |
|-------|----------------|
| `name` | Optional label for the connector (handy when you have several). |
| `base_url` | The root URL of the chatbot API (e.g., `https://api.mybot.com`). |
| `send_message.path` | Endpoint path appended to `base_url` (like `/chat` or `/messages`). |
| `send_message.method` | HTTP verb for the request. Defaults to `POST` if you leave it out. |
| `send_message.headers` | Any HTTP headers you need—authorization tokens, content type, etc. |
| `send_message.payload_template` | JSON body template. Wherever Sensei should inject the user’s message, you place the `{user_msg}` placeholder. You can include other static or dynamic fields here too. |
| `response_path` | Dot notation showing where to find the bot’s reply in the JSON response. For example, `data.answers.0.text` digs into `response["data"]["answers"][0]["text"]`. |

Once you set those, Sensei takes care of the rest—posting user turns, reading bot replies, and plugging them into your testing flow. Pretty neat, right? 😊 If you need help tweaking a specific connector, just let me know!
