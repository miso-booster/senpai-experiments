Since this profile is all about gathering menu and service details, the `chatbot` section should declare a fallback message, whether the bot starts the conversation, and—most importantly—the fields you want Sensei to extract for later checks or reporting. Here’s a ready-to-use block that mirrors the user goals:

```yaml
chatbot:
  is_starter: false
  fallback: "I'm sorry, I did not get what you said. I can help you ordering predefined or custom pizzas, and then drinks."
  output:
    - pizza_types:
        type: string
        description: >-
          A list of the pizza types offered by the shop. Look for phrases like
          "We offer..." followed by the pizza names.
    - margarita_price:
        type: money
        description: >-
          The price of a Margarita pizza, including the currency if mentioned.
          Capture every size mentioned for this flavor.
    - drinks_and_prices:
        type: string
        description: >-
          The available drinks together with their prices (name + price pairs).
    - operating_hours:
        type: string
        description: >-
          The shop's operating hours, including opening and closing times.
    - delivery_availability:
        type: string
        description: >-
          Whether the shop offers delivery or not (e.g., "We deliver" / "Pickup only").
```

These outputs map one-to-one with the questions in your goals, making it easy to plug Sensei-check rules or analytics on top. Let me know if you’d like to add anything else!
