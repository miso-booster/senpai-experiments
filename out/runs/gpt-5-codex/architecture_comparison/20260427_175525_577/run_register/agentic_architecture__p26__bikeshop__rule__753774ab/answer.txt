Hey! Here’s what I spotted in the original rule (based on the guidance in `sensei-check-doc.md`):

- `conversations: 2` isn’t needed, because we only read from one conversation. For single-conversation checks the DSL expects `conversations: 1` and direct slot names instead of `conv[0]`.
- `when:` was being used to assert the price; per the docs it should only filter which conversations get checked. If the price were wrong the rule would simply skip the conversation instead of failing.
- `then:` has to be a boolean condition. Returning a string (`"The tune-up price is $50."`) never evaluates to `True/False`, so the rule could misbehave.

Here’s the cleaned-up version:

```yaml
name: check_tune_up_price
description: Checks if the tune-up price is equal to $50.
conversations: 1
if: tune_up_price is not None
then: extract_float(tune_up_price) == 50
```

What changed and why:

1. Switched to `conversations: 1` and dropped `conv[0]`, matching the single-conversation pattern described in `sensei-check-doc.md`.
2. Removed the price comparison from `when:` so the rule actually evaluates the price inside the assertion.
3. Replaced the string in `then` with a boolean expression using `extract_float`, which the docs recommend for numeric checks.

If your profile stores `tune_up_price` as a number instead of a string, feel free to adjust the `then` line to something like `then: tune_up_price == 50`. Let me know if you need that tweak or want to add a currency check!
