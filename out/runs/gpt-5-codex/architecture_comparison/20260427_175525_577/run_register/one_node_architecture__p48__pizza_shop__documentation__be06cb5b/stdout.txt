In a Sensei profile, only the pieces that define the basic user simulation are strictly required: the `test_name`, `user` block (with language, role, context/goals), and the `chatbot.output` schema you plan to extract. Everything else is optional and can be added only when you need to fine-tune behavior.

Here are the most common **non-mandatory** sections and fields:

- **`llm` block** — you can skip it if you’re fine with the default model/temperature. Add it only to override defaults or switch to speech mode.
- **`conversation` controls**
  - `number` (defaults to the combinations derived from your goal functions; if those don’t exist, Sensei uses 1 conversation).
  - `max_cost` (both at the conversation and goal-style level).
  - `goal_style` (if you omit it, Sensei uses its default step limit).
  - `interaction_style` — totally optional; the simulator will behave “naturally” without it.
- **`chatbot.is_starter` and `chatbot.fallback`** — they provide better UX but aren’t mandatory.
- **Extra flavor in `user.context`** — you can keep it minimal; only the essentials are needed.
- **Any custom personalities, types, or advanced goal functions** — they’re great for richer tests but not required for a valid profile.

So feel free to leave out any of these optional bits until you actually need them. If you want me to review a specific profile and confirm it’s compliant, just share it and I’ll take a look!
