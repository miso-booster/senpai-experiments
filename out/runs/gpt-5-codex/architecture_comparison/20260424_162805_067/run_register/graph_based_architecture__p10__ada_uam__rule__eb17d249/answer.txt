¡Hola! 😊 Gracias por compartir el perfil, está súper completo y da bastante juego para probar comportamientos interesantes. Aquí tienes algunas ideas de reglas en Sensei-check que pueden ayudarte a validar que el bot entrega la información clave de forma consistente. Cada bloque YAML puedes guardarlo como un archivo dentro de tu carpeta `rules/`. Ajusta nombres o filtros si ves que tu bot responde con estructuras diferentes.

---

### 1. Los enlaces y datos básicos no pueden venir vacíos
Comprueba que los campos fundamentales que prometes en `chatbot.output` llegan con contenido.

```yaml
name: enlaces_clave_presentes
description: Asegura que los enlaces y la info principal para admisiones no vienen vacíos.
conversations: 1
oracle: all(field not in [None, '', 'N/A']
           for field in [
             admission_to_grados_link,
             waitlist_info_link,
             future_students_link,
             welcome_day_link,
             future_students_info,
             enrollment_process
           ])
```

---

### 2. El bot debe responder en español (igual que la persona usuaria)
Refuerza la experiencia en español, que es como está planteado el perfil.

```yaml
name: respuestas_en_espanol
description: La asistente mantiene el idioma en español como el usuario potencial.
conversations: 1
oracle: responds_in_same_language() is True
```

---

### 3. Misma titulación → mismos requisitos de admisión
Si dos conversaciones preguntan por el mismo grado, deberían recibir requisitos idénticos (a menos que algo cambie en la base de datos). Esta regla metamórfica detecta incoherencias.

```yaml
name: requisitos_consistentes_por_grado
description: Un mismo grado debe tener requisitos de admisión consistentes entre conversaciones.
conversations: 2
when: conv[0].grados == conv[1].grados and conv[0].grados is not None
oracle: conv[0].admission_requirements == conv[1].admission_requirements
```

---

### 4. Welcome Day coherente (fecha y hora)
Si el evento Welcome Day existe en ambas conversaciones, la fecha y la hora no deberían cambiar.

```yaml
name: welcome_day_coherente
description: La fecha y hora del Welcome Day se mantienen estables cuando existen en ambas conversaciones.
conversations: 2
when: conv[0].welcome_day_date is not None and conv[1].welcome_day_date is not None
if: conv[0].welcome_day_time is not None and conv[1].welcome_day_time is not None
then: conv[0].welcome_day_date == conv[1].welcome_day_date and conv[0].welcome_day_time == conv[1].welcome_day_time
```

---

### 5. Cuota de solicitud válida
Revisa que el campo de tarifa de solicitud contenga un importe numérico positivo (y descarta “N/A” u otros placeholders).

```yaml
name: cuota_solicitud_valida
description: La cuota de solicitud debe ser un importe positivo cuando se proporcione.
conversations: 1
when: application_fee not in [None, '', 'N/A']
oracle: extract_float(application_fee) > 0
```
