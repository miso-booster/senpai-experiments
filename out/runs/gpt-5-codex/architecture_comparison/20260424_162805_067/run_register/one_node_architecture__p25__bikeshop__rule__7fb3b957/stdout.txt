Sure thing! Here’s a rule you can drop into your project to enforce those exact outputs for the QA profile conversations:

```yaml
name: qa_expected_prices
description: Opening hours and key prices must match the QA golden values
conversations: 1
oracle: >
  '10' in opening_and_closing and
  '20' in opening_and_closing and
  extract_float(tune_up) == 50 and
  extract_float(tire) == 20 and
  extract_float(seat_price) == 20
on-error: >
  f"opening_and_closing={opening_and_closing}, tire={tire}, tune_up={tune_up}, seat_price={seat_price}"
```

This checks that:
- The opening hours string mentions both “10” and “20”.
- Tune-up and tire prices extract to 50 and 20 respectively.
- The seat price string also resolves to 20.
