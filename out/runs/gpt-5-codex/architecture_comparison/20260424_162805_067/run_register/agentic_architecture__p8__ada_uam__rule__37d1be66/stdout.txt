Hey! Here’s what I found while reviewing `check_cau_information`:

### What needed fixing
1. **`when` duplicated the assertion** – Because the `when` clause required the contact data to be *already correct*, the rule only ran (and trivially passed) when everything was right. That meant it could never fail, defeating the purpose.
2. **Single-conversation access pattern** – In single-conversation rules (`conversations: 1`), you can (and per `sensei-check-doc.md` examples, usually should) reference the profile outputs directly instead of via `conv[0]`. I confirmed in `consultante_de_servicios_y_asistencia_del_cau.yaml` (`sensei-chat-guide.md`) that the outputs are `contact_email`, `contact_phone`, and `physical_address`, so we can reference them plainly.

### Updated rule
```yaml
name: check_cau_information
description: Checks that the CAU provided correct information about contact details.
conversations: 1
oracle: contact_email == 'cau@uam.es' and contact_phone == '91 497 4029' and physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
```

### Why this works
- The rule now runs for every conversation generated by the profile and will **fail** whenever any of the three fields differs from the expected CAU contact data.
- Keeping the expression in `oracle` only ensures the check reflects the intent directly, matching the single-conversation patterns described in `sensei-check-doc.md`.
- It aligns with the `chatbot.output` contract in `consultante_de_servicios_y_asistencia_del_cau.yaml` (documented workflow in `sensei-chat-guide.md`).
