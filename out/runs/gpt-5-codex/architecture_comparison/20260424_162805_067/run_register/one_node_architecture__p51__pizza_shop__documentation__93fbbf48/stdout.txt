Hey there! 👋 Connectors in Sensei are your bridge between the user simulator and a real (or test) chatbot API. Instead of writing custom code, you drop in a YAML file that describes **how to send messages** and **where to read the bot’s reply**. Sensei then uses that configuration to drive full conversations against your bot.

Here’s a quick rundown of the core fields you’ll define:

| Field | What it does | Required? |
|-------|--------------|-----------|
| `name` | Friendly label for the connector (helps you remember what it’s for). | No |
| `base_url` | Root URL of the chatbot API you’re testing. | Yes |
| `send_message.path` | Endpoint path appended to `base_url`. | Yes |
| `send_message.method` | HTTP verb (POST is the default if you skip it). | No |
| `send_message.headers` | Any headers the API needs (Auth, Content-Type, etc.). | No |
| `send_message.payload_template` | JSON payload with placeholders like `{user_msg}` where Sensei will inject the simulated user’s message. | Yes |
| `response_path` | Dot-separated path pointing to the bot’s text in the JSON response (`messages.0.content`, for example). | Yes |

With those pieces in place, Sensei can send user messages, capture the bot’s replies, and feed everything into your profiles and rules for evaluation. Super handy when you want to wire up a new bot in minutes ✨
