In Sensei-check, a **metamorphic rule** is a rule that evaluates the relationship between **multiple conversations at once** instead of judging each conversation in isolation. As described in `sensei-check-doc.md`, these rules:

- Require `conversations` to be set to a value ≥ 2 (or `all`), so Sensei can compare pairs or tuples of dialogs.
- Use a `when` filter to pick comparable conversations (same pizza size, same customer segment, etc.).
- Express a relational expectation with either:
  - an `oracle` boolean expression, or
  - an `if` / `then` implication such as “if order A has more toppings than order B, then order A’s price must be higher.”

Because they look at **how outputs change when inputs change**, metamorphic rules help validate behaviors like monotonic pricing, consistent language, or uniqueness of IDs—things that aren’t obvious from a single conversation. They’re especially powerful when tied to a specific Sensei Chat profile: the rule reads fields like `conv[0].price` or `conv[1].toppings`—which come from that profile’s `chatbot.output`—to check those relationships across conversations.

In short, metamorphic rules are Sensei’s way of doing multi-conversation checks: they enforce “if input varies like X, output should vary like Y” patterns, which catches regressions or inconsistencies that single-conversation rules would miss. (`sensei-check-doc.md`)
