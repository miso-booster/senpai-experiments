Here’s a general-purpose rule that flags conversations where the user asks about promotions but the assistant never mentions any:

```yaml
name: assistant_mentions_current_promotions
description: Ensures the assistant shares current promotion details whenever the user requests them.
conversations: 1
if: |
  utterance_index('user', 'current promotion') >= 0
  or utterance_index('user', 'promotion') >= 0
  or utterance_index('user', 'deal') >= 0
  or utterance_index('user', 'discount') >= 0
then: |
  utterance_index('assistant', 'current promotion') >= 0
  or utterance_index('assistant', 'promotion') >= 0
  or utterance_index('assistant', 'deal') >= 0
  or utterance_index('assistant', 'discount') >= 0
on-error: f"User requested promotion info but the assistant reply lacked promotion details: {chatbot_phrases}"
```

### How it works
- It’s profile-agnostic: the rule only relies on the generic helper `utterance_index`, so it can apply across any profile.
- The `if` block looks for user turns that mention promotions, deals, or discounts.
- The `then` block requires the assistant to reference similar promotion language in response.
- The `on-error` message surfaces the assistant’s utterances to speed up debugging.

This design follows the guidance from **sensei-check-doc.md** (structure of `if`/`then` rules and helper usage) and the helper patterns shown in **rules-examples.md** (notably the examples that use `utterance_index`). Feel free to tweak the keyword lists to match the vocabulary your chatbot and users typically use.
