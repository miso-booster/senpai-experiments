¡Gracias por compartir la regla! 😊 Te cuento:

- Ahora mismo, el `when` está filtrando únicamente las conversaciones que ya tienen los valores correctos. Si la información estuviera mal, la condición no se cumpliría y la regla ni siquiera se evaluaría. En otras palabras, no detectaría el error 😅.
- Además, como es una regla de una sola conversación, podemos referirnos a los campos directamente, sin `conv[0]`.

Aquí tienes la versión corregida:

```yaml
name: check_cau_information
description: Checks that the CAU provides the expected contact details.
conversations: 1
oracle: contact_email == 'cau@uam.es' and contact_phone == '91 497 4029' and physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
on-error: f"Expected CAU contact info to be cau@uam.es / 91 497 4029 / C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107 but got {contact_email} / {contact_phone} / {physical_address}"
```

Así, la regla se ejecuta siempre y fallará si el chatbot entrega un correo, teléfono o dirección distintos. ¡Listo para validar esos datos del CAU! 💪
