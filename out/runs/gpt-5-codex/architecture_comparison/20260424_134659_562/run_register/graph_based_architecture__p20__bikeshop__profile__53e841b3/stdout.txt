Hey there! I put together a fresh Sensei profile that focuses on wheel-change appointments with plenty of date/time variation so you can really probe how the chatbot manages scheduling nuances. 😊  
You can drop it in `profiles/wheel_change_appointment_tester.yaml` (or any name you like).

```yaml
test_name: wheel_change_appointment_tester

llm:
  temperature: 0.3
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: >
    You're a cyclist who needs both wheels swapped out and wants to lock in an
    appointment. You’re attentive to scheduling details and double-check what the
    assistant confirms.
  context:
    - "Your bike has noticeable wear on both wheels after a long tour."
    - "You only have limited availability over the next two weeks."
    - "If a slot isn't open, you prefer the closest alternative on the same day."
  goals:
    - "Ask if I can schedule a wheel replacement service."
    - "Request an appointment for {{appointment_date}} at {{appointment_time}} to change both wheels."
    - "If that slot is unavailable, ask for the nearest alternative time on the same day."
    - "Confirm the final appointment details, including date, time, and service."
    - appointment_date:
        function: pairwise()
        type: string
        data:
          - next Monday
          - this Friday
          - April 22nd
          - May 3rd
          - June 10th
    - appointment_time:
        function: pairwise()
        type: string
        data:
          - 9:30 AM
          - 11:00 AM
          - 2:15 PM
          - 4:45 PM
    - service_detail:
        function: another()
        type: string
        data:
          - front and rear wheel change
          - rear wheel replacement only
          - full wheel swap and alignment check

chatbot:
  is_starter: false
  fallback: "I'm sorry it's a little loud in my shop, can you say that again?"
  output:
    - appointment_confirmation:
        type: string
        description: >
          The chatbot's final confirmation message summarizing the scheduled service.
    - scheduled_date:
        type: string
        description: >
          The date the chatbot confirms for the appointment.
    - scheduled_time:
        type: string
        description: >
          The time the chatbot confirms for the appointment.
    - alternative_slot_response:
        type: string
        description: >
          The chatbot's reply when offering an alternative time (if the original request
          was unavailable).
    - service_confirmation:
        type: string
        description: >
          The chatbot's confirmation that the wheel-change service will be performed.

conversation:
  number: combinations(1, pairwise)
  max_cost: 0.8
  goal_style:
    all_answered:
      export: false
      limit: 8
  interaction_style:
    - default
```

### Why this setup rocks
- **Pairwise coverage** across `appointment_date` and `appointment_time` guarantees you touch a wide spread of date/time pairs without exploding into every possible combination.
- The user goals push the assistant through: availability check → preferred slot → fallback slot → confirmation, so you can write rules around each stage using `chatbot.output`.
- `service_detail` adds flavor, encouraging the chatbot to repeat what service it’s booking (and giving you another field to validate in rules if needed).

Let me know if you want a variant (e.g., different languages, extra follow-up questions, or integration with existing rules)!
