Hi there! 😊 Here’s a fresh Sensei Chat profile for the UAM CAU support scenario. I followed the structure and best practices from `sensei-chat-guide.md`, especially around defining user goals and the `chatbot.output` schema so future rules can validate each contact detail.

**Highlights**
- Simulates a Spanish-speaking UAM student asking for CAU phone, email, office location, and opening hours.
- Uses `goal_style: all_answered` to encourage the bot to cover every goal before stopping.
- Exposes four structured outputs (`cau_phone_number`, `cau_email`, `cau_location`, `cau_opening_hours`) ready for downstream rules.

```yaml
test_name: "uam_cau_support_info"

llm:
  temperature: 0.4
  model: gpt-4o
  model_prov: openai
  format:
    type: text

user:
  language: Spanish
  role: >
    Eres un estudiante de la Universidad Autónoma de Madrid que necesita
    contactar con el Centro de Atención al Usuario (CAU) para resolver dudas.
  context:
    - "Quieres confirmar los canales oficiales de contacto antes de llamar."
    - "Necesitas la información para compartirla con compañeros de clase."
  goals:
    - "Solicita el número de teléfono del CAU de la UAM."
    - "Pregunta por la dirección de correo electrónico de contacto del CAU."
    - "Pregunta dónde está ubicado físicamente el CAU dentro de la UAM."
    - "Pregunta cuál es el horario de atención del CAU."

chatbot:
  is_starter: false
  fallback: "Lo siento, no dispongo de esa información. ¿Puedes reformular tu consulta?"
  output:
    - cau_phone_number:
        type: string
        description: "Número de teléfono de contacto del CAU."
    - cau_email:
        type: string
        description: "Correo electrónico oficial del CAU."
    - cau_location:
        type: string
        description: "Ubicación física del CAU dentro de la UAM."
    - cau_opening_hours:
        type: string
        description: "Horario de atención del CAU."

conversation:
  number: 1
  goal_style:
    all_answered:
      limit: 8
  interaction_style:
    - default
```

Feel free to tweak the persona or interaction style if you want edgier testing (e.g., typos or language switches). Let me know if you’d like a matching rule set to validate the extracted fields!
