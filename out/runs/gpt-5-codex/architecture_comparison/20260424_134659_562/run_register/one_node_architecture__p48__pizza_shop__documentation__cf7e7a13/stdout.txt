In a Sensei profile most sections *can* be customized, but quite a few pieces are optional because Sensei provides sensible defaults. Here’s a quick rundown of the pieces you don’t have to include unless you need them:

### Top-level sections
- **`llm`** – optional. If you leave it out, Sensei falls back to the project’s default model, temperature, and text mode.
- **`conversation.max_cost`**, **`conversation.interaction_style`**, and many knobs inside `conversation.goal_style` – all optional. You only add them when you want to control spending, turn counts, or special user behaviours.

### Inside `user`
- **`context`** – optional. Use it only when you want to give extra backstory or personalities.
- Even within `goals`, you don’t need advanced function/data blocks unless you’re parameterising variables.

### Inside `chatbot`
- **`fallback`** technically isn’t required, though it’s good practice.
- Any extraction field inside `chatbot.output` is optional—declare only the slots you’ll actually inspect later.

### Extras that aren’t required
- **`personalities/`** directory, **custom `types/`**, and any personality references are optional and only needed if you rely on them.

In short, the core Sensei engine only needs the bare essentials to know who the user is, what they ask for, and how to pull outputs. Everything else (LLM tuning, cost caps, interaction styles, personality snippets, etc.) is opt-in so you can keep profiles lightweight or dial them up when you need richer simulations. Let me know if you want a minimal “bare bones” template!
