Hola! 😊 Happy to chat about connectors.

**What are Sensei connectors for?**  
Connectors are the little “bridges” that let Sensei talk to your chatbot. Instead of writing custom Python integration code, you describe how to reach your bot’s API in a YAML file. Sensei then uses that config to send the simulated user’s messages and read the bot’s replies. Handy, right?

**Key fields inside a connector YAML:**

| Field | Why it matters |
|-------|----------------|
| `name` | Friendly label so you know which bot you’re hitting. Optional but nice to have. |
| `base_url` | The root URL for your chatbot’s API. Required! |
| `send_message.path` | The specific endpoint appended to `base_url` for each user message. |
| `send_message.method` | HTTP verb (POST by default, but can be GET, PUT, DELETE…). |
| `send_message.headers` | Any custom headers (Authorization tokens, content type, etc.). Optional. |
| `send_message.payload_template` | JSON body with a `{user_msg}` placeholder where Sensei will drop the simulated user’s text. Required. |
| `response_path` | Dot‑notation path to pull the bot’s reply from the JSON response (e.g., `data.answer`). Required so Sensei knows where to look. |

Once you fill those in, Sensei handles the rest—sending user messages, receiving the responses, and keeping the whole conversation flowing. Let me know if you’d like a sample template or help adjusting one of your configs!
