Hi there! Connectors are the “transport layer” in Chatbot Dojo—they describe, in YAML, how the simulator should talk to an external chatbot API without writing any Python glue code. Once you point a profile to a connector, the simulator knows exactly how to send the user’s message to your real bot and where to read the reply from. (Source: `custom-connector-guide.md`, `connector-examples.md`)

### Core fields you’ll see in a connector YAML
- **`name`** *(optional)* – A friendly label so you can tell connectors apart in the UI or logs.
- **`base_url`** *(required)* – The API root for your chatbot (e.g., `https://api.mybot.com`).
- **`send_message`** *(required object)* – Defines how to send a single turn:
  - `path` *(required)* – Endpoint path appended to `base_url`, like `/chat/send`.
  - `method` *(optional, defaults to POST)* – HTTP method (POST, GET, etc.).
  - `headers` *(optional)* – Any HTTP headers the API needs (e.g., Authorization tokens).
  - `payload_template` *(required)* – JSON payload skeleton that must include `{user_msg}` wherever the user’s message goes.
- **`response_path`** *(required)* – Dot notation path telling the simulator where to extract the bot’s reply inside the JSON response (e.g., `response.0.text`).

Example snippets in `connector-examples.md` show how headers and nested payloads work, including authenticated calls (e.g., “Ada UAM” and “Metro Madrid”).

So, think of connectors as the configuration map: they specify the URL, request body, headers, and response parsing. Once configured, profiles can reuse them, and rules can validate the conversations those connectors produce. Let me know if you’d like to walk through creating one step by step!
