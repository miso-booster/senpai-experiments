Sure thing! Here’s a single Sensei-check rule that validates the expected hours and prices for your `qa` profile outputs 😊:

```yaml
name: qa_expected_hours_and_prices
description: Verify the QA profile returns 10-20 hours and $20 tire, $50 tune-up, $20 seat prices
conversations: 1
oracle: |
  '10' in opening_and_closing
  and '20' in opening_and_closing
  and extract_float(tire) == 20
  and extract_float(tune_up) == 50
  and extract_float(seat_price) == 20
on-error: >
  f"Got opening_and_closing={opening_and_closing}, tire={tire}, tune_up={tune_up}, seat_price={seat_price}"
```

Drop this into your `rules/` folder and you’ll be set to flag any mismatches. Let me know if you’d like this extended with currency checks or additional fields!
