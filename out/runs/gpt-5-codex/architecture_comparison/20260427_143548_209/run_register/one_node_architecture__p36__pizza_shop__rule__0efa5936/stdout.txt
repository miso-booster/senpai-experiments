Hey there! 😊 The rule was firing on every pair of conversations that matched the `when` filter, even when the two orders had the same (or fewer) toppings. Because there was no `if` guard, Sensei expected the “more toppings ⇒ higher price” relation to hold all the time, which triggered failures. Adding the `if` clause restricts the check to the cases where `conv[0]` truly has more toppings than `conv[1]`.

Here’s the corrected version:

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: True
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Make sure your profile’s `chatbot.output` includes the `toppings`, `size`, `drink`, and `price` fields so the rule can read them. Let me know if you want help double-checking those outputs! 🍕
