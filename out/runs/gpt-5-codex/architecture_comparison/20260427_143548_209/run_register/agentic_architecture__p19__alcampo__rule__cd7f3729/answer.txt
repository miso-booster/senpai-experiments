Here’s a profile-agnostic Sensei-check rule that verifies the assistant actually talks about current promotions by scanning its replies for promotion-related keywords:

```yaml
name: mentions_current_promotions
description: Ensures the assistant shares information about current promotions, deals, or offers.
active: true
conversations: 1
oracle: any(len(chatbot_returns(keyword)) > 0 for keyword in ['promotion','promotions','offer','offers','deal','deals'])
yields: "Assistant did not mention any promotions, deals, or special offers."
```

Because it only relies on the general `chatbot_returns` helper, this rule can be applied to any profile without depending on custom `chatbot.output` fields. I based the structure and helper usage on the guidance from **sensei-check-doc.md** (section on profile-agnostic rules and helper functions) and cross-checked the `chatbot_returns` pattern from the examples in **rules-examples.md**. Let me know if you’d like to tighten the keyword list or add additional context checks! 😊
