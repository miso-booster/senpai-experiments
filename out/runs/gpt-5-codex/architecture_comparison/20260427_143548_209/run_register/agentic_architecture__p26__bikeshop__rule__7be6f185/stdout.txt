Here’s what I found (based on the syntax rules in `sensei-check-doc.md`):

### What was off in the original rule
- `conversations: 2` makes Sensei expect a 2-dialog metamorphic rule, but the logic only references a single conversation (`conv[0]`). For a single check you should use `conversations: 1` and access the fields directly.
- `when:` and `if:` were a bit redundant: `when:` was comparing against 50 already, but the actual validation lived in `then`. I removed `when:` and kept the check inside `if`/`then`.
- `then:` must be a boolean expression. Returning the string `"The tune-up price is $50."` doesn’t evaluate to True/False, so I replaced it with a proper comparison.
- Added an `on-error` message so the failure output is helpful (optional but handy).

### Fixed rule
```yaml
name: check_tune_up_price
description: Checks if the tune-up price is equal to $50.
conversations: 1
if: tune_up_price is not None
then: tune_up_price == 50
on-error: f"Tune-up price was {tune_up_price}, expected 50."
```

Let me know if `tune_up_price` is actually a string like “$50”; in that case we can switch the comparison to `extract_float(tune_up_price) == 50`.
