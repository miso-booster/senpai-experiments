Hey there! 😊 In the context of Sensei Rules, an **oracle** is simply the condition that must be true for a conversation (or group of conversations) to pass the rule.

Think of it like a “truth check” written in a little snippet of Python logic. When you define an oracle inside a rule, Sensei-check evaluates that expression using the data extracted from the conversation(s). If the oracle is `True`, the rule passes; if it’s `False`, the rule fails and you get a helpful report about what went wrong.

Here’s a tiny example to make it real:

```yaml
name: chatbot_fills_all_slots
description: All conversation slots are filled
conversations: 1
oracle: data_collected() == True
yields: |
  f"Missing slots: {missing_slots()}"
```

- `oracle:` is the condition being checked (`data_collected() == True`).
- If the condition isn’t met, the `yields` message (optional but super helpful) tells you what failed—in this case, which slots are still missing.

So, in short: the oracle is the rule’s “pass/fail” test based on your conversation data. Let me know if you want to see how oracles change across single-convo vs. metamorphic (multi-convo) rules! 👀
