Hey there! Thanks for the question 😊

In Sensei profiles, most top-level sections are **optional unless you actually need to override the defaults** or drive a specific behaviour. Here’s a quick rundown so you can see what’s truly required vs. what you add “as needed”:

| Section | Mandatory? | When to include it |
|---------|------------|--------------------|
| `test_name` | ✅ **Yes** | Always give the profile a name so runs and logs are identifiable. |
| `user` | ✅ **Yes** | This is the heart of the profile (language, role, goals). You must define it. |
| `chatbot.output` | ✅ **Yes (in practice)** | It’s the contract with your rules. Without outputs, Sensei-check can’t validate anything. |

Everything else is optional:

- `llm`: Only include if you need to override the default model, temperature, or switch to speech mode.
- `user.context`: Optional extras—personality snippets or extra background. Skip it if you don’t need special flavour.
- `conversation`: Optional, but powerful. Use it when you want to control number of runs, goals completion style, interaction quirks, or cost caps. If you omit it, Sensei uses default behaviours (one conversation, natural flow, etc.).
- `chatbot.fallback` and `chatbot.is_starter`: Optional but recommended for better runs; still, not strictly mandatory.
- `chatbot.output` field descriptions and custom types: Descriptions are optional but nice for documentation; using custom types is optional unless you need structured extraction.

So, the bare minimum viable profile has: `test_name`, a `user` block with at least one goal, and a `chatbot.output` schema. Everything else is there to fine-tune the experience. Let me know if you’d like a minimal template or help deciding which optional bits to include! 🍕
