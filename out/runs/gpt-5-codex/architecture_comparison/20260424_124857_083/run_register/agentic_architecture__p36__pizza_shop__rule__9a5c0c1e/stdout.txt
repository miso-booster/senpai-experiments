Hey there! The problem comes from how metamorphic rules are structured in Sensei-check. Per the syntax described in **`sensei-check-doc.md`**, whenever you want to express a conditional relationship you should use an `if`/`then` pair. In your current rule the `then` clause fires for every pair of conversations that passes the `when` filter, even if the first conversation doesn’t actually have more toppings—so the rule fails whenever prices happen to go the other way.

Here’s the fixed version with the missing `if` clause restored (same shape as the example in `sensei-check-doc.md`):

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: True
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

Now the price comparison is only enforced when the first conversation truly has a longer toppings list, which makes the rule behave as intended. Let me know if you’d like to add tighter filters (e.g., matching pizza quantity) or an `on-error` message! 😊
