Sure thing! Here’s a rule-first check that ensures lactose-free items are reported as available once you wire up the corresponding profile fields.

```yaml
name: lactose_free_availability
description: Checks that lactose-free product requests confirm availability
active: true
conversations: 1
if: 'lactose-free' in dietary_tags
then: availability_confirmed is True
on-error: f"Lactose-free request for {requested_product} was not confirmed available."
```

**What this assumes for the future profile**

- `dietary_tags`: a list of strings extracted from the conversation; it should contain `"lactose-free"` when that requirement applies.  
- `availability_confirmed`: a boolean flag indicating whether the assistant explicitly confirmed availability.  
- `requested_product`: a string with the product name (used only in the error message).

Once you add a profile that exposes those outputs in `chatbot.output`, this rule will activate and flag any lactose-free requests that aren’t marked available.
