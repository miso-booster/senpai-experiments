In Sensei, a **metamorphic rule** is a Sensei-check rule that doesn’t just look at a single conversation in isolation—it compares **pairs or groups of conversations** and checks how the chatbot’s output should change (or stay consistent) when the inputs vary in specific ways.

Think of it like this: instead of asking “Did the bot answer correctly here?”, you ask “When we tweak the user’s request, did the bot’s answer adjust the way we expect?” For example, if two orders have the same size and drink but one has more toppings, a metamorphic rule could enforce that the price should be higher in the second case.

Why it matters:
- It helps catch subtle issues by focusing on **relationships** between scenarios rather than single outcomes.
- It’s especially handy when there isn’t a single “true” answer, but you can still define expected **patterns or invariants**.

These rules are written in YAML using the Sensei-check DSL, with sections like `when`, `if`, and `then` to express the comparison logic across conversations (`conv[0]`, `conv[1]`, etc.).
