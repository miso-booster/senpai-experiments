Hey there! 😊 The rule is failing because it no longer tells Sensei-check *when* to apply the price comparison. Without an `if` clause, the tool will compare **every** pair of conversations that match the `when:` filter—even those where `conv[0]` doesn’t actually have more toppings than `conv[1]`. In those cases, you end up checking something like “Does the pizza with fewer toppings cost more?”, which obviously shouldn’t be true, so the rule fails.

To fix it, just restore the `if:` condition that narrows the rule to the right scenario. Here’s the corrected version:

```yaml
name: more_toppings_cost_more
description: Adding more toppings to a custom pizza costs more
active: true
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if: len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

This way, the rule only checks price monotonicity when `conv[0]` truly has more toppings than `conv[1]`, which is the intent you had originally 💪. Let me know if you want to harden it further (e.g., checking same quantity too)!
