Hey there! 😊 Connectors are Sensei’s way of talking to your real chatbot API. Instead of writing custom code, you just describe the API in a YAML file, and Sensei uses that to send user messages and capture the bot’s replies during simulations or tests.

Here’s what you typically specify in a connector file:

- **name** *(optional)* — Just a human-friendly label for the connector.
- **base_url** *(required)* — The root URL of your chatbot’s API.
- **send_message** *(required)* — This section tells Sensei how to send each message:
  - **path** *(required)* — Endpoint path appended to the base URL (e.g., `/chat`).
  - **method** *(optional; default is `POST`)* — HTTP method such as POST or GET.
  - **headers** *(optional)* — Any HTTP headers you need (Content-Type, Authorization, etc.).
  - **payload_template** *(required)* — JSON payload structure. You place `{user_msg}` wherever Sensei should inject the simulator’s message. You can include other fields your API needs (session IDs, language, etc.).
- **response_path** *(required)* — A dot-separated path that tells Sensei how to extract the chatbot’s reply from the JSON response (for example, `response.text`, `choices.0.message.content`, etc.).

That’s it! With those fields in place, the connector can send simulated user messages to your bot and read the bot’s answers—no custom code necessary. Let me know if you’d like help tweaking one of your connector files or setting up a new one! 🚀
