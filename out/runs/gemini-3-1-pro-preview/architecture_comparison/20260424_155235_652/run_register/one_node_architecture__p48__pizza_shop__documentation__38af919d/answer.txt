When you're building a SENSEI Chat profile, you have a lot of power to customize the simulated user, but you don't have to configure *everything* if you don't want to. 

Here are the fields that are explicitly **optional** or have built-in defaults:

*   **The entire `llm` block**: You don't have to define this at all! If you leave it out, Sensei will simply apply its default settings (like a default model, temperature, and text format). You only need to add it if you want to override those defaults or use the `speech` mode.
*   **`conversation.max_cost`**: This is an optional setting to cap the LLM spending for the *entire* run 💸.
*   **`conversation.goal_style.max_cost`**: Similar to the above, but this optionally caps the spend *per-conversation*.
*   **`conversation.goal_style.all_answered.limit`**: If you are using the `all_answered` goal style, you don't have to specify a step limit. If omitted, Sensei applies a safety stop of 30 steps by default.
*   **`conversation.goal_style.all_answered.export`**: This is an optional boolean (`true` or `false`) that tells Sensei whether to export a verification dataframe.
*   **Personalities in `user.context`**: Including a personality file (like `- personality: personalities/calm-user.yml`) is totally optional. You can just write freeform context strings instead!
*   **Complex `interaction_style`s**: You don't have to use fancy styles like `make spelling mistakes` or `change language`. You can simply use `default`, and the user simulator will carry out the conversation in a standard, natural way.

**A quick tip from Senpai 👀:** While `chatbot.fallback` isn't strictly a "must-have-or-it-crashes" field, it is *highly* recommended that you include your bot's real fallback message there. It prevents the simulator and the chatbot from getting stuck in an endless loop of "I didn't understand that."
