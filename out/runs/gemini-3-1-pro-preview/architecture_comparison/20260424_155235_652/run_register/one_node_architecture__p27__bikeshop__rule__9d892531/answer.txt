Para comprobar que el asistente no acepta la misma fecha dos veces (lo que se conoce como evitar reservas duplicadas o *double-booking*), lo ideal es utilizar una **regla metamórfica de 2 conversaciones**. 

Basándome en el perfil `appointment.yml` que tienes en tu proyecto, he diseñado una regla que utiliza las variables de entrada (`ap_date` y `hour`) y las variables de salida que extrae el bot (`confirmed_date`). 

La lógica es sencilla: si dos conversaciones intentan reservar exactamente para la misma fecha y hora, y la primera tiene éxito, la segunda debe ser denegada (es decir, su fecha confirmada debe quedar vacía).

Aquí tienes la regla lista para usar:

```yaml
name: prevent_double_booking
description: Si dos conversaciones intentan reservar la misma fecha y hora, el asistente debe denegar la segunda.
conversations: 2
when: conv[0].ap_date == conv[1].ap_date and conv[0].hour == conv[1].hour
if: conv[0].confirmed_date is not None
then: conv[1].confirmed_date is None
```

### 👀 ¿Cómo funciona esta regla?

1. **`conversations: 2`**: Le dice a Sensei-check que vamos a comparar las conversaciones en pares.
2. **`when`**: Filtra y selecciona solo aquellos pares de conversaciones donde el usuario pidió exactamente la misma fecha (`ap_date`) y la misma hora (`hour`).
3. **`if`**: Establece la condición inicial. En este caso, verificamos si la primera conversación (`conv[0]`) logró confirmar la cita exitosamente (el campo `confirmed_date` no está vacío).
4. **`then`**: Es la aserción final. Si la primera se confirmó, exigimos que la segunda conversación (`conv[1]`) **no** tenga una fecha confirmada (`is None`), lo que significa que el asistente le negó la reserva al detectar que ya estaba ocupada.

Esta es una forma genial de probar si tu chatbot mantiene el estado y respeta la disponibilidad real del negocio.
