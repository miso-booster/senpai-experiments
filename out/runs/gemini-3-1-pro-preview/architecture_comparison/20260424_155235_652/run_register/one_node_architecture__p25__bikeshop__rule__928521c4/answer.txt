Since you want to check the exact values returned in a single conversation, we can create a **single-conversation oracle** rule. We will use the fields exactly as you defined them in your profile's `chatbot.output` (`opening_and_closing`, `tune_up`, `seat_price`, and `tire`). 

To make the rule robust against slight variations in the chatbot's text (like "The price is $50" vs "50 USD"), we can use the `extract_float()` helper for the prices. For the opening hours, the `semantic_content()` helper is perfect because it uses an LLM to check if the meaning matches "10 to 20", regardless of how the bot phrased it!

Here is the rule you can use:

```yaml
name: verify_shop_qa_answers
description: Verifies the exact prices for tune-up, seat, and tire, and checks the opening hours.
conversations: 1
active: true
oracle: |
  semantic_content(opening_and_closing, '10 to 20') and extract_float(tune_up) == 50 and extract_float(seat_price) == 20 and extract_float(tire) == 20
yields: f"One or more answers were incorrect. Hours: {opening_and_closing}, Tune-up: {tune_up}, Seat: {seat_price}, Tire: {tire}"
```

### How this works:
* **`conversations: 1`**: Tells Sensei-check to evaluate this rule on each conversation individually.
* **`semantic_content(opening_and_closing, '10 to 20')`**: Checks if the text extracted for the hours semantically means "10 to 20" (e.g., "We are open from 10 AM to 8 PM" would pass!).
* **`extract_float(...) == X`**: Safely pulls the first number out of the extracted price strings and compares it to your expected values.
* **`yields`**: If the rule fails, this provides a helpful error message showing exactly what the chatbot returned so you can easily debug it. 👀
