Hello there! 😊 I'd be happy to explain what a metamorphic rule is in the world of Sensei!

In traditional testing, you usually check if one specific input gives one exact output (like a traditional oracle). But with chatbots and AI, exact answers can be unpredictable! That's where **metamorphic testing** comes to the rescue. 🦸‍♂️

In Sensei-check, a **metamorphic rule** evaluates *several* conversations at once by comparing pairs or tuples of them. Instead of checking for an absolute answer, it checks the **relationship** between the conversations when the inputs change. 

**A simple everyday analogy 🍕:**
Imagine you are ordering a custom pizza. You might not know the *exact* final price the chatbot will quote you. However, you do know a logical rule: **If two orders have the exact same size and drinks, but one has MORE toppings, that one must cost MORE.** 

In Sensei, you can write a metamorphic rule to test exactly that! You tell Sensei to:
1. Filter for comparable conversations (e.g., same pizza size and drinks) using a `when` clause.
2. Look at the change in inputs (e.g., one has more toppings) using an `if` clause.
3. Assert the expected change in the output (e.g., the price goes up) using a `then` clause.

Here is what that looks like in YAML:
```yaml
name: toppings_monotonicity
description: Adding more toppings to a custom pizza costs more (same size/drink/qty)
conversations: 2
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink
if:   len(conv[0].toppings) > len(conv[1].toppings)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

By checking these *relations* rather than exact answers, metamorphic rules help you find bugs and inconsistencies in your chatbot without needing to know the exact perfect response every single time. 💡
