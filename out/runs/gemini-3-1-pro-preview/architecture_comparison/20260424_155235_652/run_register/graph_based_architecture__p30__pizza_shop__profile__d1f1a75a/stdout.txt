A rude, impatient customer who wants their pizza *yesterday* sounds like a fantastic stress-test for your chatbot. 🍕💨 

To make this work, we will set up the `user.role` and `user.context` to reflect that grumpy, rushed personality. Then, we'll define **4 goals** using **4 variables** (`size`, `topping`, `drink_qty`, and `drink_type`). By assigning the `pairwise()` function to two of those variables, Sensei will intelligently mix and match them to test different pairs without creating a massive, exhaustive list of every single combination. Finally, we'll set `conversation.number: combinations` so the run length is perfectly matched to that pairwise matrix!

Here is the complete, ready-to-use YAML profile for your test:

```yaml
test_name: "rude_fast_pizza_order"

llm:
  temperature: 0.7
  model: gpt-4o
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: >
    You are a very rude and impatient customer ordering from a pizza shop. 
    You want your food immediately and have zero tolerance for delays, pleasantries, or small talk.
  context:
    - "You are in a huge rush and easily annoyed."
    - "You demand quick answers and fast service."
  goals:
    - "I want a {{size}} pizza and I want it right now!"
    - "Throw some {{topping}} on it, and don't mess it up."
    - "I also need {{drink_qty}} cans of {{drink_type}}. Hurry up!"
    - "Tell me exactly how many minutes until it's ready and the total price. Stop wasting my time."
    - size:
        function: pairwise()
        type: string
        data: [small, medium, large, extra large]
    - topping:
        function: pairwise()
        type: string
        data: [pepperoni, mushrooms, extra cheese, jalapenos]
    - drink_qty:
        function: random()
        type: int
        data: [1, 2, 3, 4]
    - drink_type:
        function: random()
        type: string
        data: [cola, diet cola, sprite, water]

chatbot:
  is_starter: false
  fallback: "I'm sorry, I didn't catch that. Could you repeat your order?"
  output:
    - total_price:
        type: currency
        description: "The total cost of the order."
    - estimated_time:
        type: time("hh:mm")
        description: "The estimated time until the order is ready."
    - order_id:
        type: string
        description: "The unique order identifier."

conversation:
  number: combinations  # This automatically uses the matrix generated by the two pairwise() variables!
  goal_style:
    all_answered:
      export: true
      limit: 15
  interaction_style:
    - default
```

### 💡 A quick breakdown of what's happening here:
* **The Persona:** The `role` and `context` give the LLM strict instructions to act hurried and rude.
* **The Variables:** `size` and `topping` use `pairwise()`. Sensei will calculate the most efficient way to pair every size with every topping at least once. Meanwhile, `drink_qty` and `drink_type` use `random()`, so they'll just pick a random option for each of those generated conversations.
* **The Conversation Number:** Because we used `number: combinations`, Sensei will automatically run exactly as many conversations as needed to satisfy the `pairwise()` matrix. No need to guess a number! 👀
