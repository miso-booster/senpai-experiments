Since you want to verify that the chatbot successfully collected specific pieces of information in a single chat, we will create a **single-conversation rule** (also known as a traditional oracle). 

In Sensei-check, the fields you define in your profile's `chatbot.output` automatically become variables you can use directly in your rule's `oracle` expression. 

Here is the YAML rule you can use. Just copy and paste this into a new file in your `rules` folder:

```yaml
name: cau_contact_info_provided
description: Ensures Ada UAM provides the complete CAU contact information (email, phone, and physical address).
conversations: 1
oracle: contact_email is not None and contact_phone is not None and physical_address is not None
```

### 🧠 How it works:
* **`conversations: 1`**: Tells Sensei-check to evaluate this rule on each conversation individually, rather than comparing multiple conversations together.
* **`oracle`**: This is the condition that must be `True` for the test to pass. We are simply checking that none of your three required fields (`contact_email`, `contact_phone`, and `physical_address`) are empty (`None`).

### ✨ Senpai's Pro-Tip!
If those three fields are the *only* outputs defined in your profile, you can make the rule even shorter by using one of Sensei-check's built-in helpers called `data_collected()`. This helper automatically checks that all extracted outputs are non-null! 

Here is what that alternative looks like:

```yaml
name: cau_contact_info_provided_alt
description: Ensures all required CAU contact slots were successfully filled.
conversations: 1
oracle: data_collected() is True
```
