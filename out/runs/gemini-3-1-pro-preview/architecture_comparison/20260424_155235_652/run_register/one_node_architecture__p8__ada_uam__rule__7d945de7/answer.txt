However, there is a **logical trap** in your current rule: **the `when` clause and the `oracle` clause are exactly the same.** 

In Sensei-check, the `when` clause acts as a *filter* to select which conversations to evaluate. By putting the correct answers in the `when` clause, you are telling Sensei to *only* test conversations where the bot already gave the correct information. If the bot gives the wrong email or phone number, the rule will just ignore that conversation instead of failing it! 

Also, since this is a single-conversation rule (`conversations: 1`), you don't need to use the `conv[0].` prefix. You can reference the variables directly to keep it clean.

Here is the fixed version. I removed the `when` clause so that it evaluates the extracted outputs directly:

```yaml
name: check_cau_information
description: Checks that the CAU provided correct information about contact details.
conversations: 1
oracle: contact_email == 'cau@uam.es' and contact_phone == '91 497 4029' and physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
```

### How this works now:
* **No `when` filter:** The rule will evaluate every conversation generated by the profile.
* **The `oracle`:** It directly checks if the extracted `contact_email`, `contact_phone`, and `physical_address` match your expected strings. If the bot hallucinates a different phone number, the oracle will return `False`, and Sensei-check will correctly flag it as a failure! 🚨
