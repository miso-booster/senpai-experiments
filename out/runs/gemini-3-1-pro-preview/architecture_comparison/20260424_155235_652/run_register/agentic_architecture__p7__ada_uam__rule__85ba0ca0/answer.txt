Here is the SENSEI rule to verify that the chatbot provides the correct CAU information. 

Since the outputs are strings and might have slight formatting variations (like spaces in the phone number or different abbreviations in the address), we can use the built-in `semantic_content` helper function. This function uses an LLM check to ensure the extracted values semantically match the expected information, making the rule robust against minor text differences.

```yaml
name: correct_cau_information
description: Checks that the chatbot provided the correct CAU location, email, and telephone.
conversations: 1
active: true
oracle: |
  semantic_content(contact_email, 'cau@uam.es') and semantic_content(contact_phone, '91 497 4029') and semantic_content(physical_address, 'Higher Polytechnic School, C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107')
```

### How this rule works:
* **`conversations: 1`**: It's a single-conversation rule (an oracle) that evaluates each conversation individually.
* **`oracle`**: It evaluates a boolean condition. If all three fields match the expected information, the rule passes.
* **`semantic_content(field, 'expected value')`**: It checks the variables `contact_email`, `contact_phone`, and `physical_address` (which map directly to your profile's `chatbot.output` fields) against the exact CAU details you provided.
