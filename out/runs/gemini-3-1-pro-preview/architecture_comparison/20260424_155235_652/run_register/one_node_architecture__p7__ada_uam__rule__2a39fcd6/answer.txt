Here is a rule that checks if the chatbot provided the correct CAU information! 

Since the chatbot might extract the address or phone number with slight formatting differences (like missing spaces in the phone number or translating the address to Spanish), I recommend using the `semantic_content()` helper. This uses an LLM under the hood to verify that the extracted text means the same thing as your ground truth, making your test much more robust.

Here is the YAML for your rule:

```yaml
name: correct_cau_information
description: Verifies that the chatbot provides the correct CAU contact information (email, phone, and physical address).
conversations: 1
active: true
oracle: |
  semantic_content(contact_email, 'cau@uam.es') and 
  semantic_content(contact_phone, '91 497 4029') and 
  semantic_content(physical_address, 'Higher Polytechnic School, C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107')
yields: f"Incorrect CAU info. Got Email: {contact_email}, Phone: {contact_phone}, Address: {physical_address}"
```

### How it works:
* **`conversations: 1`**: It evaluates each conversation individually.
* **`semantic_content(...)`**: It checks if the extracted `chatbot.output` fields match the meaning of your expected values, ignoring minor typos or formatting differences.
* **`yields`**: If the rule fails, it will print out exactly what the chatbot extracted so you can easily debug what went wrong.

You can save this as a `.yaml` file (for example, `cau_info_check.yaml`) inside your project's `rules/` folder! Let me know if you need any adjustments. 😊
