In software testing, an **oracle** is basically the mechanism or rule that decides whether a test has passed or failed. You can think of it as your "source of truth"!

In the context of **Sensei-check**, an oracle is the specific condition (written as a Python expression) that evaluates the conversations generated by your SENSEI Chat profiles. It looks at the outputs your chatbot produced and returns `True` (pass) or `False` (fail).

There are generally two ways we think about oracles in Sensei:

1. **Traditional Oracles (Single Conversation):** These check absolute correctness for a single chat. For example, "Did the bot return an order ID?" or "Is the price of this small pizza at least $10?"
2. **Metamorphic Oracles (Multiple Conversations):** Because chatbots are unpredictable, it's often hard to know the *exact* absolute answer. Instead, we use metamorphic testing to check the *relationship* between two or more conversations. For example, "If I order the exact same pizza but add more toppings, the price should go up." (In Sensei rules, we often write these using `if`/`then` statements, but they serve the same purpose as an oracle!).

Here is a quick example of how the `oracle` keyword is used in a Sensei rule to check a single conversation:

```yaml
name: small_base_price_floor
description: Small pizzas should cost at least $10
conversations: 1
when: size == 'small'
oracle: extract_float(price) >= 10 and currency(price) == 'USD'
```

In this rule, the `oracle` is the expression `extract_float(price) >= 10 and currency(price) == 'USD'`. If that statement is true, the test passes! ✨
