Here is a complete SENSEI profile tailored for your bikeshop testing scenario. 

I've set it up so the simulated user will ask to change both the seat and the handlebar grips, using variables to randomly select different types of seats and grip colors to ensure your chatbot can handle various requests.

```yaml
test_name: "bikeshop_bike_setup"

llm:
  temperature: 0.7
  model: gpt-4o
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: >
    You are a customer who recently bought a new bike and wants to get it set up at a local bikeshop.
    You want to tailor the bike to your liking by changing the seat and the handlebar grips.
  context:
    - "You want to know the total cost for the new parts and the labor."
    - "You want to know how long the setup will take."
    - "You are excited about your new bike and want to make sure it is comfortable."
  goals:
    - "Ask to change the seat to a {{seat_type}} seat."
    - "Ask to change the handlebar grips to {{grip_color}} grips."
    - seat_type:
        function: random()
        type: string
        data: [gel, leather, sporty, wide]
    - grip_color:
        function: random()
        type: string
        data: [black, red, blue, neon green]

chatbot:
  is_starter: false
  fallback: "I'm sorry, I didn't quite catch that. Could you repeat?"
  output:
    - seat_type_requested:
        type: string
        description: "The type of seat the user wants to install"
    - grip_color_requested:
        type: string
        description: "The color of the handlebar grips the user wants"
    - estimated_cost:
        type: float
        description: "The estimated cost for the parts and labor"
    - estimated_time:
        type: string
        description: "The estimated time to complete the setup"

conversation:
  number: 3
  goal_style:
    all_answered:
      limit: 15
  interaction_style:
    - default
```

### 🚲 How this profile works:

1. **User Role & Context**: The `role` gives the simulator its main persona (a happy new bike owner), while the `context` adds constraints like asking for the price and the estimated time.
2. **Goals & Variables**: The `goals` section uses `{{seat_type}}` and `{{grip_color}}` variables. The `random()` function ensures that across the 3 conversations (`conversation.number: 3`), the simulator will pick different combinations (e.g., a "gel" seat with "blue" grips, or a "sporty" seat with "black" grips).
3. **Chatbot Output**: The `chatbot.output` section defines the schema of information we expect the chatbot to successfully gather and provide by the end of the conversation. This is extremely useful if you later want to write SENSEI RULES to validate that the chatbot correctly quoted a price (`estimated_cost`) or understood the requested items (`seat_type_requested`).
4. **Conversation Controls**: The `goal_style` is set to `all_answered` with a limit of 15 turns, meaning the simulator will naturally end the conversation once all its goals are met or if it hits the 15-turn safety limit.

Let me know if you'd like to adjust the seat types, colors, or add any other customisations to the bike! 😊
