¡Hola! Qué gusto saludarte 😊. ¡Claro que sí! Me encanta esa idea; es un caso de prueba buenísimo para asegurarnos de que el asistente está prestando atención y no permite reservas o datos duplicados. 🕵️‍♀️

Para lograr esto en **SENSEI Check**, podemos crear una regla de **una sola conversación** (un oráculo tradicional). Como estamos evaluando el comportamiento y la intención dentro del diálogo, la herramienta perfecta para esto es nuestra función de ayuda `utterance_index(who, what)`. Esta función es genial porque usa inteligencia artificial por debajo para buscar en qué turno de la conversación alguien expresó una idea específica.

Aquí tienes la regla lista para usar:

```yaml
name: rechazo_fecha_duplicada
description: Si el usuario pide la misma fecha dos veces, el asistente debe rechazar la segunda petición.
conversations: 1
if:   utterance_index('user', 'pide la misma fecha por segunda vez') > 0
then: utterance_index('assistant', 'rechaza la fecha, dice que no es válida o que ya está ocupada') > 0
```

### 🤓 ¿Cómo funciona esta regla?
1. **`conversations: 1`**: Le decimos a Sensei-check que evalúe las conversaciones de una en una.
2. **`if` (Condición)**: Primero verificamos que, efectivamente, el usuario simulado haya intentado pedir la misma fecha dos veces. Si `utterance_index` devuelve un número mayor a 0, significa que encontró ese momento en el diálogo.
3. **`then` (Lo que debe pasar)**: Si se cumple lo anterior, exigimos que el asistente reaccione rechazando la fecha o indicando que no se puede.

### 💡 El consejo de Senpai (Conexión con SENSEI Profiles)
Recuerda que las reglas de SENSEI Check trabajan en equipo con los **SENSEI Profiles**. Para que esta regla brille y realmente se ponga a prueba, asegúrate de que tu perfil de SENSEI Chat tenga un objetivo (goal) claro donde el usuario simulado sea un poco terco e intente pedir la misma fecha dos veces a propósito. ¡Así forzaremos al asistente a demostrar que sabe decir que no! 🛡️
