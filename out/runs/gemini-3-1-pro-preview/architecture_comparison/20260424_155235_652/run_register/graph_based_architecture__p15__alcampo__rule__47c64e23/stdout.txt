Because you are just checking if the chatbot successfully extracted/provided information based on a specific request, you don't actually need to compare two conversations together (which is what `conversations: 2` does). 

It is usually much cleaner to write this as a **1-conversation rule** (a traditional oracle). Here is how I would write it using the `if/then` format, which reads very naturally:

```yaml
name: customer_service_contact_info
description: Ensure the chatbot provides correct contact options and information for customer service inquiries.
conversations: 1

then: contact_options is not None or customer_service_number is not None
```

*(Or, you could even split it into two separate 1-conversation rules: one for "contact options" and one for "customer service number" to be super precise!)*

**One last reminder:** Make sure that `user_request`, `contact_options`, and `customer_service_number` are actual fields defined in your SENSEI Chat profile's `chatbot.output` (or input selections). Sensei-check relies on those exact names to pull the data! 👀
