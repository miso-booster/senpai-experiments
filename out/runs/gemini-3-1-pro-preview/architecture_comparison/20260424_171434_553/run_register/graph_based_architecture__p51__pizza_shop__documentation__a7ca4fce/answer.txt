In the Chatbot Dojo, **Custom YAML Connectors** act as a friendly bridge between Sensei and your chatbot's API. They allow you to connect and talk to any chatbot API *without writing a single line of code*! 🚀 You simply create a YAML configuration file that describes exactly how to send messages to your bot and how to read its replies.

Here are the fields you can use to build a connector, along with what they do:

### 📝 Connector Fields

*   **`name`** *(Optional)*: A friendly name for your chatbot (e.g., "My Awesome Bot").
*   **`base_url`** *(Required)*: The main URL of your chatbot's API (e.g., `https://api.mychatbot.com`).
*   **`send_message.path`** *(Required)*: The specific endpoint path where messages are sent. This gets added to the end of your `base_url` (e.g., `/chat/send`).
*   **`send_message.method`** *(Optional)*: The HTTP method used to send the request, like `POST`, `GET`, `PUT`, or `DELETE`. If you leave this out, it defaults to `POST`.
*   **`send_message.headers`** *(Optional)*: Any custom headers your API needs to work, such as `Authorization` tokens or `Content-Type`.
*   **`send_message.payload_template`** *(Required)*: The JSON structure your API expects. This is where the magic happens! You use the special placeholder **`{user_msg}`** to tell the connector exactly where to insert the simulated user's message.
*   **`response_path`** *(Required)*: A dot-separated path that tells Sensei exactly where to find the bot's reply inside the JSON response. For example, if the API returns `{"data": {"text": "Hello!"}}`, your response path would be `data.text`.

---

### 💡 A Quick Example
Here is what a simple connector looks like for a basic Echo Bot:

```yaml
name: "Echo Bot"
base_url: "https://postman-echo.com"
send_message:
  path: "/post"
  method: "POST"
  payload_template:
    message: "{user_msg}"
response_path: "json.message"
```
