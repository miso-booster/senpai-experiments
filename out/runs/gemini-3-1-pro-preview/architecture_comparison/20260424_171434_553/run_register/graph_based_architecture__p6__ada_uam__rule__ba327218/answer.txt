Since you want to verify that the chatbot successfully extracted specific pieces of information in a single chat, we will create a **single-conversation rule** (also known as a traditional oracle). 

In Sensei-check, the fields you defined in your profile's `chatbot.output` (`contact_email`, `contact_phone`, and `physical_address`) become variables you can directly check in your rule. 

Here are two great ways to write this rule. You can choose the one you like best! ✨

### Option 1: Explicitly checking each field
This rule explicitly checks that none of your three specific fields are empty. It's very readable and great if your profile has other optional outputs that you *don't* want to check here.

```yaml
name: cau_contact_info_complete
description: Verifies that Ada UAM provided the CAU phone number, email, and physical address.
conversations: 1
oracle: contact_email is not None and contact_phone is not None and physical_address is not None
```

### Option 2: Using Sensei-check built-in helpers (Senpai's favorite! 🌟)
Sensei-check has a handy built-in helper called `missing_slots()` that returns a list of any `chatbot.output` fields that are still empty. If we expect the chatbot to collect *all* the data defined in the profile, we can just assert that the missing slots list is empty!

```yaml
name: cau_contact_info_complete
description: Verifies that Ada UAM provided all required CAU contact information.
conversations: 1
oracle: missing_slots() == []
```
*(Note: You could also use the `data_collected() is True` helper, which does exactly the same thing!)*

### How to use it:
Just save your chosen YAML block into a `.yaml` file inside your project's `rules/` folder. When Sensei-check runs, it will look at the conversations generated by your Ada UAM profile and flag any where the chatbot forgot to give the user the complete CAU contact info. 🕵️‍♀️
