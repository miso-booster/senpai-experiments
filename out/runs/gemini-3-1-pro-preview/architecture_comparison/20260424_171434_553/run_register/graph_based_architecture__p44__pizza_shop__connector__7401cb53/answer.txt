Como ambos chatbots están hechos con la tecnología de 1millionbot, la estructura es prácticamente idéntica. Lo único que tenemos que hacer es actualizar las credenciales de autorización y los identificadores específicos (como el ID del bot, la conversación y el usuario) basándonos en la petición HTTP que me has pasado.

Además, he añadido las cabeceras `Origin` y `Referer` por si el servidor del Ayuntamiento las necesita por seguridad (es una buena práctica 👀).

Aquí tienes tu nuevo **SENSEI CONNECTOR** listo para usar:

```yaml
name: "Ayuntamiento de Morón"
base_url: "https://api.1millionbot.com"
send_message:
  path: "/api/public/messages"
  method: "POST"
  headers:
    Content-Type: "application/json"
    Authorization: "65ca19e7dbbb4e26cbeadf28"
    Origin: "https://www.morondelafrontera.es"
    Referer: "https://www.morondelafrontera.es/"
  payload_template:
    conversation: "67ea76f4e213b2dcbc146e2b"
    sender_type: "User"
    sender: "67ea76f40643a3dd27e59411"
    bot: "65ca19e7dbbb4e26cbeadf24"
    language: "es"
    url: "https://www.morondelafrontera.es/"
    message:
      text: "{user_msg}"
response_path: "response.0.text"
```

### 💡 ¿Qué ha cambiado?
1. **Autorización:** Hemos puesto el nuevo token `65ca19e7dbbb4e26cbeadf28` en los `headers`.
2. **Payload:** Hemos actualizado los campos `conversation`, `sender`, `bot` y `url` con los datos del Gallo de Morón.
3. **Mensaje del usuario:** Hemos sustituido el `"hola"` estático de tu petición por nuestra variable mágica `{user_msg}` para que SENSEI pueda enviar cualquier texto dinámicamente.
4. **Ruta de respuesta:** Se mantiene igual (`response.0.text`) porque, como vemos en el JSON de respuesta que me enviaste, el texto del bot sigue estando dentro del primer elemento (`0`) de la lista `response`.

Solo tienes que guardar esto en un nuevo archivo `.yml` (por ejemplo, `moron-frontera.yml`) dentro de tu carpeta de conectores (`/home/ivan/miso/automatizacion/graph/users/user_1/connectors/`) y estará listo para la acción. 🚀
