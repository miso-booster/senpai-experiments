Para este caso, lo ideal es crear una regla de **una sola conversación** (`conversations: 1`) y aprovechar la función de ayuda `utterance_index`. Esta función utiliza un LLM por debajo para buscar en qué momento exacto de la conversación el asistente menciona un concepto específico (en este caso, rechazar la fecha).

Aquí tienes el código YAML listo para usar en tu proyecto:

```yaml
name: rechazo_fecha_duplicada
description: Si el usuario propone la misma fecha dos veces en la conversación, el asistente debe rechazar la segunda.
conversations: 1
oracle: utterance_index('assistant', 'niega o rechaza la fecha por estar duplicada') > 0
```

### 💡 Un consejo de Senpai sobre tu Perfil (SENSEI Chat)

Recuerda que las reglas de Sensei-check trabajan en equipo con los **Perfiles de SENSEI Chat**. Para que esta regla tenga sentido y se evalúe correctamente, necesitas asegurarte de que el perfil que genera la conversación esté diseñado para provocar esta situación. 

Es decir, el comportamiento del usuario simulado en tu perfil debe incluir explícitamente la instrucción de **repetir la misma fecha dos veces**. Si el usuario simulado nunca repite la fecha, el asistente nunca la rechazará y la regla fallará.
