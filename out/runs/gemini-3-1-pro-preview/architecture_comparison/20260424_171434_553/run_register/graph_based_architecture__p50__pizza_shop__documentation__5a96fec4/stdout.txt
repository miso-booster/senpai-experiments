In the world of software testing—and specifically in **SENSEI RULES**—an **oracle** is basically your "source of truth" or the specific condition you use to decide if a test passed or failed. 

Think of it like a teacher's grading rubric. The chatbot takes a test (has a conversation), and the oracle is the rule that checks the chatbot's answers to say, *"Yes, this is correct!"* or *"No, this failed."*

### How it works in Sensei-check
In your Sensei-check YAML files, `oracle` is an actual keyword. You use it to write a Python expression that evaluates to either `True` or `False`. If it evaluates to `True`, the conversation passes the rule!

Oracles are most commonly used for **single-conversation rules** (traditional testing) to check baseline sanity. For example, you might want to check if the chatbot always answers in English, or if it successfully collected all the necessary data.

Here is a quick example of how an oracle looks in a rule:

```yaml
name: answers_in_english
description: The chatbot must answer in English
conversations: 1
oracle: language(chatbot_phrases) == 'ENG'
```

Or a global oracle that checks all conversations at once to make sure every order ID is unique:

```yaml
name: unique_order_ids
description: Every conversation has a unique order_id
conversations: all
oracle: is_unique('order_id')
```

### Oracle vs. Metamorphic Rules 🕵️‍♂️
While an `oracle` is perfect for checking absolute truths in a single conversation (like *"Is the price greater than $10?"*), Sensei-check also specializes in **metamorphic testing**. For metamorphic rules, instead of using a single `oracle`, you usually compare *multiple* conversations using an `if` and `then` structure (like *"If I add more toppings, then the price should go up"*).
