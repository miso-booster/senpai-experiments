Since we don't have a profile yet, I'll invent a couple of variables for this rule: `user_requested_lactose_free` (a boolean to check if the user actually asked for them) and `lactose_free_items` (a list of products the chatbot should return). 

When you build your SENSEI Chat profile later, just remember to add these exact variable names to your `chatbot.output` so the rule can read them properly! 👀

Here is your rule:

```yaml
name: lactose_free_availability_check
description: If the user asks for lactose-free products, the chatbot must provide a list of available items.
conversations: 1
active: true
if: user_requested_lactose_free == True
then: lactose_free_items is not None and len(lactose_free_items) > 0
yields: f"Expected a list of lactose-free items, but got: {lactose_free_items}"
```

### How this works:
* **`conversations: 1`**: This is a standard oracle rule that checks a single conversation at a time.
* **`if`**: This acts as our precondition. We only care about checking the output if the user actually requested lactose-free products.
* **`then`**: This is the assertion. It ensures that the chatbot successfully extracted a list of items and that the list isn't empty.
