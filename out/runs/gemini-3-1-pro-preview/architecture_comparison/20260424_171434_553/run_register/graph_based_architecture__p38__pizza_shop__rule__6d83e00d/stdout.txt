Since we only need to look at one conversation at a time to verify if the chatbot gave us the order ID, we will create what we call a **single-conversation oracle**. 

Here is exactly how you can write it in YAML:

```yaml
name: order_id_provided
description: The chatbot must successfully provide an order_id.
conversations: 1
oracle: order_id is not None
```

### 🧐 A quick breakdown of how it works:
* **`conversations: 1`**: This tells Sensei-check to evaluate the rule on each conversation individually, rather than comparing multiple conversations together.
* **`oracle: order_id is not None`**: This is the condition that must be true! It simply checks that the `order_id` variable has been filled with some data. 

Alternatively, you can also use the built-in `data_output` dictionary or the `missing_slots()` helper to check for it. Here is another valid way to write the exact same rule:

```yaml
name: order_id_in_output
description: Ensures the order_id is present in the extracted data.
conversations: 1
oracle: "'order_id' in data_output"
```

### 💡 Senpai's Pro-Tip:
For this rule to work perfectly, remember that your **SENSEI Chat profile** needs to have `order_id` explicitly defined in its `chatbot.output` section. Sensei-check pulls the variables directly from there!
