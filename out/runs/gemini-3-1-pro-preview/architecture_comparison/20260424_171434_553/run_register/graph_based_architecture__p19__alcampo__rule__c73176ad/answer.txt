Since you are designing this rule *before* having a specific profile, you are using what we call **Rule-first design**. This means we can invent a variable name now, but you'll just need to remember to add it to your future SENSEI Chat profile's `chatbot.output` later so they can talk to each other! 🤝

I'll give you two fun ways to do this: one using a custom variable, and another using a built-in helper that doesn't even need a custom variable. 👀

### Option 1: Using a custom variable (Rule-first design)
Let's invent a variable called `promotions_details`. We will check that the chatbot actually extracted some text for it.

```yaml
name: provided_promotions_info
description: Checks if the chatbot provided information about current promotions. Requires a 'promotions_details' field in the profile.
conversations: 1
oracle: promotions_details is not None and len(promotions_details) > 0
```
*Note: When you eventually create your profile, just make sure to add `promotions_details` to your `chatbot.output`!* 📝

### Option 2: Using the `utterance_index` helper (No custom variables needed! ✨)
If you just want to check if the assistant *talked* about promotions without extracting a specific variable, you can use our handy `utterance_index` helper. It uses an LLM under the hood to check the conversation history!

```yaml
name: mentioned_promotions
description: Checks if the assistant mentioned current promotions or discounts during the chat.
conversations: 1
oracle: utterance_index('assistant', 'current promotions or discounts') > 0
```

Both of these are single-conversation rules (oracles) that will perfectly do the trick.
