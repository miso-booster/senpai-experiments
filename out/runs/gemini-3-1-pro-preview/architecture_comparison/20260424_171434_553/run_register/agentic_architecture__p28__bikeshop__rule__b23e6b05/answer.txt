Based on the SENSEI rules documentation (`sensei-check-doc.md` and `rules-examples.md`), there is a built-in helper function specifically designed for this called `responds_in_same_language()`. 

Because this rule relies on a generic helper rather than specific extracted fields, it is a **general (profile-agnostic) rule**. This means it will work across any of your profiles without needing you to define specific language slots in your `chatbot.output`.

Here is the YAML for the rule:

```yaml
name: chatbot_responds_in_same_language
description: The chatbot responds in the same language as the user
conversations: 1
active: true
oracle: responds_in_same_language()
on-error: "The chatbot did not respond in the same language as the user."
```

### How it works:
* **`conversations: 1`**: This is a single-conversation oracle rule. It checks each conversation individually.
* **`oracle: responds_in_same_language()`**: This uses the built-in LLM-backed helper to analyze the dialogue and verify that the assistant matches the user's language.
* **`on-error`**: If the rule fails, it will output this helpful message. (Note: In older examples this was sometimes called `yields`, but `on-error` is the standard way to provide a helpful failure message).

You can save this as a `.yaml` file in your `rules` directory, and SENSEI will automatically start checking your chatbot's language consistency! Let me know if you need help applying this to your project.
