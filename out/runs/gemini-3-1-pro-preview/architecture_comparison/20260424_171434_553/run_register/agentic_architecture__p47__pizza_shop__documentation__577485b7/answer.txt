In the context of Sensei (specifically **Sensei-check**), a **metamorphic rule** is a type of test that checks the *relationship* between two or more conversations, rather than looking at just one conversation in isolation. 

Instead of checking if an absolute answer is correct (which is hard to do when you don't know the exact expected output—a challenge known as the "oracle problem"), metamorphic rules assert how the chatbot's outputs should change (or stay the same) when the inputs change in a specific way.

Here is a breakdown of how they work based on the `sensei-check-doc.md` documentation:

### 1. The Core Concept
Imagine you are testing a pizza-ordering chatbot. You might not know exactly how much a custom pizza will cost, but you *do* know a logical rule: **If two people order the exact same size and drinks, but one person adds more toppings, their pizza should cost more.** 

A metamorphic rule lets you test this exact logic by comparing pairs (or tuples) of generated conversations!

### 2. How it looks in YAML
Metamorphic rules require setting `conversations` to 2 or more. They typically use a `when` filter to find comparable conversations, and an `if`/`then` statement to define the relationship. You access the different conversations using the `conv` array (e.g., `conv[0]` and `conv[1]`).

Here is a classic example from the docs checking **Price Monotonicity**:

```yaml
name: toppings_monotonicity
description: Adding more toppings to a custom pizza costs more (same size/drink/qty)
conversations: 2
# 'when' filters for two conversations that are identical in size, drink, and quantity
when: conv[0].size == conv[1].size and conv[0].drink == conv[1].drink and conv[0].number == conv[1].number
# 'if' states the change in input (one has more toppings)
if:   len(conv[0].toppings) > len(conv[1].toppings)
# 'then' asserts the expected change in output (the price must be higher)
then: extract_float(conv[0].price) > extract_float(conv[1].price)
```

### 3. Key Components
* **`conversations: N`**: Tells Sensei-check how many conversations to compare (usually 2).
* **`when` (Filter)**: Creates a "comparable cohort". It ensures you are only comparing apples to apples (e.g., keeping the pizza size and drinks equal).
* **`if` / `then`**: Reads like a law. "If X changes this way, then Y should change that way."
* **`conv[i].field`**: These fields (like `size`, `toppings`, `price`) map directly to the extracted data defined in your SENSEI Chat profile's `chatbot.output`.

### Other common use cases:
* **Size Monotonicity**: A large pizza should never be cheaper than a small pizza of the same type.
* **Language Consistency**: If the user asks for the same thing in two different conversations, the chatbot should consistently reply in the same language.
* **Banking/Travel**: A higher fee tier should result in a higher total debit; upgrading to first-class should not result in a cheaper ticket.
