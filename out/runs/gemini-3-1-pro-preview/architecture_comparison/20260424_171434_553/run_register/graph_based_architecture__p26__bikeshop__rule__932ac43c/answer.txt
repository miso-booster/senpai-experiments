Looking at your goal—checking if the tune-up price is exactly $50—this is actually a **single-conversation check** (a traditional oracle) rather than a metamorphic rule (which compares two or more conversations). 

Your current rule has a few structural issues, but don't worry, it's an easy fix! Here is the corrected version of your rule:

```yaml
name: check_tune_up_price
description: Checks if the tune-up price is equal to $50.
conversations: 1
oracle: extract_float(tune_up_price) == 50
```

### 🛠️ What I changed and why:

1. **`conversations: 1` instead of `2`**: Since you are checking an absolute value in a single chat rather than comparing two different chats, we only need 1 conversation.
2. **Removed `conv[0]`**: For single-conversation rules, you don't need the `conv[0]` prefix. You can just use the field name directly!
3. **Removed the `when` filter**: The `when` clause is used to *filter* which conversations are eligible for the test. If you put `tune_up_price == 50` in the `when` clause, Sensei-check will just ignore any conversation where the price isn't 50, rather than properly failing the test.
4. **Replaced `if/then` with `oracle`**: For simple absolute checks, `oracle` is the cleanest way to write it. Also, your previous `then` clause was a text string (`"The tune-up price is $50."`), but Sensei-check expects a Python expression that evaluates to `True` or `False`.
5. **Added `extract_float()`**: It's a Sensei-check best practice to use the `extract_float()` helper function. It safely pulls the number out just in case the chatbot outputs a string like `"$50.00"` or `"50 dollars"`!
