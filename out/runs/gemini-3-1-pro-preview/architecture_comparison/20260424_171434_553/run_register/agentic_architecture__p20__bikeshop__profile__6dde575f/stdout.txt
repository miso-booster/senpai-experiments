Here is a SENSEI profile designed to test how your bike shop chatbot handles appointment scheduling across different days and times. 

I have used the `pairwise()` function for the variables, which is a best practice to efficiently test combinations of days and times without generating an overwhelming number of conversations.

```yaml
test_name: "bike_shop_wheel_change"

llm:
  temperature: 0.7
  model: gpt-4o
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: >
    You are a customer who needs to change the wheels on your bicycle.
    You want to schedule an appointment at the local bike shop.
  context:
    - "You have a mountain bike."
    - "You need both the front and rear wheels changed."
  goals:
    - "Schedule an appointment for a wheel change on {{appointment_day}} at {{appointment_time}}"
    - appointment_day:
        function: pairwise()
        type: string
        data: [Monday, Tuesday, Wednesday, Thursday, Friday, Saturday]
    - appointment_time:
        function: pairwise()
        type: string
        data: ["09:00", "11:30", "14:00", "16:45"]

chatbot:
  is_starter: false
  fallback: "I'm sorry, I didn't understand that. Could you please repeat?"
  output:
    - scheduled_day:
        type: string
        description: "The confirmed day of the appointment"
    - scheduled_time:
        type: time("hh:mm")
        description: "The confirmed time of the appointment"
    - service_type:
        type: string
        description: "The service requested by the user"

conversation:
  number: combinations
  goal_style:
    all_answered:
      export: true
      limit: 15
  interaction_style:
    - default
```

### 📝 Summary of the Profile

* **User Persona & Context:** The simulated user is a mountain bike owner who needs both wheels changed and wants to book an appointment.
* **Variables (`appointment_day` & `appointment_time`):** 
  * I defined two variables in the `goals` section with a list of different days and times.
  * By using the `pairwise()` function for both, Sensei will generate a smart matrix of combinations. This ensures every day and every time is tested together at least once, giving you great coverage without running a massive Cartesian explosion of every single possibility.
* **Conversation Number:** Set to `combinations`, which tells Sensei to automatically run enough conversations to cover the pairwise matrix generated by the variables.
* **Chatbot Output:** At the end of the conversation, Sensei will extract the `scheduled_day`, `scheduled_time` (using the built-in `time("hh:mm")` type), and the `service_type`. This is extremely useful if you want to write SENSEI RULES later to verify that the chatbot actually booked the correct day and time requested by the user!
