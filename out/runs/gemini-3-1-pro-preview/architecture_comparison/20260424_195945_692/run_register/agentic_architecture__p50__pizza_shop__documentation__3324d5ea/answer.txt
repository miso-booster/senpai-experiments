In **SENSEI-check**, an **oracle** is essentially a boolean condition (a statement that evaluates to `True` or `False`) used to validate whether a chatbot's conversation behaved correctly. 

Conceptually, it solves the problem of "how do we know if the chatbot did the right thing?" by letting you define a strict rule that the conversation outputs must pass.

### How it works in SENSEI Rules
When you write a rule in YAML, you can use the `oracle:` keyword to define this condition using a Python-like expression. If the expression evaluates to `True`, the test passes. If it evaluates to `False`, the test fails. 

*(Note: For metamorphic rules that compare multiple conversations, you can also use an `if`/`then` structure, but `oracle` is perfect for straightforward boolean checks).*

Here are a few ways oracles are typically used, based on the `sensei-check-doc.md` and `rules-examples.md` documentation:

#### 1. Single-Conversation Oracles (Traditional Checks)
These check a specific condition within a single conversation. For example, ensuring that a small pizza always costs at least $10:

```yaml
name: small_base_price_floor
description: Small pizzas should cost at least $10
conversations: 1
when: size == 'small'
oracle: extract_float(price) >= 10 and currency(price) == 'USD'
```

#### 2. Global Oracles (All Conversations)
These check a condition across an entire batch of generated conversations. For example, ensuring that every single order ID generated by the bot is unique:

```yaml
name: unique_order_ids
description: Every conversation has a unique order_id
conversations: all
oracle: is_unique('order_id')
```

#### 3. Style and Scope Oracles
Oracles are also great for checking the "style" or "boundaries" of a chatbot using SENSEI's built-in helpers. For example, making sure the bot doesn't go off-topic:

```yaml
name: scope_guardrails
description: Assistant does not drift from the pizza domain
conversations: 1
oracle: only_talks_about('pizza and drink orders, delivery, store info')
```

### Summary
Whenever you see `oracle:` in a SENSEI rule, it is simply the **test condition** that the conversation data (like extracted prices, languages, or order IDs) must satisfy to be considered correct!
