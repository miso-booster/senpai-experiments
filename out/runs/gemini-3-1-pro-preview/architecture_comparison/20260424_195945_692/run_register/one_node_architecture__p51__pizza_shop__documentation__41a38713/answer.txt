**What are Connectors used for?**
Connectors act as a bridge between Sensei and the chatbot you want to test. Specifically, the Custom YAML Connector allows you to connect Sensei to *any* chatbot API without writing a single line of code! You just create a simple YAML configuration file that tells Sensei how to send messages to your chatbot and how to read its replies. 

**What fields do they have?**
A connector configuration file uses a straightforward structure. Here are the fields you can use:

*   **`name`** *(Optional)*: A friendly name for your chatbot.
*   **`base_url`** *(Required)*: The base URL of your chatbot's API (e.g., `https://api.mychatbot.com`).
*   **`send_message.path`** *(Required)*: The specific API endpoint path, which gets appended to the base URL (e.g., `/chat/send`).
*   **`send_message.method`** *(Optional)*: The HTTP method to use, such as `POST`, `GET`, `PUT`, or `DELETE`. If you leave this out, it defaults to `POST`.
*   **`send_message.headers`** *(Optional)*: Any custom headers your API needs, like `Authorization: "Bearer your-api-key"` or `Content-Type: "application/json"`.
*   **`send_message.payload_template`** *(Required)*: The JSON structure of the request body. This is where you place the special `{user_msg}` placeholder so Sensei knows exactly where to inject the simulated user's message!
*   **`response_path`** *(Required)*: A dot-separated path that tells Sensei how to navigate the chatbot's JSON response to extract the actual reply text. For example, if the bot replies with `{"data": {"messages": [{"content": "Hello!"}]}}`, your response path would be `data.messages.0.content`.

Here is a quick example of a simple Echo Bot connector so you can see how the fields look in action:

```yaml
name: "Echo Bot"
base_url: "https://postman-echo.com"
send_message:
  path: "/post"
  method: "POST"
  payload_template:
    message: "{user_msg}"
response_path: "json.message"
```
