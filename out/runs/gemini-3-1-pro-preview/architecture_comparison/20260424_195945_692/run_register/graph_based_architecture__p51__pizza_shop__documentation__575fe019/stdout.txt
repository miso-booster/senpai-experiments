Connectors in SENSEI are super handy! They allow you to connect your testing environment to any custom chatbot API **without writing a single line of code**. You just create a simple YAML configuration file that acts as a bridge, telling SENSEI exactly how to communicate with your chatbot's API. 🤖💬

Here is a breakdown of the fields you can use in a connector configuration, along with whether they are required or optional:

*   **`name`** *(Optional)*: A friendly name for your chatbot (e.g., "My Awesome Bot").
*   **`base_url`** *(Required)*: The main URL of your chatbot's API (e.g., `https://api.mychatbot.com`).
*   **`send_message.path`** *(Required)*: The specific endpoint path that gets appended to your base URL (e.g., `/chat/send`).
*   **`send_message.method`** *(Optional)*: The HTTP method to use for the request, such as `POST`, `GET`, `PUT`, or `DELETE`. If you don't include this, it defaults to `POST`.
*   **`send_message.headers`** *(Optional)*: Any custom headers your API needs, like an `Authorization` token or `Content-Type`.
*   **`send_message.payload_template`** *(Required)*: The JSON structure of the message you are sending to the bot. This is where you use the magic placeholder `{user_msg}` so SENSEI knows exactly where to inject the simulated user's text! ✨
*   **`response_path`** *(Required)*: A dot-separated path that tells SENSEI how to navigate the JSON response to find the bot's actual reply. For example, if the bot's text is inside `response["data"]["text"]`, your path would be `data.text`.

**Here is a quick example of how it all comes together:**
```yaml
name: "Echo Bot"
base_url: "https://postman-echo.com"
send_message:
  path: "/post"
  method: "POST"
  payload_template:
    message: "{user_msg}"
response_path: "json.message"
```
