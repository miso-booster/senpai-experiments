Because you want to check that the chatbot matches the user's language, we can create a **general rule**. This means the rule is profile-agnostic—it will work for any profile because it relies on a built-in SENSEI-check helper rather than specific data extracted from a conversation.

Based on the `sensei-check-doc.md` and `rules-examples.md` documentation, SENSEI has a built-in helper called `responds_in_same_language()` specifically designed for this.

Here is the YAML for your rule:

```yaml
name: chatbot_responds_in_same_language
description: The chatbot responds in the same language as the user
conversations: 1
active: true
oracle: responds_in_same_language()
on-error: "The chatbot did not respond in the same language as the user."
```

### How it works:
* **`conversations: 1`**: This rule evaluates each conversation individually (it's a standard oracle, not a metamorphic rule).
* **`oracle: responds_in_same_language()`**: This calls the built-in LLM-backed helper that automatically analyses the user's input language and checks if the assistant's replies match it.
* **`on-error`**: If the rule fails (meaning the chatbot switched languages inappropriately), this helpful message will be logged. *(Note: In older examples this was sometimes called `yields`, but `on-error` is the standard way to provide failure messages).*

You can save this as a `.yaml` file in your `rules` directory. Since it doesn't depend on any specific `chatbot.output` fields, it will automatically apply to any conversation generated by your profiles!
