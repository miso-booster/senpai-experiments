Based on the SENSEI rules documentation (specifically `sensei-check-doc.md`), you can create a single-conversation rule that checks if a specific field was successfully extracted by the chatbot.

Since you mentioned the output name is exactly `order_id`, we can check if this key exists in the `data_output` dictionary, which stores all the extracted fields for a conversation.

Here is the YAML for the rule:

```yaml
name: order_id_provided
description: The chatbot must provide an order ID during the conversation
conversations: 1
active: true
oracle: |
  'order_id' in data_output
```

### How it works:
* **`conversations: 1`**: This is a single-conversation rule (a traditional oracle), meaning it evaluates each conversation individually rather than comparing multiple conversations.
* **`oracle`**: This is the condition that must evaluate to `True` for the test to pass. 
* **`'order_id' in data_output`**: `data_output` is a built-in dictionary containing all the fields extracted from the profile's `chatbot.output`. This expression simply verifies that the `order_id` was successfully captured.

*(Note: Alternatively, you could also write `order_id is not None` in the oracle, as SENSEI-check injects the extracted variables directly into the evaluation context, but checking `data_output` is the canonical way recommended in the docs for this specific check!)* 😊
