This is a great profile! It has very clear goals and a rich set of variables to extract in `chatbot.output` (like links, dates, times, and money). 

To test this profile, we use **SENSEI RULES** (Sensei-check). Rules evaluate the conversations generated by your profile by looking at the fields defined in your `chatbot.output`. 

Based on the documentation (`sensei-check-doc.md` and `rules-examples.md`), here are **4 different rules** you can use to validate the chatbot's behaviour. I have designed them specifically around the outputs and goals you provided.

### 1. Completeness Rule (Single Conversation)
Since one of the user's goals is to ask about the Welcome Day, the chatbot should always provide the date, time, and location of the event. This rule checks that those specific fields from your `chatbot.output` are successfully extracted and not empty.

```yaml
name: welcome_day_details_provided
description: The chatbot must provide the date, time, and location for the Welcome Day event.
conversations: 1
oracle: welcome_day_date is not None and welcome_day_time is not None and event_location is not None
```

### 2. Consistency Rule (Metamorphic - 2 Conversations)
Metamorphic rules compare two or more conversations. In your profile, the user asks about different `grados` (degrees). This rule ensures that if two different simulated users ask about the **same degree**, the chatbot should quote them the **same application fee**.

```yaml
name: consistent_application_fee
description: The application fee should be the same when asking about the same degree.
conversations: 2
when: conv[0].grados == conv[1].grados
if: conv[0].application_fee is not None and conv[1].application_fee is not None
then: extract_float(conv[0].application_fee) == extract_float(conv[1].application_fee)
```
*(Notice how we use the built-in `extract_float()` helper because your `application_fee` is of type `money`)*

### 3. Language Rule (Global/Style)
Your profile explicitly sets the user's language to `Spanish`. We can use a built-in helper to ensure the chatbot doesn't accidentally reply in English or another language.

```yaml
name: responds_in_spanish
description: The chatbot must respond in Spanish.
conversations: 1
oracle: language(chatbot_phrases) == 'SPA'
```

### 4. Topic Scope Rule (Global/Style)
To ensure the chatbot doesn't hallucinate or drift into unrelated topics (like selling pizzas or talking about sports), we can use the `only_talks_about` helper to restrict its domain strictly to university admissions.

```yaml
name: scope_admissions
description: The chatbot should only talk about university admissions, courses, and events.
conversations: 1
oracle: only_talks_about('university admissions, degrees, courses, waitlist procedures, and Welcome Day events')
```

### How to use them:
You can save each of these YAML blocks into separate files inside your project's `rules/` directory (for example, `rules/welcome_day_details.yml`, `rules/consistent_fee.yml`, etc.). When you run Sensei-check, it will automatically apply these rules to the conversations generated by your "Usuarios Nuevos y Admisiones" profile! 😊
