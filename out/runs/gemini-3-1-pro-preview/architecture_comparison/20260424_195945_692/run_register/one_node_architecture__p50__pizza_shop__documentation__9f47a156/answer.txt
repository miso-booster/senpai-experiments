In the world of Sensei-check, an **oracle** is basically a traditional pass/fail test condition for your chatbot. 

Think of it as a strict judge. You give the judge a specific rule—like *"the chatbot must always provide an order ID"* or *"the price must be greater than zero"*—and the oracle looks at a **single conversation** to determine if that statement is `True` or `False`. 

In your Sensei-check YAML rules, `oracle` is the actual keyword you use to define this boolean condition. It's perfect for baseline sanity checks!

Here is a quick example of a rule using an oracle to check if the chatbot responds in English:

```yaml
name: answers_in_english
description: The chatbot answers in english
conversations: 1
active: True
oracle: language(chatbot_phrases) == 'ENG'
```

**How it compares to other rules:**
While an **oracle** is great for absolute checks on a single conversation, Sensei-check also lets you write **metamorphic rules** (using `if` and `then`). Metamorphic rules compare *multiple* conversations to see how the output changes when the input changes (for example: *"If I add more toppings, then the price should go up"*).
