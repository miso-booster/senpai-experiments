To create a scenario where the simulated user changes their mind halfway through, we can use a very handy feature in Sensei Profiles called **interaction styles**. Specifically, the `change your mind` interaction style is built exactly for this kind of indecisive behavior! 

We will also set up the `user.goals` and `user.role` so the simulator knows it should start with a custom pizza (using a `{{toppings}}` variable) and then switch to a `{{predefined_pizza}}`.

Here is the complete, ready-to-use YAML profile for your project:

```yaml
test_name: "change_mind_custom_to_predefined"

llm:
  temperature: 0.7
  model: gpt-4o-mini
  format:
    type: text

user:
  language: English
  role: "A slightly indecisive customer ordering dinner from a local pizza shop."
  context:
    - "You want to order a pizza but you aren't entirely sure what you want at first."
  goals:
    - "Start by ordering a custom pizza with {{toppings}}."
    - "Change your mind halfway through the conversation and ask for a {{predefined_pizza}} pizza instead."
    - "Ask for the total price of your final order."
    - toppings:
        function: random()
        type: string
        data: 
          - "pepperoni and extra cheese"
          - "mushrooms, onions, and bell peppers"
          - "bacon and olives"
    - predefined_pizza:
        function: random()
        type: string
        data: 
          - "Margherita"
          - "BBQ Chicken"
          - "Vegetarian"
          - "Hawaiian"

chatbot:
  is_starter: false
  fallback: "I'm sorry, I didn't quite catch that. Could you repeat your order?"
  output:
    - final_pizza_ordered:
        type: string
        description: "The predefined pizza the user finally decided to order."
    - total_price:
        type: currency
        description: "The final price of the order."

conversation:
  number: 3
  goal_style:
    all_answered:
      export: false
      limit: 15
  interaction_style:
    - change your mind
```

### 👀 A quick look at what makes this work:
* **`interaction_style: [change your mind]`**: This tells the Sensei user simulator to naturally hesitate, backtrack, or alter its choices during the chat.
* **Variables (`{{toppings}}` and `{{predefined_pizza}}`)**: We use the `random()` function to pick different combinations each time the test runs, ensuring your chatbot can handle various changes!
* **`chatbot.output`**: At the end of the conversation, Sensei will extract the `final_pizza_ordered` and the `total_price`. This is super useful if you want to write a Sensei Rule later to verify that the chatbot charged for the *predefined* pizza and not the custom one!
