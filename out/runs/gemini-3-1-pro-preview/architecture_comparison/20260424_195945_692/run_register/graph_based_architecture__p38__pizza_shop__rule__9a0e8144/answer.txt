To check if the chatbot successfully provided an `order_id`, we only need to look at one conversation at a time. This means we'll create a **single-conversation rule** (also known as a traditional oracle). 

Assuming your SENSEI Chat profile has `order_id` defined in its `chatbot.output`, here is exactly how you would write the rule in YAML:

```yaml
name: order_id_provided
description: Ensures the chatbot successfully provides an order ID.
conversations: 1
oracle: order_id is not None
```

### 📝 A quick breakdown of how it works:
* **`conversations: 1`**: This tells Sensei-check that we are evaluating each conversation individually, rather than comparing multiple conversations together.
* **`oracle: order_id is not None`**: This is the magic condition! Because `order_id` is defined in your profile's output, Sensei-check makes it available as a variable. This line simply asserts that the chatbot actually filled it with a value.

**💡 Senpai Pro-Tip:** 
If you ever want to check if *all* of your expected outputs were provided (like `order_id`, `price`, `size`, etc.), you can use our built-in helpers! For example, you could write `oracle: data_collected() is True` to ensure nothing was left blank, or use `missing_slots() == []` to verify no fields are missing. 👀
