Testing how a chatbot handles dates and times is super important, especially for a business like a bike shop where scheduling is everything! I would love to help you set up a Sensei Profile for this.

To test different days and times efficiently, we can use **variables** in the `user.goals` section and apply the `pairwise()` function. This will mix and match different date formats (like "tomorrow", "next Monday", or specific dates) with different time formats (like "10:00 AM", "noon", or "14:30") to ensure your chatbot understands all of them without having to run hundreds of redundant conversations.

Here is a complete, ready-to-run profile tailored to your needs:

```yaml
test_name: "wheel_change_appointment_test"

llm:
  temperature: 0.7
  model: gpt-4o-mini
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: >
    You are a cyclist who needs to get your bike wheels replaced and wants to book an appointment at the local bike shop.
  context:
    - "Your current wheels are worn out. You just need the shop to install new ones for you."
    - "You want to make sure the shop is available on your preferred day and time."
  goals:
    - "Tell the assistant you need to get your bike wheels changed."
    - "Ask to schedule an appointment for {{appointment_day}} at {{appointment_time}}."
    - appointment_day:
        function: pairwise()
        type: string
        data: 
          - "tomorrow"
          - "next Monday"
          - "Friday"
          - "November 15th"
          - "any weekend day"
    - appointment_time:
        function: pairwise()
        type: string
        data: 
          - "10:00 AM"
          - "14:30"
          - "noon"
          - "4:00 PM"
          - "morning"

chatbot:
  is_starter: false
  fallback: "I'm sorry, it's a little loud in the shop right now. Could you repeat that?"
  output:
    - confirmed_day:
        type: string
        description: "The exact day confirmed for the appointment."
    - confirmed_time:
        type: time("hh:mm a")
        description: "The exact time confirmed for the appointment."
    - service_booked:
        type: string
        description: "The type of service the user booked (e.g., wheel change)."

conversation:
  number: combinations(1, pairwise) # This runs 100% of the pairwise combinations!
  goal_style:
    all_answered:
      export: true
      limit: 15
  interaction_style:
    - default
```

### 🧐 Why this setup works great:
1. **The `pairwise()` Magic**: By using `pairwise()` on both `appointment_day` and `appointment_time`, Sensei will intelligently pair these options together. It guarantees that every day and every time is tested at least once in combination, giving you great coverage without a massive Cartesian explosion of tests!
2. **`combinations(1, pairwise)`**: This tells Sensei to use the combination matrix generated by our pairwise variables to determine exactly how many conversations to run.
3. **`chatbot.output`**: At the end of the conversation, Sensei will extract the `confirmed_day` and `confirmed_time`. You can later use **Sensei Rules** to check if the extracted time matches what the user actually requested!
4. **`export: true`**: Because we set this in `goal_style`, Sensei will generate a handy `.csv` dataframe at the end so you can easily verify which goals were successfully answered.

**💡 Senpai Tip:** If you want to make the test even harder for your chatbot, you could add `- change your mind` to the `interaction_style` list! The simulated user will occasionally book a time, and then suddenly say, *"Actually, can we do Tuesday instead?"* It's a fantastic way to test the bot's memory and flexibility!
