Since you want to verify that specific information was successfully extracted in a single chat session, we will create a **single-conversation rule** (also known as a traditional oracle). 

Because you already defined `contact_email`, `contact_phone`, and `physical_address` in your SENSEI Chat profile's `chatbot.output`, we can reference those exact field names directly in our rule.

Here is the YAML rule you can use:

```yaml
name: cau_contact_info_complete
description: Checks that Ada UAM successfully provided the CAU email, phone number, and physical address.
conversations: 1
oracle: contact_email is not None and contact_phone is not None and physical_address is not None
```

### 🧠 How it works:
* **`conversations: 1`**: Tells Sensei-check to evaluate this rule on each conversation individually, rather than comparing multiple conversations together.
* **`oracle`**: This is the condition that must be `True` for the test to pass. We are simply checking that none of your three required fields came back empty (`None`).

### 💡 Senpai Pro-Tip!
If those three fields are the *only* outputs defined in your profile, you can make this rule even shorter by using one of Sensei-check's built-in helpers called `data_collected()`. This helper automatically checks that all the slots in your `chatbot.output` were successfully filled:

```yaml
name: cau_contact_info_complete
description: Checks that Ada UAM successfully provided all required CAU contact details.
conversations: 1
oracle: data_collected() is True
```

Either approach works perfectly! Just save the YAML block into your `rules/` folder, and Sensei-check will make sure Ada UAM is doing her job correctly.
