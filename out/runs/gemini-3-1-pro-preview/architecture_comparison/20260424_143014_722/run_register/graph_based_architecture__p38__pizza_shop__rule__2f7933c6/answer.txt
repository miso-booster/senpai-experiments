Since you just want to verify that a specific piece of information (the `order_id`) was successfully extracted in a single chat, we'll use a **single-conversation oracle**. We don't need to compare multiple conversations for this one, so setting `conversations: 1` is perfect!

Here is how you can write this rule in YAML:

```yaml
name: order_id_provided
description: The chatbot must provide an order ID in the output.
conversations: 1
oracle: "'order_id' in data_output"
```

### 📝 A quick breakdown of what's happening:
* **`conversations: 1`**: Tells Sensei-check to look at each conversation individually rather than comparing a pair.
* **`oracle`**: This is our pass/fail condition! It simply checks if the key `'order_id'` exists in the `data_output` that Sensei-chat collected at the end of the conversation.

*(Alternatively, if you want to check that the variable itself was filled out and isn't empty, you could also write the oracle as `oracle: order_id is not None`!)*

**💡 Senpai Tip:** 
Just remember that Sensei-check and SENSEI Chat profiles work as a team! For this rule to work perfectly, make sure that your target **SENSEI Chat profile** actually exposes `order_id` under its `chatbot.output` section.
