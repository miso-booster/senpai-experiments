Here is a rule that checks if the chatbot properly provides the availability status when a user requests a lactose-free product. 

Since you mentioned there is no profile yet, I have designed this using a **Rule-first approach**. I've invented a couple of logical variable names (`dietary_requirement` and `availability_status`) that your future profile will need to extract.

```yaml
name: lactose_free_availability
description: Ensures that when a user requests a lactose-free product, the chatbot clearly states its availability status.
conversations: 1
if: dietary_requirement == 'lactose-free'
then: availability_status in ['available', 'out_of_stock']
```

### How this rule works:
* **`conversations: 1`**: This is a single-conversation rule (an oracle) that evaluates each conversation individually.
* **`if` condition**: It checks if the extracted `dietary_requirement` from the user's request is exactly `'lactose-free'`.
* **`then` condition**: If the `if` condition is met, it asserts that the `availability_status` must be successfully extracted as either `'available'` or `'out_of_stock'`.

### ⚠️ Requirements for your future SENSEI Chat Profile
For this rule to work, the profile you create later **must** expose the following fields in its `chatbot.output` schema:

1. **`dietary_requirement`**: A string field capturing any special dietary needs requested by the user (e.g., `"lactose-free"`, `"vegan"`, `"gluten-free"`).
2. **`availability_status`**: A string field capturing the chatbot's response regarding stock (e.g., `"available"`, `"out_of_stock"`).
