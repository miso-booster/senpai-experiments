Here is the rule you need! 😊

Since you already provided the exact `chatbot.output` fields (`contact_email`, `contact_phone`, and `physical_address`), we can map them directly into a single-conversation oracle rule. 

To make the rule robust against minor formatting differences (like `"914974029"` vs `"91 497 4029"`, or slight variations in how the address is phrased), I have used the `semantic_content` helper from the SENSEI-check DSL. This helper uses an LLM under the hood to verify that the extracted value matches the expected meaning.

```yaml
name: correct_cau_information
description: Checks that Ada UAM provides the correct CAU location, email, and telephone number.
conversations: 1
active: true
oracle: |
  semantic_content(contact_email, 'cau@uam.es') and semantic_content(contact_phone, '91 497 4029') and semantic_content(physical_address, 'Higher Polytechnic School, C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107')
yields: |
  f"Incorrect CAU info. Got Email: {contact_email}, Phone: {contact_phone}, Address: {physical_address}"
```

### How this rule works:
* **`conversations: 1`**: This is a standard oracle rule that evaluates a single conversation at a time.
* **`oracle`**: It checks all three fields simultaneously. If any of the fields don't semantically match the official CAU information you provided, the rule will fail.
* **`yields`**: If the rule fails, it will print out exactly what the chatbot extracted so you can easily debug what went wrong.
