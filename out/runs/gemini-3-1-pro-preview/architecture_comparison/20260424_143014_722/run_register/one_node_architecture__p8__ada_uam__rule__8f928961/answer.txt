However, there are two little issues with how the rule is currently structured:

1. **The `when` clause trap:** In Sensei-check, the `when` clause acts as a **filter** to select which conversations to evaluate. If you put the exact same condition in the `when` clause and the `oracle`, the rule will *only* look at conversations where the bot already gave the perfect answer. If the bot gives the wrong phone number, the rule will just ignore that conversation instead of failing it! 
2. **The `conv[0]` prefix:** Because this is a single-conversation rule (`conversations: 1`), you don't need to use the `conv[0].` prefix. You can just call the variables directly by their names.

Here is the corrected version of your rule:

```yaml
name: check_cau_information
description: Checks that the CAU provided correct information about contact details.
conversations: 1
oracle: contact_email == 'cau@uam.es' and contact_phone == '91 497 4029' and physical_address == 'C/ Francisco Tomás y Valiente nº 11, Building B, first floor, office TI-107'
```

### 💡 Why this works better:
By removing the `when` clause, Sensei-check will now evaluate **all** conversations generated by this profile. The `oracle` will then act as the actual test: it will check the extracted `contact_email`, `contact_phone`, and `physical_address`. If the chatbot hallucinates a different phone number or forgets the address, the oracle will evaluate to `False`, and the test will correctly report a failure so you can catch the bug. 👀
