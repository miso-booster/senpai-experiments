In the world of Sensei-check, an **oracle** is basically your "source of truth"—it's a condition that determines whether a specific conversation (or a set of conversations) has passed or failed a test. 

When you write a SENSEI RULE, you use the `oracle` keyword to define a simple true/false check (a boolean condition). It is most commonly used for **single-conversation checks** (traditional testing) or **global checks** across all your data.

Here are a couple of everyday examples of how you might use an oracle in your rules:

**1. Checking if the chatbot collected all the necessary data:**
```yaml
name: chatbot_fills_all_slots
description: All conversation slots are filled
conversations: 1
oracle: data_collected() == True
```

**2. Doing a baseline sanity check on a price:**
```yaml
name: small_base_price_floor
description: Small pizzas should cost at least $10
conversations: 1
when: size == 'small'
oracle: extract_float(price) >= 10 and currency(price) == 'USD'
```

**3. Checking a global rule (across all conversations):**
```yaml
name: unique_order_ids
description: Every conversation has a unique order_id
conversations: all
oracle: is_unique('order_id')
```

**Oracles vs. Metamorphic Rules 🕵️‍♂️**
While an `oracle` is perfect for checking absolute truths (like "the price must be > 10"), sometimes you want to compare *multiple* conversations to see how changing the input changes the output (e.g., "adding more toppings should increase the price"). For those metamorphic rules, instead of a single `oracle`, we usually use an `if` / `then` structure!
