Hi there! I'd be happy to help you write this rule for Ada UAM! 🎓✨

Since you already have your `chatbot.output` fields perfectly defined, we just need a **single-conversation rule** (`conversations: 1`). This rule will act as an oracle to verify that the chatbot successfully extracted and filled all three of those specific slots during the chat.

Here is the ready-to-use YAML for your rule:

```yaml
name: cau_contact_info_complete
description: Verifies that Ada UAM provided the complete contact information for the CAU (email, phone, and physical address).
conversations: 1
oracle: contact_email is not None and contact_phone is not None and physical_address is not None
```

### 💡 Senpai's Pro-Tip:
If those three fields are the *only* outputs defined in that specific profile, you can make the rule even simpler by using the built-in `data_collected()` helper! That helper automatically checks that all extracted outputs are non-null:

```yaml
name: cau_contact_info_complete_alt
description: Verifies that Ada UAM provided all the requested CAU contact information.
conversations: 1
oracle: data_collected() is True
```

Both approaches work perfectly! The first one is great if you have other optional fields in your profile and *only* want to strictly check these three. The second one is super clean if those three are the only outputs you care about for this profile. 

Just save this as a `.yaml` file in your `rules/` folder, and you'll be good to go! Let me know if you need help with anything else. Happy testing! 🚀😊
