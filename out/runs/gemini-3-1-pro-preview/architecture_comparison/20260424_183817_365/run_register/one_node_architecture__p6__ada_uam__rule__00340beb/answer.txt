Since you want to verify that those three specific pieces of information (email, phone, and physical address) were successfully extracted from the conversation, we can write a **single-conversation rule**. This rule will check that none of those specific `chatbot.output` fields are empty (`None`).

Here is the YAML for your rule:

```yaml
name: cau_contact_info_provided
description: The chatbot successfully provides the email, phone number, and physical address of the CAU.
conversations: 1
active: true
oracle: contact_email is not None and contact_phone is not None and physical_address is not None
```

### How it works:
* **`conversations: 1`**: This tells Sensei-check that it only needs to look at one conversation at a time (a standard oracle).
* **`oracle`**: This is the condition that must be true for the test to pass. It directly references the names of the variables you defined in your profile's `chatbot.output` (`contact_email`, `contact_phone`, and `physical_address`) and ensures the LLM was able to extract a value for all of them.

Just save this in your `rules/` folder (for example, as `rules/cau_contact_info.yaml`), and Sensei-check will automatically validate it against your Ada UAM conversations! Let me know if you need help with anything else. 👀✨
