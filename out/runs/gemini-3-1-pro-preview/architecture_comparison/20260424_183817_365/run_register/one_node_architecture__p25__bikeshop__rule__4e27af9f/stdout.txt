Since you want to check the exact values extracted from a single conversation, we can use a **single-conversation oracle**. 

To make the rule robust, we will use a couple of built-in helpers:
* `extract_float()`: This is perfect for pulling the numeric values out of your `money` and `str` fields (like `tune_up`, `seat_price`, and `tire`) so we can compare them mathematically.
* `semantic_content()`: Since the `opening_and_closing` field is a string and the chatbot might phrase it differently (e.g., "From 10 AM to 8 PM" or "10:00 - 20:00"), this LLM-backed helper checks if the meaning matches "10 to 20" without needing an exact word-for-word match.

Here is the rule you can use:

```yaml
name: check_qa_prices_and_hours
description: Checks that the opening hours are 10 to 20, tune-up is 50, seat is 20, and tire is 20.
conversations: 1
active: true
oracle: >
  semantic_content(opening_and_closing, '10 to 20') and 
  extract_float(tune_up) == 50 and 
  extract_float(seat_price) == 20 and 
  extract_float(tire) == 20
yields: f"One or more values did not match the expected output! Hours: {opening_and_closing}, Tune-up: {tune_up}, Seat: {seat_price}, Tire: {tire}"
```
