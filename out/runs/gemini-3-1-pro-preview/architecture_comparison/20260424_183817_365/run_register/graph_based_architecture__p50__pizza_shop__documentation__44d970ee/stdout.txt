In the world of **SENSEI RULES** (specifically Sensei-check), an **oracle** is basically the judge! ⚖️ It is the condition or expression that evaluates whether your chatbot's conversation passed or failed a test. 

When you write a rule to test your chatbot, you use the `oracle:` keyword to define the exact condition that *must* be true. 

There are generally two ways we use them in Sensei:

**1. Traditional Oracles (Single Conversation)**
These check absolute truths within one specific chat. You use them for baseline sanity checks. For example, you might want to check if the chatbot answered in English, or if it successfully collected all the required data.
*Example:*
```yaml
name: answers_in_english
description: The chatbot answers in English
conversations: 1
oracle: language(chatbot_phrases) == 'ENG'
```

**2. Global or Metamorphic Oracles (Multiple Conversations)**
Instead of checking an absolute answer in just one chat, these check the *relationship* or *consistency* across several conversations, or even your entire dataset. For example, checking that every single order ID generated by the bot is unique.
*Example:*
```yaml
name: unique_order_ids
description: Every conversation has a unique order_id
conversations: all
oracle: is_unique('order_id')
```

*(Note: When comparing exactly two conversations—like checking if adding more toppings makes a pizza more expensive—we often use `if:` and `then:` instead of `oracle:` because it reads a bit more clearly, but the underlying concept is exactly the same!)*

Think of the oracle as the ultimate source of truth for your test. If the Python expression inside the oracle evaluates to `True`, your chatbot passes the test! 🎉
