Para comprobar que tu asistente se defiende bien y rechaza una fecha si el usuario la repite, podemos crear una regla de **SENSEI RULES** (Sensei-check) evaluando una sola conversación. 

Para lograrlo, usaremos la función mágica `utterance_index(who, what)`, que utiliza un modelo de lenguaje por debajo para analizar los turnos de la conversación y encontrar en qué momento exacto alguien dijo algo específico.

Aquí tienes la regla lista para usar:

```yaml
name: rechazo_fecha_repetida
description: Si el usuario menciona la misma fecha dos veces, el asistente debe rechazar la segunda petición.
conversations: 1
if: utterance_index('user', 'repite una fecha que ya había mencionado antes') > 0
then: utterance_index('assistant', 'rechaza la fecha, dice que no es posible o que ya fue solicitada') > 0
```

### 🧠 ¿Cómo funciona esta regla?
1. **`conversations: 1`**: Le dice a Sensei-check que evalúe las conversaciones de una en una (es un oráculo tradicional).
2. **`if` (Condición)**: Busca si en algún momento el usuario (`'user'`) intentó repetir la fecha. Si el índice que devuelve es mayor a `0`, significa que ¡efectivamente lo hizo!
3. **`then` (Consecuencia)**: Si el usuario hizo la trampa, verificamos que el asistente (`'assistant'`) haya respondido negando o rechazando esa fecha en algún turno (índice > `0`).

### 💡 Un consejo de Senpai:
Recuerda que las reglas de Sensei-check no viven aisladas; trabajan en equipo con los **Perfiles de SENSEI Chat**. Para que esta regla se ponga a prueba de verdad y no se quede sin evaluar, asegúrate de tener un perfil de simulación donde el usuario tenga el objetivo explícito de ser un poco insistente y repetir la misma fecha. 😉
