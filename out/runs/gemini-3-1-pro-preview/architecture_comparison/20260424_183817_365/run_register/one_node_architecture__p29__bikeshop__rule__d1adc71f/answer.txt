Looking at your project, you have a great profile named `appointment.yml` that already extracts `confirmed_date`, `confirmed_time`, and `confirmed_service` in its `chatbot.output`. 

We can write a single-conversation rule (an oracle) that checks if these fields were successfully filled out by the end of the conversation. If they aren't `None`, it means the chatbot successfully confirmed the appointment details with the user!

Here is the rule you can use:

```yaml
name: appointment_is_confirmed
description: The chatbot successfully confirms the appointment date, time, and service.
conversations: 1
active: true
oracle: confirmed_date is not None and confirmed_time is not None and confirmed_service is not None
on-error: f"The appointment was not fully confirmed. Missing slots: {missing_slots()}"
```

### How it works:
* **`conversations: 1`**: This tells Sensei-check to evaluate each conversation individually.
* **`oracle`**: This is the condition that must be true. It checks that the three specific output fields from your `appointment.yml` profile were successfully extracted.
* **`on-error`**: If the rule fails, it uses the built-in `missing_slots()` helper to tell you exactly which piece of information the chatbot forgot to confirm!

If you'd rather target your `bike_repair_and_maintenance_scheduler.yaml` profile instead, you would just change the oracle to check `appointment_confirmation is not None`.
