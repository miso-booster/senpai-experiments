Based on the SENSEI rules documentation (`sensei-check-doc.md`), since we are creating this rule *before* a profile exists (Rule-first design), I will define the rule using assumed variables. 

For this rule, I'll assume that a future profile will extract whether the product is lactose-free and its current availability status. 

Here is the rule:

```yaml
name: lactose_free_product_availability
description: Ensures that if a requested product is lactose-free, it is confirmed as in stock.
active: true
conversations: 1
if: is_lactose_free == True
then: availability_status == 'in_stock'
```

### 📋 What you need for your future profile
For this rule to work correctly, the SENSEI Chat profile you create later **must** expose the following fields in its `chatbot.output`:

1. **`is_lactose_free`** (boolean): Indicates whether the user requested a lactose-free product (or if the product discussed is lactose-free).
2. **`availability_status`** (string): The stock status of the product (e.g., `'in_stock'`, `'out_of_stock'`).

If you decide to name these fields differently when you create your profile (for example, `lactose_free_requested` or `is_available`), you will just need to update the variable names in the `if` and `then` clauses of this rule to match! 😊 Let me know if you'd like to adjust the logic or if you're ready to create the profile next!
