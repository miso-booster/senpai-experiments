In Chatbot Dojo, **Connectors** are used to connect the SENSEI simulator to any external chatbot API without having to write a single line of code! 🚀 

They act as the transport layer, allowing our system to send simulated user messages to your target chatbot and extract its replies. You configure them using a simple YAML file that describes exactly how to communicate with the chatbot's API.

Based on the `custom-connector-guide.md`, here are the fields you can use to configure a connector:

### 🔌 Connector Fields

| Field | Required? | Description |
|-------|-----------|-------------|
| `name` | No | A friendly name for your chatbot (e.g., "Support Bot"). |
| `base_url` | **Yes** | The base URL of the chatbot API (e.g., `https://api.mychatbot.com`). |
| `send_message.path` | **Yes** | The API endpoint path that gets appended to the base URL (e.g., `/chat/send`). |
| `send_message.method` | No | The HTTP method to use (POST, GET, PUT, DELETE). It defaults to `POST`. |
| `send_message.headers` | No | Any custom headers your API needs, such as `Authorization` tokens or `Content-Type`. |
| `send_message.payload_template` | **Yes** | The JSON structure of the request body. You must include the `{user_msg}` placeholder here so the simulator knows where to inject the simulated user's message. |
| `response_path` | **Yes** | A dot-separated path used to navigate the JSON response and extract the bot's actual reply text (e.g., `response.0.text` or `data.messages.0.content`). |

### 📝 Quick Example
Here is what a typical connector YAML file looks like:

```yaml
name: "Secure Bot"
base_url: "https://api.mychatbot.com"
send_message:
  path: "/chat/send"
  method: "POST"
  headers:
    Authorization: "Bearer your-api-key"
    Content-Type: "application/json"
  payload_template:
    query: "{user_msg}"
    session_id: "user123"
response_path: "response.text"
```
