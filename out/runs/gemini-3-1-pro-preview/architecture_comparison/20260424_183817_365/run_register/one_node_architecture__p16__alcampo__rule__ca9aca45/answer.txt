Since you are designing the rule before the profile exists, we are using what we call a **Rule-first design**! ✨ This means we will invent the variable names now, but you'll just need to make sure your future SENSEI Chat profile exposes these exact same names in its `chatbot.output` section later.

Here is a single-conversation rule that checks if lactose-free products are confirmed as available and listed whenever a user specifically asks for them:

```yaml
name: lactose_free_availability_check
description: Ensures that when a user asks for lactose-free products, the chatbot confirms availability and provides at least one product option.
conversations: 1
active: true
when: dietary_request == 'lactose-free'
oracle: lactose_free_available == True and len(suggested_products) > 0
on-error: f"Expected lactose-free products to be available and listed, but got available={lactose_free_available} and products={suggested_products}"
```

### 📝 What to remember for your future profile:
For this rule to work perfectly, your future profile will need to have these fields in its `chatbot.output`:
* `dietary_request` (e.g., a string like `'lactose-free'`)
* `lactose_free_available` (a boolean `True` or `False`)
* `suggested_products` (a list of strings containing the product names)
