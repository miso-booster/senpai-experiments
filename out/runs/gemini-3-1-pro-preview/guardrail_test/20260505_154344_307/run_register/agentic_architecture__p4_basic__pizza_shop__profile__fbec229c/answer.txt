To create a Python automation that uses an LLM to generate valid SENSEI profiles, the most reliable approach is to use a **strong System Prompt** combined with standard text generation, and then parse the output into YAML. 

While you *could* use strict JSON schemas (like OpenAI's Structured Outputs with Pydantic), SENSEI profiles use specific YAML patterns (like lists mixing strings and single-key dictionaries in `user.goals` and `chatbot.output`) that are much easier for an LLM to generate directly as YAML text.

Here is a complete, ready-to-use Python script using the `openai` and `pyyaml` libraries. It embeds the core rules from the `sensei-chat-guide.md` documentation to ensure the LLM outputs a perfectly formatted profile.

### Prerequisites
Make sure you have the required libraries installed and your OpenAI API key set:
```bash
pip install openai pyyaml
export OPENAI_API_KEY="your-api-key-here"
```

### Python Automation Script

```python
import os
import re
import yaml
from openai import OpenAI

# Initialize OpenAI client
client = OpenAI()

# This system prompt contains the exact schema and rules from the SENSEI documentation
SENSEI_PROFILE_SYSTEM_PROMPT = """
You are an expert in creating valid SENSEI profiles for chatbot testing.
A SENSEI profile is a YAML file that defines a simulated user's behavior, goals, and the expected chatbot outputs.

You must generate a valid YAML file following this exact structure:

```yaml
test_name: "string_without_spaces"

llm:
  temperature: 0.7
  model: gpt-4o
  model_prov: openai
  format:
    type: text

user:
  language: English
  role: "A clear description of the user's persona and objective."
  context:
    - "Constraint or preference 1"
    - "Constraint or preference 2"
  goals:
    - "A natural language goal containing {{variables}}"
    - variable_name:
        function: random() # options: default(), random(), random(n), forward(), pairwise(), another()
        type: string # options: string, int, float, or custom types like currency
        data: [list, of, values]

chatbot:
  is_starter: false
  fallback: "Sorry, I didn't understand that."
  output:
    - field_name:
        type: string # options: string, int, float, time("hh:mm"), date("mm/dd/yyyy"), list[string]
        description: "Description of what to extract"

conversation:
  number: 3 # integer or combinations(0.5, pairwise)
  goal_style:
    steps: 5 # or random steps: 5, or all_answered: {export: true, limit: 20}
  interaction_style:
    - default # options: long phrases, change your mind, make spelling mistakes, single questions, all questions
```

CRITICAL RULES:
1. `user.goals` must be a list. It contains string prompts with `{{variable}}` placeholders, followed by dictionaries defining those exact variables.
2. Variable definitions in `goals` must have `function`, `type`, and `data`.
3. `chatbot.output` must be a list of dictionaries, each with a single key (the field name) containing `type` and `description`.
4. Output ONLY valid YAML inside a ```yaml block. Do not include any other text or explanations.
"""

def generate_sensei_profile(description: str, output_path: str):
    """
    Generates a SENSEI profile YAML using an LLM based on a natural language description.
    """
    print(f"🤖 Generating profile for: '{description}'...")
    
    try:
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": SENSEI_PROFILE_SYSTEM_PROMPT},
                {"role": "user", "content": f"Create a SENSEI profile for the following scenario:\n{description}"}
            ],
            temperature=0.2 # Low temperature for more deterministic, schema-compliant output
        )
        
        content = response.choices[0].message.content
        
        # Extract YAML from the markdown block
        yaml_match = re.search(r'```yaml\n(.*?)\n```', content, re.DOTALL)
        if yaml_match:
            yaml_content = yaml_match.group(1)
        else:
            # Fallback if the LLM didn't use markdown formatting
            yaml_content = content.strip()
            
        # Validate that the output is valid YAML
        parsed_yaml = yaml.safe_load(yaml_content)
        
        # Ensure the target directory exists
        os.makedirs(os.path.dirname(output_path), exist_ok=True)
        
        # Save the validated YAML to the file
        with open(output_path, 'w', encoding='utf-8') as f:
            yaml.dump(parsed_yaml, f, sort_keys=False, allow_unicode=True)
            
        print(f"✅ Successfully generated and saved profile to: {output_path}")
        return parsed_yaml
        
    except yaml.YAMLError as e:
        print(f"❌ Failed to parse generated YAML: {e}")
        print("Raw output from LLM:")
        print(yaml_content)
        return None
    except Exception as e:
        print(f"❌ An error occurred: {e}")
        return None

# ==========================================
# Example Usage
# ==========================================
if __name__ == "__main__":
    scenario = """
    A user trying to book a table at an Italian restaurant for a group of friends. 
    They need to specify the date, time, number of people (between 2 and 6), 
    and check if there are vegan options. The user might make spelling mistakes.
    """
    
    # This will create the file in a 'profiles' folder in your current directory
    generate_sensei_profile(scenario, "profiles/restaurant_booking.yml")
```

### How this solution works:
1. **System Prompt Engineering**: The prompt acts as a strict template. It explicitly shows the LLM how to format the tricky parts of a SENSEI profile, such as the `user.goals` variable definitions and the `chatbot.output` extraction schema.
2. **Low Temperature**: We set `temperature=0.2` to stop the LLM from getting overly creative with the YAML structure, ensuring it sticks to the provided SENSEI rules.
3. **Regex Extraction & Validation**: The script uses regex to safely extract the YAML block from the LLM's response, and then passes it through `yaml.safe_load()`. This guarantees that the script will only save a file if it is syntactically valid YAML. 

You can easily expand this script to read a CSV of test scenarios and loop through them to generate dozens of SENSEI profiles automatically! Let me know if you'd like to adjust the prompt to include custom data types or specific interaction styles. 😊
